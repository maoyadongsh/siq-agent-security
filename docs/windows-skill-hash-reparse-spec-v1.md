# Windows Skill 内容哈希的目录链接边界

2026-09-18。细化开发规格 §3.6.1 的不跟随目录链接、根外链接拒绝及 Go/Python 内容哈希对等要求；不改变签名格式、普通文件摘要或 POSIX 根内文件链接语义。

Windows 普通用户可能不能创建 file symlink，但可以在隔离 NTFS 目录创建 junction。安全回归必须实际构造根外目录链接，不能因为缺少 symlink 特权就跳过逃逸拒绝检查，也不能将不同链接类型的覆盖相互冒充。Windows 的此项检查明确记为 junction 目录逃逸；其他 OS 保持原 file symlink 检查。Windows file symlink 的专有行为仍不由 junction 结果证明。

Python 清单验证器与 Go admission/HashSkillDir 必须识别 Windows junction 作为目录链接：不递归进入根外目标，不为根外链接树返回成功内容哈希；根内目录链接与现有目录 symlink 一样不递归、不重复计入文件。普通完整目录树保持 Go/Python 哈希一致。除 junction 外未知的重解析类型不能被当作可正常读取文件或目录；需要明确拒绝而不是跟随。

测试可用仅测试文件中的标准库 Win32 API 在 t.TempDir 内创建 junction，目标也必须属于本次夹具。清理只移除链接本身，不递归删除链接目标。不得提权、启用开发者模式、改变系统权限或创建用户目录中的链接。

必须保存修复前行为，验证普通树正向、根外目录链接负向、根内目录链接不递归及源文件不变；运行 Go/Python 哈希对等与受影响清单测试。此修复属于 Windows 本地路径/安装验证的阻断修复，不能据此宣称真实宿主接入或整套 Skill 安装通过。
