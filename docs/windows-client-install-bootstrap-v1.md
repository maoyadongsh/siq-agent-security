# Windows 客户端首次安装身份顺序

2026-09-18，补充 `client-install` 的首次安装行为；沿用现有发行信任根、显式确认、状态兼容检查与 Windows Task Scheduler 归属规则。

## 问题

原顺序为发行验证 → `clientrelease.Stage` → 暂存程序的 `setup`。Stage 在状态目录的 `client-releases` 中发布程序和清单；`init` 只建立初始化元数据。首次任务注册随后调用 `signing.Load` 时，这些非空制品已经构成历史，正确的缺钥保护会返回 `identity_missing_restore_required`，使首次安装无法完成。

## 必须遵守的顺序

1. CLI 先检查显式安装确认、参数及 Windows 不支持的 `--runtime`。原生产发行验证成功前，不创建状态目录、身份或制品。
2. Windows 在第一次发行验证成功后、调用 Stage 前，先执行原状态写兼容检查，再用 `signing.LoadExisting` 只读加载已有身份。有效身份直接复用，不获取主 Writer；运行中的同一实例因此可沿既有 setup 健康复用分支重复安装。只读身份成功不替代后续发行、系统任务归属、健康和版本复验。
3. 仅在只读加载报告不存在、且精确的 `keys/signing.seed` 路径也确认不存在时，复用 `loadWindowsTaskPreparationKey`：取得当前状态的主 Writer，再由现有 `signing.Load` 重新核对状态、缺钥历史与密钥，随后释放 Writer。只允许符合现有首次身份规则的状态建立身份；不得把损坏、权限或状态屏障错误当作缺钥。Writer 必须在 Stage 的 `client-releases` 独立锁之前释放。Stage 继续使用生产内置信任根、兼容声明、制品大小/摘要及排他发布规则；暂存之后的二次发行验证、摘要路径约束不变。
4. 已验证的暂存程序继续执行原 Windows setup。初始化、注册、启动及父进程的真实任务/健康/版本复验全部保留。准备身份或暂存成功都不等于安装完成。

## 拒绝与恢复边界

- 既有历史缺钥（包括先前已有的 `client-releases` 文件）、损坏密钥、不兼容状态或首次生成所需的 Writer 冲突必须在本次 Stage 前拒绝；不为制品目录增加缺钥豁免，不旋转或伪造旧身份，不修补既有 ACL。已有有效身份时不因主 Writer 被健康实例持有而拒绝，只读复用仍必须通过原 N01 读写屏障，不能借读取允许绕过未来 writer 版本或迁移状态。
- 不能先暂存再绕过历史检查补钥。旧失败安装若已留下制品且缺钥，仍须按原可信恢复规则处理，不能由重试自动认可。
- 发行验证后的身份创建是本次明确安装的一部分；后续 Stage/setup 失败时保留该身份和已有诊断状态。重试复用相同身份，不自动删除密钥、制品或任务，不声称已经回滚所有副作用。
- Linux/macOS 的现有行为不在本次修改范围；不增加发行根替换、验签绕过、命令行或 HTTP 合同。

## 定向验证

组件测试以缺失状态和仅有 init 元数据两种初始状态，检查 Stage 第一个操作前已能只读加载真实磁盘身份，且主 Writer 已释放；再经过实际 `cmdInitialize` 与任务注册使用的身份加载入口确认同一公钥。独立验证已有有效磁盘身份且主 Writer 被占用时仍可完成暂存准备、保持原身份及原锁；缺钥且 Writer 被占用时拒绝生成。保留源发行拒绝无落盘、历史缺钥与损坏密钥不覆盖、ACL 失效及未来 writer 屏障不进入 Stage、暂存失败后同身份重试等负向断言。

测试只注入发行检查与制品准备读取器，写入合成程序字节且不执行；不替换生产发行根，不注册任务、不启动服务，也不替代最终受信任制品的原生安装、重复安装和清理验收。
