# ADR-044：明确确认的 Skill 移除与恢复

日期：2026-09-11。状态：核心/API 及个人前端已实施，在隔离 Linux/Hermes 环境验证。承接 [ADR-043](0043-installed-skill-inspection.md)。

移除只针对 SIQ 有完整签名成功安装记录的具体副本。请求固定原操作签名、当前 Grant 版本、当前运行绑定签名（无绑定为空串）、操作者和显式 confirm_remove。操作编号即幂等键，一份安装只有一份不可变移除声明；响应丢失或中断后由同一确认内容重试，不能换操作者或悄悄改变范围。

先签名并排他发布 removal-claim/v1，再通过原 GrantCommit/CAS/审计撤销权限，最后复用归属预检和排他删除清理原目标。来源损坏或权限过期不阻止撤销。Grant 只在当前运行绑定属于此安装或尚无绑定时撤销；已绑定另一安装的同一 Grant 保留，并把绑定签名固定到移除声明，恢复时重新检查。一个安装的文件清理不能删除其他目标、导入来源或共享操作副本。

不改变其他安装所持 Grant 时，无需创建虚假的权限状态变更；签名移除声明作为文件操作前的不可变审计依据，结果继续记录保留的安装关联。需要撤权时，声明不能替代 GrantCommit 的状态与审计完整提交。

新运行验证器遇到此安装的移除声明即拒绝使用；Activate 拒绝已开始移除的目标和待撤销 Grant，防止中断期间把同一权限接到另一安装。旧程序在撤销提交后也必须通过既有 Grant 终态拒绝；审计缺失或提交不完整时不得开始外部文件删除。这不宣称已完成所有状态格式的旧版本写入拒绝。

清理前完整检查现存目标；未知、修改或归属不明对象使清理停止并保留现场，不扩大删除范围。先移除 Skill 入口，再清理可证明归属的目录；成功前复核目标确实不存在，签名 removal-result/v1 追加记载完成及权限处理结果。异常保留声明，查询区分 revocation_pending 和 cleanup_pending；恢复重试复核当前权限与归属。撤销不回滚，不在恢复时自动续权或重建文件。

目录标记删除后、空目录删除前的进程崩溃可能留下无法证明归属的空目录。保持 cleanup_pending，不能凭路径或旧声明猜测其仍为原对象；需要用户核对后处理，再显式重试。成功结果是历史终态，之后同路径出现新对象也不再删除或修改。内部操作副本与原审计保留，后续存储治理另行处理。

状态存于 `skill-installations/removals/{sin-id}.claim.json` 和 `.result.json`，均不可变、已签名、私有文件，至多 64 份安装，枚举预算 256 项。管理 GET `/v1/skill-installations/operations/{id}/removal` 返回只读 removal-view/v1；POST 同一路径提交 remove/v1。只读视图不是批准，只有显式请求执行撤销/清理；状态不明确时不宣称完成。前端确认与恢复入口另行接入并验证，不把核心/API 完成计作 UX-010 整项完成。

### M30 个人管理入口

已安装记录页按所选安装顺序读取移除状态和当前内容，避免共用工作锁的并发查询。历史移除完成单独显示，不能把目标缺失等同于移除。明确打开确认窗口后暂停该页轮询和切换；窗口列出具体安装、当前授权处理范围、保留的另一安装及用户内容保护说明。

仅勾选确认并点击执行才 POST。新操作使用本机管理会话的操作者标识；恢复展示并重用签名声明的原操作者与版本，不改变请求范围。同步提交锁阻止双击。写响应丢失后只 GET 原移除状态，不自动重发；查询失败撤下旧操作按钮，允许显式重新查询。pending 不显示为成功，保留原目录，指引用户核对内容后再明确重试；removed 显示历史完成，不再次提供执行按钮。窗口关闭或卸载不会被解释为服务端操作已取消。
