# ADR-047：明确确认的 Skill 更新事务

日期：2026-09-11。状态：核心与管理 API 已实施并验证，产品界面待接通。承接 [ADR-046](0046-skill-update-preparation.md)。

更新提交固定 sup 更新计划 ID、签名、原操作者及 confirm_update=true。首次提交完整复验未过期计划，再排他发布不可变 update-claim；声明包含原更新计划和由其确定派生的新安装计划。新安装计划保持原五分钟期限，不因提交或重试续期。状态目录 update-operations 保存声明及最终结果，复用已持有的安装工作锁，嵌套操作不得重复获取锁。

签名更新声明同时作为 update-installations/{sip-id}.json 的保留记录；普通 apply 一旦发现该记录始终拒绝，包括更新终止后，只有已确认事务可调用共用内部安装过程。新安装计划尚不对普通安装接口发布。先在状态目录准备并核验独立安装副本，然后按原更新范围执行 ADR-044 移除：撤旧 Grant 或保留已绑定另一安装的 Grant，完整记录移除结果，且目标必须缺失，才排他发布新安装计划并执行 ADR-039 安装。移除声明与原 Grant 签名、版本、运行绑定和保留关系必须精确匹配。任何源、批准、旧目标或副本变化在旧移除开始前拒绝；移除开始后仍需重新验证新批准及期限才能发布新版。全程不执行 Skill，不激活实例权限或签发身份。

更新声明固定的普通安装计划只能在旧移除成功后发布，因此普通 apply 无法借准备计划覆盖旧版本。新计划 ID 由更新 ID 派生的独立 request ID、来源、目标、批准签名及权限摘要确定。使用既有签名安装清单、排他文件发布、归属检查及不可变结果，不新建第二套目标文件协议。原更新副本和导入记录继续保留。

读取查询只验证不可变声明和关联操作，返回 confirmed、removing_previous、installing_candidate、recovery_required、updated_unverified 或 aborted；终态为历史证据，不代表当前目标或运行保护状态。已成功安装但更新结果未落盘时，明确重试可依据签名安装结果补记历史结果，不再次安装，也不要求旧计划重新获得五分钟资格。查询不补写任何结果。

恢复请求必须确认并绑定更新声明签名与原操作者。旧移除尚未开始时，恢复可终止事务而保留旧版本；已开始移除时，先完成既有撤权/归属清理。新安装尚未开始则不触碰新路径；失败安装只调用既有恢复，未知用户对象保留。新安装已有成功结果时不允许把恢复当卸载，应补记更新成功。恢复不重新安装、不延长期限、不复活旧权限；需要重新安装的用户须重新审阅批准。最终 result 签名引用声明及实际移除/安装结果（不存在时为空），status 为 updated_unverified 或 aborted。

同一原安装最多存在一个未终止的更新声明，后续请求须等待其结果；终止后可重新准备独立更新。每次继续使用原声明；拒绝替换计划、操作者、签名，拒绝篡改/孤立最终结果。已确认后的私有安装暂存只能按签名清单完整复验后复用；不完整或未知内容保留并要求恢复，不隐式补写。最多 64 个更新事务、256 个目录项，容量拒绝发生在旧目标变更前。进程强退后持久状态决定恢复路径，单机内存锁不冒充跨进程状态锁；调用方仍持有现有 state writer lock。

本增量提供共用 Go 核心及管理 POST `/v1/skill-installations/updates`、GET `/v1/skill-installations/updates/{sup-id}`、POST `/v1/skill-installations/updates/{sup-id}/recover`。管理分权、严格正文、路径与请求 ID 一致、no-store、60/65 秒预算及共享安装工作锁沿用既有实现。写入出错返回稳定错误，客户端先只读查询持久进度，不消费错误前的状态快照。产品差异确认窗口及真实平台更新验收继续实施。Windows/macOS、WorkBuddy 和可信 Skill 归属仍独立验收。
