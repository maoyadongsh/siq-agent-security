# ADR-032：个人待办通知与平台继续执行边界

状态：浏览器交付逻辑已实现并通过 Linux Chromium 测试替身验证；UX-008 继续实施，OS 实际展示与后台启动器尚待验收。

## 已核实的 Hermes 边界

本机安装的 Hermes 原生 `pre_tool_call` 默认受 30 秒回调上限约束，超时阻止调用。当前 `hermes_cli/plugins.py` 在汇总回调返回值时允许其他插件产生 `modify` 参数变更，`model_tools.py` 在分发前采用合并参数；现有插件协议没有 SIQ 可使用的最终参数执行前再次校验回调。直接在 SIQ pre-hook 等待确认后返回允许，不能证明实际执行参数仍是用户批准的参数。此次不据此实现自动放行，也不修改兄弟仓库。

后续原生继续执行必须有最终参数、原请求标识、当前 Authority、有效期和取消状态的执行前复核；需验证宿主扩展或受控启动的完整链路。保留 ADR-031 的 Hermes 阻断提示，不把“能等待”当作可安全继续执行。该结论是当前安装版本与已检查扩展点的限制，不泛化为所有 Hermes 版本。

## 通知交付

个人 Web 外壳共用一个待办数据源，跨页面每 5 秒读取已有管理列表及待批准 Grant。待办页与导航计数使用同一读回；确认写入后强制刷新，旧请求结果不覆盖新状态。导航的计数不等于实时执行授权。

通知默认关闭，只能由用户点击“开启通知”请求浏览器权限。拒绝、不可用或系统投递失败均不妨碍待办操作。关闭页面后不保证提醒，三系统后台启动器仍归后续交付；浏览器 Notification API 的调用成功也不等于操作系统已展示通知。

通知只显示产品名和待确认数量，不含平台、智能体、工具、参数、路径或结果内容。通知点击仅聚焦本窗口并定位待办详情；多请求时定位列表，绝不调用批准、拒绝、部署或实例发行 API。

同源多窗口通过 Web Locks 协调去重；不支持锁协调时禁用浏览器通知，待办仍可使用。localStorage 只保存启用偏好、按本机签名公钥区分的请求 ID 摘要及最近发送时刻，不存凭据或参数。待处理摘要上限 512；超过时仅发汇总提示。以 500ms 合并同批变化，同源每 15 秒最多一条；后台限流与系统通知设置可能延迟投递。

读回失败时不发通知。关闭、退出管理或快照更换后，未完成的异步准备不得发送旧通知。跨窗口关闭偏好立即传播；关闭当前窗口发出的通知。通知状态不会写入 Grant 或回执。

## 验证

纯逻辑测试覆盖摘要边界、隐私、去重与限流。浏览器验证显式开启、拒绝权限仍能操作、通知点击只导航、批量合并、多窗口去重、关闭与断连；Notification API 用可审计测试替身验证调用和事件，不冒充桌面实际投递。原生通知与三系统实机验收独立保留。
