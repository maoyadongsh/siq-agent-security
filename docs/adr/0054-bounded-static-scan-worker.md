# ADR-054：有界静态扫描子进程

日期：2026-10-07。状态：实施中（OPT-03 / OPT-14）。

## 背景

DGX Spark / Linux arm64 / Python 3.13.12 的受控样本测量中，1,048,576 字节 Python 文本静态分析耗时约 1.49 秒、峰值 RSS 448,536 KiB。请求大小和线程超时不能限制 AST 内存放大，也不能杀停仍在执行的分析线程。

## 决定

1. 控制面 HTTP 扫描使用单次子进程执行已有静态分析器；不引入常驻队列、后台自动重试或模型判定。复用 OPT-03 并发槽，队列长度为零，超额立即 429。
2. 父进程发送内容、文件名、随机任务 ID、验证身份派生的作用域摘要，以及已验证并加载的规则快照。子进程不接收租户管理凭据、数据库地址、签名种子、HOME 配置或请求 Authorization。规则快照摘要绑定任务，子进程不自行读取外部签名包或签名私钥。
3. 输入和输出使用有界 JSON 通道，不使用 pickle 或 shell。父进程核对任务 ID、作用域摘要、输入摘要、规则摘要及分析器版本；只有完整且一致的结果才能进入既有 Finding/审计/Outbox 事务。输出不全、错配、崩溃或预算耗尽返回固定失败类别，不转为 clean。
4. POSIX 子进程在解析样本前设置资源限制：地址空间 256 MiB、CPU 3 秒、core dump 0；父进程墙钟期限 5 秒。结果通道最多 2 MiB。超时/输出超限杀停本次进程组并回收；不会复用失败子进程，也不会自动重试。同步 HTTP 客户端断开不会立即取消已启动的底层任务，但仍受父进程 5 秒期限约束，不能在断开后无限执行。
5. 生产运行必须使用 Linux bubblewrap：独立 user/PID/network 等 namespace，最小只读程序/依赖挂载，无真实 HOME/状态/密钥挂载，禁用宿主网络，空临时工作目录。环境不支持时扫描失败关闭，不默默退回宿主进程。
6. 显式开发模式可使用 `process` 配置做资源控制测试；它不具备 OS 文件系统/网络隔离，不作为生产保护证明。默认生产 `bwrap`、开发 `process`；生产配置拒绝 process。原生 Linux 的 bwrap 路径另有隔离验收。
7. 已有纯函数 `analyze` 继续供规则对等测试和离线语料使用；HTTP 入口必须调用 worker 包装器。规则热更新以每次已加载快照为准，不把不同规则版本结果贴上父进程当前版本。

## 兼容与运维

- 已有 1 MiB 内容上限不意味着任意 1 MiB 输入均可分析成功；复杂样本超出资源预算将返回扫描失败，不写成功或安全结论。
- 部署需安装 bubblewrap 并允许非特权 user namespace。容器运行时的 seccomp/AppArmor/userns 策略可能阻止它；必须验证该部署，不建议为通过扫描而关闭整个容器安全配置。
- 回退时不得把失败记录重解释成已扫描；历史 Finding、签名、规则文件和证据保持原格式。
- 本机制不执行样本、不做动态沙箱分析，不宣称抵抗内核逃逸或任意同 UID 管理员修改程序。

## 验收

普通与恶意固定语料对等；外部已验证规则快照对等；256 MiB/CPU/墙钟/输出超限可回收；崩溃不生成成功审计；治理健康端点可响应；错误任务/租户摘要/输入摘要/规则版本被拒；无父进程凭据继承；真实 bwrap 文件不可见、写入拒绝与宿主接收端不可达。

参考：[bubblewrap 官方选项说明](https://github.com/containers/bubblewrap/blob/main/bwrap.xml)。参数配置本身不构成通过结论，状态以实现与验收记录为准。
