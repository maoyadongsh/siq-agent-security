# ADR-009：OpenShell 版本路径与 patch 治理（草案）

- 状态：**草案，待 D1 spike 结果后定稿**
- 日期：2026-08-13
- 对应开发计划决策 #5 / #8

## 背景

SIQ 冻结 OpenShell v0.0.83（上游 commit e3d26dd3），带 2 个本地 patch；其网络策略为编译期固定集合，动态更新需升级版本或采用 Providers v2。设计文档 §29.1 已把 MVP 动态网络策略设为版本依赖项。

## 待选方案

| 方案 | 成本 | 收益 | 风险 |
| --- | --- | --- | --- |
| A. 升级最新稳定版 | rebase 5 patch + 78 项回归 + bind-mount 契约重审（D1 spike 估计 1-2 周） | 恢复动态网络策略能力，进入上游演进线 | 上游破坏性变更未知 |
| B. 维持 v0.0.83 | 无升级成本 | 现状稳定 | MVP 降级为静态 generation 计划；Interceptor 不可用；长期漂移 |
| C. 升级 + patch 上游化 | A + 上游 PR 流程 | 消除 Fork 债务 | 上游合并节奏不可控 |

## 推荐

先执行 D1 spike（方案 A 的评估版），若 rebase 成本 ≤ 2 周且回归通过，选 A；否则选 B 并接受 MVP 降级。

## 后果

Phase 3 进入条件与本 ADR 结论绑定。
