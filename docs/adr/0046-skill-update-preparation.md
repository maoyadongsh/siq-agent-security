# ADR-046：保留旧版本的更新准备

日期：2026-09-11。状态：准备/读取核心和管理 API 已实施并验证；提交与 UI 待实施。承接 [ADR-045](0045-skill-update-review.md)。

更新计划先固定已批准的新 Grant 和独立副本，再要求明确确认切换。本增量只准备与读取计划，旧目标、旧权限和运行身份保持原状，不把准备视为更新完成。

请求固定原操作签名、新 Grant ID/版本、原 Grant 当前版本、原运行绑定签名、request_id（up- 加 32 位十六进制）及操作者。原目标必须完整匹配签名安装清单与归属；新 Grant 必须同实例/平台、独立于旧 Grant、已批准且期限有效，完整候选与批准来源一致。读取及复制前后复验这些条件。旧权限绑定另一安装时固定保留关联，后续提交不得误撤该安装权限。

`local-skill-update-plan/v1` 以 sup- 加内容摘要标识，绑定原签名记录、新副本来源、两份权限版本/签名、新权限摘要、绑定与保留关系、目标、操作者、文件计数、5 分钟确认期限。计划签名并排他发布到 `skill-installations/update-plans/`；独立副本位于 `skill-installations/update-stages/{sup-id}/payload`。与普通安装计划分开，不能通过普通 apply 接口发布更新。

复用导入模块的受限复制、完整清单校验和独立文件写入；仅新增 update-stages 命名空间，不开放任意复制目的地。相同请求复用同一计划，不延长期限；改变原安装、授权、绑定或操作者时拒绝重用请求编号。最多 64 份更新暂存，计划枚举预算 128 项。未签名的中断副本保留并拒绝隐式接管；本次未发布的失败副本仅清理本次新建的私有目录。

管理 POST `/v1/skill-installations/operations/{sin-id}/update-plans` 创建，GET `/v1/skill-installations/update-plans/{sup-id}` 复验读取。管理权限、取消、安装互斥和时间预算沿用既有实现。读取必须同时核验旧目标、新来源、暂存副本、批准和计划有效期；未完成准备不能显示为可确认。

后续更新提交会先发布不可变事务声明，再撤旧权限/清理原副本/排他发布新副本，并将中断恢复与原计划绑定。它不能自动扩大权限、复活旧授权或覆盖用户内容。本批不提供提交入口；原生运行验证、更新恢复和前端另行实施。计划过期只取消新的确认资格，不自行删除任何用户对象。
