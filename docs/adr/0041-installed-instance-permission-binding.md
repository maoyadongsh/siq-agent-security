# ADR-041：安装内容与实例权限的持续绑定

状态：安装权限绑定核心与管理 API 已实现，Linux 公开 Hermes CLI 验证通过；个人按钮与完整 Skill 归属仍待接通，承接 ADR-039/040。

真实公开 Hermes `skills list --source local --enabled-only` 已识别 SIQ 安装的合成 Skill。清单识别不等于可信加载归属或执行隔离；安装结果不得直接变成 runtime_verified。

安装后的实例权限准备复用已人工批准的 Grant、固定会话引用与实例凭据。新绑定记录限制这份 Grant 只能用于该安装实例和已批准完整内容；准备、凭据发行、认证、会话登记及工具调用前均完整复验。细节与状态目录见 [开发规格](../agentshield-dev-spec-v1.md#安装内容绑定的实例权限准备adr-041)。通用部署按钮仍不能绕过安装器。

先落签名绑定，再以原批准版本 CAS 和审计追加相同批准内容的新版本，旧 Grant 状态保持 approved。仅连续验证安装绑定的固定选择路径可使用该版本；旧二进制拒绝 approved 的运行选择，不能借新数据获得未校验权限。中断遗留绑定不产生执行权限；已授权提交的恢复复用原材料，不签发新权限。每次运行检查会发现内容或权限变化并拒绝，不能仅依赖准备时的历史成功；缺少验证器的离线路径默认拒绝。当前绑定控制的是实例会话权限，实际调用 Skill 归属保持未验证。

验证须覆盖目标/原候选替换、实例错配、原批准变化、撤销/期限、绑定篡改、重复/冲突准备、审计缺失、离线验证器缺省、会话与既有决策的即时失效、所有运行模式拒绝和普通授权兼容。公开 Hermes 清单与真实 CLI 运行分别登记，不用合成 HTTP 代替宿主执行。


## M26 验证与限制

[验证记录](../evidence/personal-experience/installed-instance-permissions-20260911/verification.json)分别记录 Go 核心/HTTP/竞态、跨语言合同、公开 Hermes 清单识别、公开 CLI 运行，以及旧 M25 二进制对新权限的拒绝。原始 Intent.Open 默认拒绝已批准的导入权限，只有显式安装验证读取入口且内容验证成功才可使用；并非任意 approved 均可作为运行权限。

真实 CLI 运行使用现有公开插件启用和 Agent 循环，不导入兄弟内部代码，不执行合成 Skill 脚本；模型只在本机合成服务生成预设 read_file/write_file 探针。当前成功证据是实例权限边界、内容绑定和签名回执，实际工具调用 Skill 归属仍未验证。准备权限不自动签发身份、改写适配器或提升安装结果的 runtime_verified 字段，前端后续复用已有实例管理流程。

为了兼容旧读者，绑定提交追加批准内容版本而不设置旧 deployed 状态。旧版会拒绝这种批准权限的实例身份与会话；这是特定新权限格式的防误用边界，不等于已实现所有历史程序的状态写入禁用。缺少可用工具的授权仍不能创建有效运行会话，其用户提示需随个人接入界面继续完善。
