# ADR-022：接入变更预览、应用与失败恢复

- 日期：2026-09-10；状态：核心实现与 Linux 验证已完成；跨 OS 实机验收待完成。
- 对应 UX-002、UX-006、UX-012；在 ADR-021 的配置诊断上继续实现接入操作。

## 用户流程与合同

`选择安装/卸载 → 获取变更预览 → 确认具体改动 → 应用 → 配置诊断 → 运行自检`。

管理端新增 `POST /v1/adapter/preview`，输入 platform/action。响应 `local-adapter-plan/v1` 包括短期 plan_id、plan_digest、expires_at、将创建/修改/删除的文件、字段类别和必要后续操作；不返回配置正文或凭据。预览只读平台和 SIQ 状态，不创建原始快照，不执行插件，不启用保护。

现有 install/uninstall 路径保留，浏览器必须提交同一管理会话获得的 plan_id/plan_digest。缺少预览、计划过期、对象/动作不符、服务模式变化、文件或安装记录变化时拒绝并要求重新预览。新增管理端 `POST /v1/adapter/recover` 与 CLI `adapter recover <platform>`，显式恢复中断操作；CLI `adapter preview <platform> [install|uninstall]` 只读输出同一脱敏合同。

CLI 的显式 install/uninstall 是用户已授权的操作，内部复用同一规划和应用引擎；不得另走旧的无事务写路径。

操作只记录“配置已应用”；需要重启的宿主会话由用户决定时间。Hermes 原生启用、具体 profile 根和可失效的运行自检仍作为 UX-006 后续部分实现，不能被此事务代替。

## 写入与恢复

- 规划器先读取所有有界常规文件、检查目录祖先、构造准确的目标内容及原始状态。拒绝符号链接、特殊文件、不可解析配置与超限内容；文件路径来自服务端已知平台规则。
- 将每个计划的 before/after 材料加密保存在私有状态目录的 `adapter-transactions/`。使用标准库 AES-GCM 和独立随机本机备份密钥（0600），AAD 绑定事务 ID；密钥不共享给适配器、不使用决策或管理 token 派生。加密保护误拷贝日志/备份的风险，不构成恶意同 UID 隔离。
- 原有不可变 `.siq-agent-security.orig` 快照兼容保留，按既有约定仅用于配置恢复；新事务不将配置原文写入普通审计、API 或业务记录。
- 应用以状态目录中的不可变版本记录竞争同一平台操作 revision。未结束操作会阻止该平台下一次操作；跨进程不能仅依赖内存锁。准备材料与开始审计成功后才修改平台文件。
- 所有文件先整体比对，再在每次写入前检查当前摘要；创建采用排他发布，替换使用同目录临时文件和原子 rename。多文件操作不是 OS 原子事务，不宣称同 UID 并发修改无法发生。
- 保存安装归属与文件摘要，并保留旧记录。成功终态必须在完成审计之后发布；终态写入失败不返回安装成功。
- 中断操作的恢复仅回滚已经写入且仍匹配预期 after 状态的文件。第三方随后修改的文件保留，明确 recovery_required；不静默覆盖、不递归删除未知用户文件、不清除活跃写锁。恢复动作不重新批准安装。
- 文件原权限随 before 状态恢复；新状态与备份目录 0700、文件 0600，需执行的包装器保持必要执行位。Windows 权限和 rename 行为单独实机验收。
- 卸载只处理有归属的具体文件与本产品 JSON 字段，保留用户后来增加的无关设置；不能把整份旧配置覆盖到正在使用的文件上。无法判定归属、内容变化或历史恢复材料缺失时给出冲突，保留现场。

## 验证要求

预览零写入；正常应用和卸载；未预览/错会话/过期/重复/篡改；预览后配置或服务设置变化；陈旧 revision 和并发；开始或完成审计失败；文件写入中断及进程终止后恢复；原始快照不可变；用户新增设置不丢失；改动后冲突保留；备份不含可直接读取的配置原文；符号链接/特殊文件/超限输入。沿用三 OS 四目标编译与 Go/HTTP/浏览器/合同验证。

## 实现限制与后续

- 当前进程锁在 Windows 无法证明旧进程退出，恢复会保守拒绝占用中的锁；需随跨 OS 生命周期实现与实机验收完善，交叉构建不能证明已解决。
- 旧记录缺少归属摘要、原始副本缺失或与当前首次接入内容不一致时返回冲突；保持旧快照不可变，后续提供明确的迁移/人工恢复流程。
- 现有 `.orig` 是受文件权限保护的兼容快照，新事务的完整前后材料使用加密；不宣称所有历史备份已加密迁移。
- 管理 API 返回可操作的错误类别，不把底层 JSON/文件系统错误原文带入界面。详细配置原文留在用户本机，冲突不会触发整份旧配置覆盖。
