# ADR-058：企业 OpenShell 行为验证的单次操作边界

日期：2026-10-08。状态：设计接受，分阶段实施；不表示真实部署已获行为验证。

## 背景

OPT-09 要求企业部署获得绑定真实目标的行为证据。当前部署调用 `adapter.verify(target, checks, receipt)`，没有传入行为证据；有效部署只达到 `readback_verified`。旧 `enforcement-probe/v1` 用于历史离线工具，绑定 revision／digest／目标／指纹，但不设 TTL，也不承担持久防重放。其历史结果与测试保持原语义。

## 决定

新增 `openshell-behavior-challenge/v1` 与 `openshell-behavior-result/v2`。新生产接线只接受由控制面发起并持久登记的独立验证操作，不允许调用者上传一份自述结果直接提升等级。

挑战绑定租户、环境、RuntimeBinding、Deployment、已持久化 OpenShell apply operation、后端目标、网关指纹、策略 revision／digest、受保护探针制品与运行身份摘要。操作拥有随机 nonce、唯一验证 ID、签发时间及不超过五分钟的截止时间。探针执行两份相同 ELF 制品的不同绝对路径，不以 Python／shell 脚本路径推测可执行程序归属；保护和实际运行身份必须由受信任的收集器核验。

第一版执行模板为同一已授权 IPv4 TCP 接收端的差分，3–10 轮，每轮依次执行：边界外可达性前对照 → 边界内允许路径 → 边界内拒绝路径 → 边界外后对照。两份 ELF 内容摘要相同，只改变策略中的程序路径。固定模板不接受 shell 字符串、URL、重定向或任意上传程序。端点来自算子批准的探针配置，不来自用户自由输入；只发送有界合成探针标识。IPv6、DNS、HTTP 语义、替代程序及其他路径在验证范围外，需分别补充协议／实测，不继承通过状态。

结果包含前后独立策略读回、逐轮原始观测和收集器时间。必须核对当前绑定、策略、保护身份、允许规则集合及挑战摘要，逐次核对 nonce、轮次、来源、程序摘要和时间顺序。任何臂缺失、重复、过期、错误绑定、策略变化、对照不可达或探针异常均不升级。DNS 失败不作为拒绝成功；拒绝臂的连接拒绝／重置／超时只有在同一端点前后对照与允许臂均成功时才有差分意义。

## 持久协调与部署等级

协调器复用 OPT-05 的目标互斥与权威身份检查，另行持久保存验证操作。API 按租户和对象授权创建挑战，先提交审计及 running 状态，再执行外部命令；不在数据库写事务内等待网络探针。重复提交相同操作仅返回已记录状态，不再执行。结果采信与消费必须原子 CAS；进程崩溃或租约到期进入 unknown，不自动恢复外部网络访问。重新探测须创建明确的新操作。

纯协议校验器要求可信调用方提供持久运行状态及当前绑定，但不能独立实现数据库 CAS、防重放或外部身份认证。其通过只表示候选观测与挑战自洽，不能直接写入 `enforcement_verified`。持久协调、真实收集器、生产接线、前端范围／时间展示及同目标真实三臂验收完成前，企业入口继续如实显示配置读回级别。

最终提升只适用于本目标、本策略、本探针覆盖范围。策略或绑定变化使旧行为结果失效；保留原始记录供审计，禁止改写历史为新候选通过。Fake／HTTP 后端不能借新协议提升为行为已验证。

## 分批验收

1. 合同与纯校验器：正常差分及目标／nonce／时间／策略／身份／臂故障反例；v1 历史合同不变。
2. 持久协调：并发消费、跨租户、已消费／过期重放、审计失败回滚、崩溃后不重放网络访问。
3. 真实收集器与企业接线：受控 OpenShell 目标、相同受保护 ELF、允许／拒绝／前后可达性实测；错误程序归属和保护不满足时保持未验证。
4. 前端与部署生命周期：明确配置／行为等级、范围、时间、过期和漂移；正式结果不得沿用组件夹具分母。

本 ADR 不扩大 OS 或同 UID 信任边界，不把自报摘要当作独立信任根，也不放宽任何现有安全门禁。
