# ADR-048（提案，未实施）：非凭据路径私有数据读取的可信分类入口

- 日期：2026-09-11；状态：**提案（设计阻塞登记，未实现）**；由 KIMI-001-R1 审阅修复登记，对应原个人任务书 UX-007 相关缺口。

## 背景与缺口

ADR-025 生效后，凭据路径（`.env` 等）在决策边界一律拒绝，且先于目录 allow。引擎目前唯一将会话标记为 `private_data` 的入口是「请求路径命中凭据模式」（`internal/receipt/engine.go` 的 credPathRe 分支，拒绝前仍保守置位）；被允许读取的非凭据路径文件不会产生私有数据分类。因此「成功读取操作员指定的私有（但非凭据路径）文件 → 后续不可信输入 + 出网被 lethal trifecta 拒绝」这一端到端场景在当前合同下不可达。

KIMI-001-R1 的演示分离已按现状交付：凭据读取边界拒绝（执行器未进入、无观测伪报）、非凭据合成夹具真实读取成功且无私有分类（`test_confidential_note_read_allowed_without_private_classification` 固定该事实）、拒绝尝试的保守状态由 `TestLethalTrifectaDenied` 在引擎层锁定。本 ADR 只登记缺口与候选方向，不在本批实现。

## 候选方向（需审阅方裁决，均不动既有授权不变量）

1. 操作员显式声明：Grant/Intent 层增加经人批的「私有数据路径」声明（与凭据 deny 区分），读命中后置 `private_data`；需新合同字段与跨语言向量。
2. 内容分类：对允许读取的文件结果在 Observe 侧做受控的私有内容分类（当前仅 secret/PII 字面量污点）；需定义分类规则来源与防注入边界。
3. 维持现状：凭据路径拒绝即保守置位，非凭据文件不视为私有；端到端 trifecta 演示仅以引擎层测试为准。

## 约束

任何方向不得：放宽凭据路径拒绝；允许模型/适配器自报私有分类；把拒绝尝试的保守污点表述为成功读取后的信息流；改变已签名历史对象。选择后先改规格与合同，再实现。
