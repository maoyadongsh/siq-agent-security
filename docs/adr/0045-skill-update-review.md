# ADR-045：固定候选的 Skill 更新审阅

日期：2026-09-11。状态：比较核心/API 已实施并验证；更新准备、提交与 UI 待实施。承接 [ADR-044](0044-explicit-skill-removal.md)。

更新沿用既有导入、权限审批、安装与撤权链路。新版本先成为完整校验的导入副本，产生绑定其内容的独立 Grant；不能把原安装批准自动用于新内容。本增量先实现只读差异审阅，后续再实现准备、明确确认、切换与恢复，以及远端新版检查，不把比较完成算作更新完成。

管理 POST `/v1/skill-installations/operations/{id}/update-comparison` 只读计算，四个必需字段为 schema_version、operation_signature、candidate_grant_id、expected_candidate_revision。新 Grant 可处于 draft、pending_approval 或 approved，但必须签名有效、未过期、主体和平台与原安装相同，准入与完整新候选一致；不同来源或状态拒绝。原 Grant 由签名安装记录的权限摘要固定，当前允许 approved/revoked；原导入源损坏不改变签名基线，但新候选必须全量校验。已开始移除的安装不能再作为更新入口。

内容差异比较原签名安装清单与新导入清单，包含文件摘要、字节数、执行位、文件/目录类型、新增和删除。既有目标的当前内容检查仍由 inspection 独立提供；比较不证明当前目标未变化。最多显示 200 项，保留差异总数和截断标识，完整清单比较后才返回。名称转义限长，原路径摘要用于区分，不执行任何内容。

权限差异比较去除事实编号、证据和读回来源后的规则：domain、action、resource、effect、conditions、state；state 保守保留，避免把未可执行的声明等同于运行权限。语义完全相同的重复规则按集合去重。另比较默认效果、执行模式、有效期、Hermes 工具集和 OpenClaw 工具策略；不因 Grant ID、来源、签发时间不同就制造“权限扩大”。不自动判断宽窄，也不自动批准：无差异仍需明确确认。响应保留两份 Grant、完整签名引用和差异，客户端不能把展示视为密码学验签。

比较过程不落状态文件、不复制平台文件、不创建移除声明、不撤权或签发运行身份。结束前重读双方 Grant 版本/签名和移除状态，避免把计算期间已变化的权限返回为当前候选。共用安装锁与取消/时间预算。响应声明 platform_changes=false、runtime_verified=false、requires_confirmation=true。

后续切换须固定本次基线与新候选，提前准备新副本；明确确认后使旧权限失效，再只清理归属可证的旧文件并排他发布新文件。中断保留可恢复状态，未知用户内容不覆盖、不删除。失败不能复活旧授权；回到旧版本也需新的明确权限确认。新内容运行身份重新绑定，已有任务不能借旧版本授权继续执行新文件。该事务与 UI、兼容写入防护的实现和验收另行登记。
