# ADR-025：权限编辑前的明确资源边界

- 日期：2026-09-10；状态：资源边界修正已实现并通过 Linux 原生验证；完整权限编辑与可信归属仍在实施；对应 UX-002、UX-007。
- 延续既有 Grant、Intent、回执和人工批准流程，不引入第二个决策引擎。

## 已确认的缺口

当前 Grant 运行选择仍是平台与智能体身份，不是可信 Skill 调用归属。准入内容摘要与配置消费者关系不能证明正在运行哪个 Skill。完整实例/Skill 绑定需独立补齐，界面不能把当前权限显示为已验证的 Skill 独立隔离。

旧工具层 Grant 检查只对未授权写入默认拒绝，普通读取可在无文件范围时通过；路径匹配未区分 fs.read/fs.write；网络匹配会忽略端口，且匹配 allow 时没有完整处理 deny 优先。这些行为无法支持用户明确设置只读目录和网络端口，须在完整权限编辑上线前修正。

## 资源执行规则

1. 文件工具必须有可解析的结构化目标，每个目标均在授权范围内。fs.read 只允许读取，fs.write 允许读取和修改/删除；仅工具名被允许不能代替文件范围。目录匹配必须满足路径分隔符边界，规范化后的越界目标拒绝。路径范围不证明 OS 级隔离或通用符号链接防绕过。
2. 匹配的文件 deny 优先于 allow。凭据路径限制在通用目录 allow 之前检查，广泛目录授权不能绕过原有凭据读取保护。
3. 网络范围是明确的 ASCII/Punycode 主机或 IP 与端口，端口必须精确匹配；支持 `*.example.test:443` 的子域模式，不包含根域。匹配的 deny 优先。无法表达/解析的资源和端口不解释为任意权限；现有端点路径模式不能被降为主机范围后执行。
4. 普通 Grant policy 在 block 模式拒绝；warn/audit_only 保留拒绝建议，不变成强制保护。无效必需 Intent/Authority 继续在全部模式 hard deny。
   脱敏只能改变数据，不能跳过资源范围或工具的人批要求；生成替换参数后重新检查完整 Grant policy，只有结果为 allow 才能转换成 redact，不能将 hold/deny 转换为可执行替换。
5. 已签名历史对象不改写。升级后读取原事实并按修正的 default-deny 规则执行，缺少文件范围的旧授权可能需要重新起草；不能为兼容而自动添加目录。需用新版本完成权限配置和验证，旧二进制不具有本修正保证。

## 后续权限产品流程

继续实现完整资源编辑、只读/读写模板、明确清空语义、精确 revision、审计和重新批准，并统一资产详情和签发入口。可信 Skill 归属、同 Skill 多实例权限、版本漂移和多 Skill 调用边界仍是 UX-007 验收门槛。本增量通过不代表整个 UX-007 完成。

## 验证与兼容边界

新旧二进制使用同一公开 Hermes CLI、同一隔离夹具和合成操作者：Grant 只读而 Intent 允许读写。M7 二进制确实产生测试文件写入；M8 在正常 pre_tool_call 阶段产生 `authority_status=valid`、`policy_action=deny`、`grant_scope_violation`，拒绝前后读取正常且回执链通过。这补充了 M7 自检中由严格 Intent 拒绝写入的证据，不能混淆两个拒绝层。

文件范围匹配保留为工具层声明检查，支持当前明确的绝对 POSIX 路径；不会用缺失资源、相对路径、Windows 路径或不支持的工具参数猜测权限。三系统和各平台参数适配仍需后续实测。shell/exec 保留既有文本提示局限，必需 Intent 对 unknown 的拒绝不变；不据此宣称通用进程隔离。
