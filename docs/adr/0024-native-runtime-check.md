# ADR-024：实例运行自检与临时授权

- 日期：2026-09-10；状态：Grant 期限与 Hermes 产品实例自检已实现，并通过 Linux arm64 隔离 profile 验证；其他平台、OS 和完整 UX-006 仍待验收。
- 对应：UX-002、UX-006、UX-007；延续 ADR-023 的实例与配置诊断边界。

## 问题与事实

配置已启用不等于工具调用经过门禁。自检需要当前目标实例的真实宿主加载、正常读取、执行前拒绝和服务端回执，并在配置、程序或服务身份变化后失效。

Hermes 公开插件接口 `ctx.dispatch_tool()` 在本机版本直接进入工具 registry；实际 `pre_tool_call` / `post_tool_call` 位于 Agent 的工具调用路径。不能把调用前者后得到的结果标为原生门禁验证通过。采用公开 CLI 的原生测试会话，保留正常 Agent 循环与钩子；生产适配器不导入兄弟仓库内部模块。

参考：[Hermes 插件接口](https://hermes-agent.nousresearch.com/docs/developer-guide/plugins)、[公开 CLI](https://hermes-agent.nousresearch.com/docs/reference/cli-commands)。文档与本机实现有差异时，以被验证版本的实际调用证据限定能力，不修改上游内部代码来制造通过。

## 自检流程与信任边界

1. 管理用户明确选择实例并启动自检。服务生成不可预测检查 ID、单次启动凭据与独立测试目录；先记录审计。未确认的扫描、预览和页面轮询不启动宿主。
2. 限定测试材料为本产品生成的普通文本、允许目录与拒绝写入目标；不运行被发现的 Skill，不接受客户端传入可执行命令或任意测试路径。
3. 复用既有 Grant、Intent 和绑定机制，生成仅对本次测试身份、短期限和测试资源有效的临时授权；自检不能有跳过 Authority 或正常决策的特殊 allow 分支。模型和子进程均不持有管理凭据或签名私钥。
4. 原生会话提供真实 session ID。适配器使用独立启动凭据将本次检查关联到该 session；服务仅接受预期平台、实例、运行身份及首次会话。并发替换、参数拼接、过期与跨实例重放拒绝。原生会话之外的普通调用行为保持原约束。
5. 自检依次尝试允许读取、越权写入和再次允许读取。成功判据包括允许结果匹配随机测试内容、明确的拒绝决策、拒绝目标未产生文件、前后回执关联与链校验。宿主退出 0、模型声称成功、健康 API 返回 200 都不是成功证据。
6. 全程记录宿主、适配器、目标配置、服务公钥身份、执行模式和检查方法摘要。完成前再次读回；漂移、超时、缺少钩子、缺少结果、异常副作用各自导致失败或未验证。
7. 结束、取消或失败后撤销临时绑定/授权并清理本次测试材料。撤销失败须明确显示，不能留下长期权限。仅保存限长状态、摘要与回执引用，不保留模型请求、宿主 stdout/stderr 或用户配置正文。

## 原生会话执行选择

先以已安装 Hermes 的公开 `hermes chat` 命令验证非交互运行、CLI 参数、配置兼容、宿主生成的 session ID 和真实钩子。开发验证使用隔离 profile、合成操作者及 loopback 模型；明确区别于对用户现有会话的验证。

自动自检最终必须使用目标实例实际加载的配置与适配器，不能复制一份已修复配置后把结果写回原实例为通过。既有运行会话不自动重启或替换授权；新的测试会话可能产生宿主自身的历史、缓存和启动维护动作，启动 UI 需说明实际影响。

本机模型替身只负责确定性地产生上述固定工具请求；不向模型返回管理身份，不依据模型判断批准或成功。公共 CLI 的参数/环境覆盖能否保证预期模型路由，必须实测后才能写入产品能力。未验证版本不自动启动，也不声称不会触发宿主其他后台行为。

## 状态与剩余工作

已提供独立版本化检查对象，区分准备、等待宿主、执行、完成、失败、取消和失效。旧配置诊断 v1 保持 runtime_state=unverified；检查结果经独立版本合同展示，不回填旧合同未允许的成功值。

`desktop-same-uid` 下，进程、配置与决策凭据仍处于同一用户信任域。检查证明指定版本和调用边界，不证明恶意同 UID 隔离，不扩展为 Skill 归属证明或整个宿主永远受保护。OpenClaw、WorkBuddy 与三个系统分别实现与验收。

## 临时授权的期限前置工作

现有 Grant 合同已含 expires_at，但原决策实现未检查该字段；在使用临时自检授权前先补齐期限。新增 `grant-expiry-edit/v1` 管理请求，pending_approval 下按服务端时间修改期限，变更后重新发起原有人类 challenge。期限覆盖批准、部署、决策和 hold 状态重查；禁止直接延长已批准授权。

`POST /v1/grants/{id}/expiry` 要求有效管理会话、actor_id 和精确的 expected_revision（初版存储 revision=0）。duration_seconds 为 60–2592000 秒，null 明确表示无期限；服务端计算绝对时间并签名。使用既有 CommitGrant，审计未成功发布的版本不能作为已提交授权读取。到期范围为 now < expires_at；非法非空期限拒绝。新的审批挑战有效期取自身 TTL 与 Grant 剩余期限的较小值。

列表中的历史状态不自动改写；新决策检查最新 deployed/effective Grant 的期限，不因为它到期而退回较旧的宽权限。已执行结果仍可按原动作关联规则补交观测、验证历史回执；补交观测不产生新的执行权限。签发页提供期限设置及服务端到期时间，已批准后隐藏编辑入口，后端同样拒绝延期。

公开 CLI 验证使用临时 profile 和测试观察插件从 pre_llm_call 获取真实 session ID，由测试控制器绑定既有 Intent。允许读取、拒绝写入、再次允许读取均经过正常 Agent 循环；CLI 自身生成标题的辅助请求与工具轮次分别计数。它验证公开入口可行性，尚未把观察插件或控制器安装到用户实例。

Grant 仍属于既有 policy 模式边界，warn/audit_only 不升级为强制保护；短期自检还必须有到期后在全部模式 hard deny 的 Intent。缺少这条绑定时不允许运行自动自检。

## 产品协议增量

`local-runtime-check.v1` 区分管理预览、确认启动、适配器单次会话接入和结果。预览不执行宿主，不创建有效授权；服务持有最多 8 个、5 分钟过期、绑定同一管理会话的预览。确认必须给出同一 check_id、plan_digest、人工 actor_id 和 confirm=true；配置与二进制摘要改变时必须重新预览。每个服务同时只运行一个自检，禁止无界进程/材料创建。

确认所授权的固定范围为 120 秒、独立测试身份、两份 SIQ 生成的只读文件及一个仅用于负向测试的写入目标；正常文件读取必须允许，写入必须在执行前拒绝。通过原 Grant 状态机签名与审计，用户确认预览是本次固定临时范围的人工批准依据，不能挪用于其他 Grant。Intent 进一步限制确切读取资源与效果。自动化测试使用明确的合成操作者。

适配器在真实 pre_tool_call 中、普通 decide 之前提交宿主 session_id，使用独立内存启动凭据，绝不使用管理 token。首次绑定后仅同一会话可幂等重试；跨实例、跨身份、会话替换、过期或取消均拒绝。缺失真实 session_id 或启动凭据异常时，自检调用在所有模式拒绝；普通会话不走自检分支，不更改原 policy 模式语义。

结果只保存限长状态、摘要、检查项和回执引用，不保存启动凭据、stdout/stderr 或模型请求正文。Grant/Intent/绑定在结束时撤销，运行崩溃后最多 120 秒失效；重新启动时清理未结束自检并登记中断，不恢复执行。结果只能在临时权限已撤销、材料已清理、回执已校验且目标摘要未变时显示 passed。后续读状态若发现摘要或服务身份变化则显示 invalidated。此摘要限定于被核对文件，不等于整个 Python 依赖和 OS 隔离证明。

若清理失败，管理端可调用 `POST /v1/runtime-checks/{id}/cleanup` 幂等重试既有记录的撤权和材料清理；不恢复宿主执行，不重新批准，不删除任何非该检查材料。不完整的底层 Grant 事务仍由服务持有 writer 锁的恢复流程处理，不能跳过其审计条件。存在清理失败的记录时不接受新自检。

同一管理会话对同一实例重新预览会替换该会话的旧预览，避免正常重试耗尽容量；它不影响已确认的后台自检。当前每个状态目录最多保留 128 个检查，读取有 2,048 个版本文件及单文件 64 KiB 的预算；容量耗尽明确拒绝新检查，历史保留策略随 UX-013 完善，不擅自删除审计或授权历史。

M7 实测入口为设置/运行绑定页的“运行自检”：关闭窗口不取消后台任务，重新打开按实例读取最近结果；取消为独立显式操作。配置归属不再匹配时须先在“管理实例”处理接入；恢复旧配置也不会把已失效记录自动变为通过。结果页按绑定、正常读取、拒绝写入、再次读取、签名链顺序展示五项证据。验证范围与制品身份见 [M7 台账](../personal-experience-development-progress-20260910.md#m7hermes-产品运行自检ux-006-仍在进行)。
