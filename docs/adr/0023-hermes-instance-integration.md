# ADR-023：Hermes 实例定位、原生启用与自检边界

- 日期：2026-09-10；状态：实例与原生配置已实现，运行自检待实现。
- 对应 UX-005、UX-006、UX-012；继续使用 ADR-022 的预览、文件事务与恢复。

## 事实与接入方式

Hermes 以独立 home 表示 profile，配置和插件均位于该 home。默认位置与 `HERMES_HOME`、`<root>/profiles/<name>` 需要一起解析；扫描不能把某个 profile 的已安装文件算给所有实例。Windows 原生默认目录与 POSIX 分开处理。

依据：[官方 profiles 文档](https://hermes-agent.nousresearch.com/docs/user-guide/profiles/)、[官方插件文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/built-in-plugins)，以及本机已安装版本的公开 CLI 实测。CLI `plugins enable ... --no-allow-tool-override` 可在配置副本上启用插件而不执行其入口；这只是当前版本证据，不能代表其他版本或完整运行会话。

## 实例与合同

- 共享目录解析模块向发现与接入提供相同实例定位。实例 ID 来自规范化绝对目录摘要，内容更新不改变 ID；显示名称不作为文件、事务或权限主键。
- 保留已存在的默认/命名 profile 台账 ID，新增自定义根用目录身份避免同名冲突。拒绝符号链接、特殊文件和相对环境根，列举有预算，失败有明确类别。
- 新增管理接口 `GET /v1/adapter/instances?platform=hermes`，返回可选择实例、脱敏目录、配置诊断与限制。读取接口不执行宿主、不启用插件。
- 带 `instance_id` 的预览使用 `local-adapter-plan/v2`，明确目标实例和原生启用选择；未带实例的旧预览保持 v1。应用必须匹配预览中的实例，不能换 profile 或换目录。
- 按实例隔离安装归属、操作 revision、未完成操作与恢复。旧默认目录继续读取原 platform 记录；命名/自定义目录使用独立 namespace。包装器放在实例目录，不覆盖其他 profile 的入口。

## 原生启用

用户在接入预览中选择原生启用后，调用已定位的 Hermes CLI，在私有临时目录里处理配置副本与本产品清单；不对真实 profile 直接执行配置写命令。环境中固定临时 HOME/HERMES_HOME，关闭项目插件，清除凭据与扩展环境，仅传必要的运行变量；stdout/stderr 有界且不作为用户日志或原文 API 返回。

- 使用原生 CLI 解析 YAML、更新启用名单与读取 JSON；Go 不实现局部 YAML 解析器，也不导入兄弟仓库内部模块。
- 不授予 `tools.override`；仅启用本产品插件。核对变更前后其他配置语义，异常变化拒绝进入计划。
- 预览展示宿主配置文件与格式规范化影响。确认后由既有文件事务写入计划内容，CLI 超时/缺失/失败不会留下真实平台半配置。
- 原生读出的配置状态和目标配置摘要一起保存，仅用于配置诊断；文件漂移使结论失效。配置启用不表示实际调用已经受保护。
- 卸载用同样的副本机制撤销本产品登记，恢复接入前本产品启用状态，保留当前其他插件与配置。遇到不兼容宿主或恢复材料不足时保留现场。

## 运行自检

后续自检必须通过真实宿主加载与工具执行路径完成：临时普通读取成功、越界目标在执行前被拒、拒绝目标未产生副作用，并有相关回执。记录需绑定实例、宿主/适配器版本、配置摘要与本地服务身份，漂移后失效。

配置副本的原生解析、仅请求 SIQ API、模拟回执均不能产生“运行自检通过”。夹具验证与实际用户会话状态独立展示；无实时实例证据时继续 unverified。完整会话、跨 OS 和 WorkBuddy 仍各自保留验收项。

## 本批验证

Linux arm64 的浏览器、原生 CLI、经新安装产物进入实际加载器/分发器的调用验证、真实旧二进制升级与四目标交叉构建分别保存证据，见[开发台账 M5](../personal-experience-development-progress-20260910.md)。跨版本验证覆盖旧默认目录的加密归属记录与包装器恢复，不外推到缺少摘要的更早安装记录。CLI 入口摘要用于漂移检查，不宣称覆盖宿主所有依赖文件。
