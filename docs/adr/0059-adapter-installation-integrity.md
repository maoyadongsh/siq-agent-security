# ADR-0059：适配器安装完整性与独立诊断

日期：2026-10-08。状态：实施中，对应 OPT-12。

## 目标与信任边界

钩子目录中的文件不能自行证明其可信性。沿用当前服务二进制内嵌适配器和状态目录中的 AES-GCM 安装事务作为两个独立于插件目录的核对来源；不接受插件提供的新摘要或替代清单。这里的独立是存储与检查入口独立，不是恶意同 UID 的 OS 隔离。可替换服务二进制、读取备份密钥或完全控制宿主者仍在当前桌面信任边界之外。

## 本批行为

1. `Inspect` 在文件存在性判断前读取当前实例的受保护安装事务。已安装但钩子／配置入口被全部删除时返回 `incomplete`，不能误报从未安装。
2. 事务不完整、密封材料损坏或操作与密封内容不匹配时新增 `installation_record=fail`，最终配置状态为 `incomplete`。正常记录显示通过，但 `runtime_state` 始终为 `unverified`。
3. 安装和卸载操作均先认证密封计划，再解释动作；不能通过修改明文 action 为 uninstall、伪造匹配的结束记录来绕过安装归属验证。
4. 继续逐字节核对内嵌插件、连接配置和宿主登记。历史无事务记录保留原兼容诊断，不凭空补齐可信身份。
5. 诊断只读，不自动安装、撤权、阻断或重启。删除钩子可能使宿主不再调用 SIQ；发现漂移不能宣称已阻止该绕过。强制后果必须在另有受保护宿主加载路径的验收中证明。

现有 `local-adapter-diagnostics/v1` 的 check code 是开放的类别字符串；本批不新增字段、不改变 wire 版本或历史签名字节。安装、备份、显式恢复和保留共享配置仍遵循 ADR-022。

## 验证与剩余工作

验证正常安装、删除全部钩子、替换插件清单、密封材料损坏、伪造卸载、升级中断与显式恢复、合法卸载。负向必须在旧实现出现可识别失败，再在新实现通过；检测通过不计为宿主强制阻断。

后续仍需核对完整发行制品身份和可信宿主的受保护加载、安装／升级实际执行后果、跨 OS 原生证据。未完成前 OPT-12 保持 implementing。

## 受保护宿主的实际执行验证

第二批使用独立OpenShell网关、已固定业务基础镜像、当前Hermes原生覆盖层和隔离Go Authority。批准及Skill内容是明确合成测试材料，真实签名、管理／运行HTTP、内核进程身份、文件系统和Hermes工具执行不替换为回调夹具。

先完成writer Skill加载及允许写入；同一非root运行进程尝试改写、删除、替换受root保护的钩子和镜像清单，应在OS层失败。正常写入仍须成功。随后仅对本次创建的沙箱，由宿主测试操作员改变已绑定钩子内容；下一次真实write_file应报拒绝且独立文件观察无副作用。恢复原字节后旧guard仍必须失效，不能自动复活。该管理员故障注入不是宣称能抵御恶意root；它验证独立校验及终态行为。仅运行确定性工具，不调用模型，不修改日常网关、配置、密钥或冻结历史结果。

## 安装程序身份读回

第三批复用既有密封计划中的`BinaryDigest`和准确程序路径，诊断同时核对安装时记录与当前实际程序。程序丢失、摘要变化或当前诊断程序路径与安装记录不同，显示`installation_program=fail`；旧计划缺少摘要只显示unknown，不能补造可信发行身份。新的明确安装／升级仍先预览并固定新程序摘要，应用前复验，成功后新记录成为当前事实；中断恢复后再次以原安装身份为准。无新增状态格式或密钥，不用当前程序自报版本替代文件摘要，不声称快照检查消除同UID替换窗口。
