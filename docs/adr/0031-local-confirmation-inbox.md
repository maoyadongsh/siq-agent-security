# ADR-031：个人统一确认待办

状态：Web 待办及单次处理已实现并通过 Linux 验证；UX-008 继续实施，系统通知与平台恢复执行仍须分别验收。

## 决策

个人控制台增加 `/confirmations`，集中展示运行操作确认与待批准的长期授权。长期授权跳转既有签发详情，继续使用版本绑定 challenge；待办列表和通知都不能批准或部署授权。回执页的历史 hold 链接改为定位待办详情。

`GET /v1/confirmations` 仅管理会话可读，返回 `local-confirmations/v1`。运行待办从已验签恢复的引擎 action 状态派生，最多 8192 条，按原始回执序号倒序；窗口为既有 action 的 24 小时，不是完整历史档案。过期状态仅派生，不写链、不延长有效期；历史仍可在回执中查询。展示参数仅采用既有脱敏、限长 excerpt，不采集或重建参数原文。

`POST /v1/confirmations/{action_id}/resolve` 接收 `local-confirmation-resolve/v1`：decision_receipt_id、decision_hash、params_digest、approve、actor_id 全部必填、精确键名、不接受重复键、null 或扩展字段。单引擎锁内比对原始已签名回执与未处理状态；并发批准只有一次成功，所有重复提交返回 409，客户端刷新读取结果而不再次执行。新入口复用签名 hold_resolution 作为审批审计证据。旧 `/v1/hold` 保持同意图重试幂等，不能生成第二份批准。

有效期采用半开区间：截止时刻已失效。检查绑定 Intent/Grant 当前身份、状态及期限；这不代替平台提交完整参数的 `/v1/hold-status` 执行前校验，不产生新的执行租约。管理页的“已批准”表示存在批准记录，不表示工具已执行；被拒绝、到期和失效请求不能通过新入口批准。实例凭据撤销仍由各决策请求的在线身份校验执行。

统一入口首先落地 Web 待办与现有长期授权详情定位。Hermes 现有 hold 为阻止并提示人工处理，尚不支持批准后原调用自动恢复；界面必须显式说明。三系统后台通知、通知合并和任务内授权仍是后续工作，不能把浏览器页面等同于系统启动器。

## 验证

核心覆盖只读、无原文增量、稳定排序、时间等于截止、拒绝、消费、恢复、摘要错配、绑定/Grant 变化、并发双批与审计写入失败。HTTP 验证管理/决策凭据隔离、严格请求和错误状态。浏览器验证详情确认、重复/过期处理、长期授权定位、移动端可操作性；已处理不得保留可操作按钮。
