# ADR-060：容器控制面的独立静态扫描服务

日期：2026-10-08。状态：已实施并完成本机限定验收，承接 ADR-054 / OPT-14。

默认 Docker seccomp/AppArmor 阻止容器内非特权 bubblewrap 创建 namespace。
采用可选的 `bwrap-service` 部署：控制面保留 Docker 默认防护，通过只读挂载的
Unix socket 连接独立 Linux 用户运行的扫描服务；服务逐次启动原有 bwrap worker。
`bwrap` 原生路径与开发 `process` 保持兼容，生产不接受 process，不自动降级或重试。

## 信任与部署边界

- 通道为 [scan-service v1](../../packages/contracts/threat-scan-service.v1.md)，不开放 TCP。
  服务在读取内容前用 Linux SO_PEERCRED 核对唯一允许的控制面 UID；客户端在发送内容前
  核对服务 UID。UID 使用宿主内核实际映射，rootless/userns 映射需逐部署确认。
- 生产使用独立非 root 服务 UID 和控制面 UID；共享组只提供 socket 访问，不能写目录。
  socket 0660、服务目录 0710、服务所有者持有目录；客户端验证 socket/祖先类型、
  所有者和权限，拒绝符号链接、可被非受信任用户替换的路径。root 管理员与服务所有者
  是受信任部署主体，不宣称抵抗其替换程序或端点。
- 服务不加载控制面 settings、数据库、JWKS、签名材料或用户 HOME 配置；输入只含原
  worker v1 请求。扫描规则由控制面已验证快照提供，不执行样本。结果仍由控制面逐项绑定
  任务/范围/内容/规则/版本后进入原事务。扫描服务没有业务权限、审批或数据库写入能力。
- 实际 API、服务程序及解释器需由部署管理员保护。Unix UID 证明连接进程的 OS 身份，
  不等于二进制签名或对 root 的远程证明。

## 预算与失败

- 服务最多 2 个并发连接任务（可显式配置 1–8）；无应用任务等待队列，满时返回 busy。
  listen backlog 只承担有界内核连接握手，不是持久任务队列。
  控制面进程配额满仍为 429；独立服务拒绝/繁忙经既有 ScanFailure 映射为 503。
- 单连接一次请求，输入 4 MiB、输出 2 MiB；固定头与长度先验，超限不继续读取正文。
  收发共用绝对墙钟截止时间 8 秒，worker 仍受 5 秒、CPU 3 秒、地址空间 256 MiB 限制。
  慢速发送不能逐字节刷新总期限；请求必须半关闭，尾随数据拒绝。
- peer 错误、端点异常、畸形帧、超时、崩溃、输出超限均固定类别失败，无 clean 结果、
  无后台自动重试。客户端断开后的已启动 worker 最多继续原 5 秒预算；服务停机等待所有
  有界处理器退出，再只移除本服务创建且 inode 匹配的 socket，不删除别人替换的端点。
- 服务只中继有界字节，不输出样本、规则正文或原始异常。客户端拒绝未知状态及失败正文。
  SO_PEERCRED 不是多租户身份；租户鉴权、配额和审计继续由控制面承担。

## 验收与回退

先验证帧/UID/路径/预算/停机/不重试与业务失败无成功事务；再用实际 Docker 非 root
控制面客户端、宿主 bwrap、真实静态分析器验证正常、恶意、内存/CPU失败后的恢复及
文件/网络隔离。明确开发身份 HTTP 与生产身份验收的区别。
不使用 privileged，不关闭默认 seccomp/AppArmor，不挂载 Docker socket。
停止扫描服务后控制面扫描失败关闭；恢复原生 bwrap 配置只适用于已验收的宿主运行环境。

实施验证见[本机验收记录](../development/optimization-opt14-host-service-validation-20261008.md)。
历史 ADR-054 的直接容器限制仍属实；通过的是本 ADR 的独立部署路径。
