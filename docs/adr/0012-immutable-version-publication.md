# ADR-012：本地不可变版本的排他发布

- 日期：2026-09-06。
- 状态：实施中，依据用户授权执行联合开发计划 DEV03。
- 范围：grant 与资产/finding 的版本文件；不是多文档事务或审批 CAS 的替代。

## 决策

旧实现先 Stat 再 O_EXCL，公共 writeNew 将存在冲突当成功，造成成功响应对应的内容丢失。新版本在目标目录创建私有暂存文件（CreateTemp 使用 O_EXCL、0600），完成写入、Sync 和 Close 后，以标准库 os.Link 创建最终版本名。Link 对已有目标失败，因此不会覆盖旧版本；只对目标已存在重试下一序号，其余错误立即失败。暂存名不匹配正常 JSON 枚举规则，读者不会看到半条版本；退出时删除本次暂存文件，崩溃遗留文件不参与读取。

本地文件系统必须支持同目录普通文件硬链接，例如常见 Linux 文件系统、APFS 和 NTFS；不支持时拒绝版本写入，不回退到覆盖式 rename 或可见半写。所有支持平台仍需实机验证；交叉编译不证明文件系统行为。

完成内容 Sync 不等于所有 OS 上目录项在断电后均已持久化。单写者与 grant expected revision CAS 由 DEV03-B 落地（`AcquireWriter` + `PutVersionedCAS`）；审计/多文档提交协议和 hold 决议 CAS 仍由 DEV03-C 负责。固定 ID 的 admission/evidence/policy 暂不套用版本追加：其 ID/签后修改与真实幂等需一起修复，不能保留为已解决声明。

## 验证

不同 Store 实例、并发 goroutine 和独立进程写同一对象时，每个成功写入都有独立完整版本；旧文件字节不变；编码/发布失败无正常最终文件；读者不把损坏最新版本静默视为缺失。真实文件系统不支持排他发布时给出明确错误。
