# ADR-033：Skill 固定导入副本

状态：实施中；UX-009 的所有来源共用的存储与准入基础，完整安装流程仍待实现。

## 完整流程与本批边界

目标流程为本地目录、仓库 URL 或下载 URL → 受限获取 → 固定副本 → 准入 → 权限审阅/批准 → 平台安装 → 读回内容。先实现共用的固定副本存储及本地目录/本地 ZIP 获取，再接 HTTPS/Git、安全来源解析、管理 API/UI 和平台安装事务。当前 `local-skill-import-create/v1` 只声明已经实现的 local_dir/local_zip，不宣称 URL 获取、授权或安装已可用。

输入有客户端生成的 `si-<32 hex>` 请求 ID、来源类型/路径和操作者。相同 ID 与来源路径摘要/操作者重试返回既有已验证副本，不重新读取后来变化的源；不同输入冲突。原路径不进入签名记录，只保存摘要。失败不覆盖任何已有 Skill。

## 固定副本与信任

`<state>/skill-imports/blobs/<id>/payload` 存放必要的原始包内容，0700 目录、0600/0700 文件；程序永不执行、导入或 eval 包内容。此安装候选副本与审计原文存储分开，不因“原文审计关闭”丢弃安装所需文件。已有 fileopen.Regular 提供 ADR-013 的平台读文件保护，不新增 syscall。

导入拒绝符号链接和特殊文件，复制为独立普通文件。拒绝绝对/父级路径、反斜杠、Windows 设备名/ADS、尾随点或空格、控制字符、重复及大小写冲突路径；实际写入 O_EXCL，文件系统自身认定重名时也拒绝。`.git` 元数据不复制，排除行为明确记录；不运行 Git 钩子、归档脚本或嵌套解包。ZIP 的 SKILL.md 必须位于所选归档根，不猜测多个子目录。

上限：2000 文件、2000 目录、深度 16、路径 512 字节/段 128 字节、单文件 8 MiB、总内容 64 MiB；ZIP 输入 32 MiB，中央目录先限条目数与字节，拒绝多卷、ZIP64、加密及非 Store/Deflate。实际解压流仍按字节上限、大小和 CRC 检查。状态区最多 64 个候选目录，包含孤立目录，防止无限创建。耗尽空间或取消时无已发布可用记录。

完整 artifact_digest 覆盖排序目录列表、所有实际复制文件的路径/字节数/sha256/可执行位。它与既有 admission.content_hash 是两个不同身份：后者按旧合同跳过签名辅助文件，前者固定安装载荷的一切实际内容，不能混用。准入仅对固定 payload 运行。analysis.json 只保存准入、脱敏证据和卡片，不重复保存 Frontmatter 原文；其摘要由导入记录签名绑定。

最终 `records/<id>.json` 是单次导入的签名审计事实，包含 actor、时间、完整清单摘要及分析摘要；最后用 os.Link 排他发布，失败不暴露可用候选。未发布目录不能用于安装；恢复不擅自接纳孤立目录。同 ID 的并发创建通过进程锁和现有 daemon writer 锁协调。Load 必须重新核对记录签名、完整载荷清单、分析摘要与准入签名；任何差异拒绝后续使用。被准入隔离的副本可以留作审阅，不产生批准或安装权限。

这些保护检测导入和使用之间的内容变化，不构成恶意同系统用户的文件系统隔离或断电持久性保证。未来安装事务仍需在目标目录发布前和读回时绑定同一 artifact_digest，不能仅凭本批导入成功就声称安全安装完成。

## 验证

目录与 ZIP 正常导入；源变化不改变既有副本；payload/分析/记录替换被拒；路径穿越、链接、设备名、重复/大小写、特殊文件、ZIP 元数据欺骗/CRC/解包超限、取消、并发同 ID、签名失败和不可用存储不发布可用记录。新合同样例由 Go 输出并交 Python 校验；三系统交叉编译不等于实机安装验收。

## 首批可操作入口

`siq-agent-security import-skill --path DIR --kind local_dir --actor ACTOR [--id si-...]` 固定并分析本地目录；`--kind local_zip` 处理本地 ZIP。ID 未指定时随机生成，指定原 ID 可重试并验签读回固定副本。命令取得既有 state writer 锁；已有 serve 进程占用同一状态时明确失败，不并发写入。管理 API/UI 将在后续批次接入这同一核心。响应 `local-skill-import-result/v1` 的 installed 恒为 false，包含签名导入记录和准入结果，不自动创建 Grant 或修改平台目录。

## 管理接口

`POST /v1/skill-imports` 接受同一 create/v1 严格请求，返回 result/v1（首次 201，已验证同 ID 重试 200）。`GET /v1/skill-imports/{id}` 重新验签和重算全部副本后返回同一结果（reused=true），不读取原目录，不产生批准。两个端点只允许管理会话，继承 loopback、Host/Origin 与凭据分权；决策凭据不能导入本机文件。请求 16 KiB、必需字段精确大小写且非 null；API 路径必须为本机绝对路径，不能依赖 daemon 工作目录。返回不含源绝对路径、文件正文或凭据。

每个 daemon 同时最多处理一个导入/完整读回，繁忙返回 429 + Retry-After，不在 HTTP 内无限排队；处理绑定请求取消及 60 秒期限。超时 408，非法输入 400，超限 413，ID 冲突/内容变化 409，缺失记录 404，存储不可用 503；错误只返回固定类别。核心创建等待进程锁时也响应取消。读取和导入始终 `Cache-Control: no-store`。客户端断连可能发生在最终发布之后，必须以原 ID 重试/查询确定结果，不将断连解释为必定未导入。候选记录就是已签名的导入审计；本接口不把候选插入全局准入/Grant/资产台账，不声称已安装。后续权限准备和安装将明确绑定这个候选。

同步导入/读回端点将本次响应写入期限设为 65 秒，以容纳 60 秒处理预算；仅在管理认证、请求解析和单并发取得后调整，其他端点保留既有 15 秒写期限。设置期限失败时不开始导入；不支持 ResponseController 的内存测试 writer 由请求上下文约束。
