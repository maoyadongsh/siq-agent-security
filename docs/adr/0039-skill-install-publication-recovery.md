# ADR-039：Skill 文件发布、归属与恢复

状态：提交、目标读回与恢复核心已实现并通过 Linux 隔离验证；管理 API、确认界面和原生平台识别仍待接入。承接 ADR-037/038，UX-009 仍在进行。

## 安装与保护的事实边界

任务书 §4.3 顺序保持为：固定候选、批准权限、用户确认、安装具体内容、平台识别和保护验证。安装记录只能证明目标文件与批准摘要一致；不能通过写入文件将 Grant 标记 effective，也不能冒充已验证 Skill 运行归属。既有导入 Grant 的通用 deploy/effective 禁止路径继续保留，后续接入只能通过明确证据协议实现。

Hermes 官方 [Skills System](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills) 与 [Working with Skills](https://hermes-agent.nousresearch.com/docs/guides/work-with-skills/) 描述 profile 内 skills 目录、分类子目录与 SKILL.md 识别。2026-09-11 查阅；文档不是本机宿主版本实测，也不能推断它会遵守 SIQ 的事务标记。安装器不能假设“未提交标记”可以阻止宿主读取文件。

## 不覆盖已有文件的发布方式

不以 os.Rename 作为跨系统 no-replace 目录原语。实际安装前重新读取已签名预览、当前批准 Grant、完整候选与暂存，要求签名、版本、操作者、目标和有效期一致；用户确认须绑定具体计划签名。只允许预览中经可信解析器得到的新目标目录，不复用已有目录。

安装准备在对应 profile 的私有操作目录中进行，位于默认 skills 搜索目录之外。文件先以不含 SKILL.md 的不透明名称写入、同步和校验，再通过标准库 os.Link 排他发布到独占创建的目标目录；每个最终路径必须不存在，不支持硬链接或跨文件系统时显式失败。平台文件与操作副本的链接只用于证明本次发布归属，原始已检查候选和状态目录暂存保持独立副本。运行期修改链接文件会影响操作副本，因此恢复必须同时核对签名清单中的原摘要，不能仅凭 SameFile 删除。

目标目录采用 Mkdir 独占创建。每个自建目录通过操作侧与目录内的专用归属标记关联；包中与保留元数据名称冲突的路径须在写入前拒绝并清晰提示，不静默丢弃内容。归属与文件发布记录均绑定计划和具体相对路径。普通支持文件先发布，所有 SKILL.md 入口延后，根入口最后发布；最终再次核对整个目录与批准清单。

这是一组可恢复的排他文件发布，不声称整个目录在所有 OS 上原子可见。嵌套 Skill 入口可能分步出现，异常状态必须如实报告；宿主识别/保护验证另行完成。不得通过悄悄排除嵌套文件来使清单检查通过。

## 事务与恢复约束

外部目标写入前，先排他发布签名操作声明，绑定计划签名、来源、批准权限、操作者与清单。完成记录最后发布，必须建立在目标完整读回之上；请求响应丢失时复验原操作，不重复安装。继续使用现有 state writer 锁和进程内串行入口。

恢复不依赖授权仍未过期或候选仍完整：恢复依据是已验签的原操作清单及本次发布的归属证据。恢复只能删除内容仍符合原清单、文件身份仍匹配本次发布、目录归属仍有效的对象；用户新建或修改的内容保持原状并返回需要处理的冲突。删除前重新核对，不能对平台目标使用无条件 RemoveAll。

Mkdir 与写入归属标记之间存在跨进程崩溃窗口。重启后若无法证明目标归属，即使目录为空，也不得猜测它属于 SIQ；保留目录，明确报告 recovery_required。正常异常路径可以结合当前进程持有的文件身份清理自建空目录。不得把“留下无法证明归属的目录”报告为已回滚，也不得用清理未知文件换取成功状态。

同 UID 恶意并发替换仍不构成已解决的 OS 隔离问题。后续界面应分别呈现未安装、已安装但未完成保护验证、恢复完成、需人工处理，避免用单一成功布尔值混淆这些事实。回滚不重新批准或恢复已撤销授权。

## 固定副本读取接口

安装器需要按已批准的完整清单读取文件，避免每复制一个文件都重新扫描整个候选。skillimport 提供只读 InstallationSnapshot：打开时完整 Load 并固定已签名元数据；Metadata 返回独立副本；ReadFile 只接受清单中的准确相对路径，每次重新检查目录/文件类型、内容摘要、字节数与执行位，返回字节而不写平台路径；Verify 在整批读取后完整复验原候选及元数据签名是否仍匹配。

ReadFile 是单文件校验，不是整份候选、准入或当前运行授权的重新批准。安装器必须在发布前后结合 Verify、暂存与目标读回，以及当前 Grant/计划期限重新校验。此接口不执行脚本，不读取清单外文件，不允许调用方修改返回的 Metadata 来扩张读取范围。

## 必需验证

固定读取：完整清单中非 SKILL.md 辅助文件的替换、执行位改变、符号链接、清单外路径、原始来源后来变化、元数据返回值修改、取消、最终分析/签名变化必须有正负向测试。

事务：已有路径与大小写冲突、创建到标记的崩溃窗口、每个排他发布窗口、撤权/到期、源/暂存/目标替换、响应丢失、重复确认、恢复时用户改动、原生平台识别以及三系统真实文件操作分别登记。仅有固定读取测试或交叉编译不能标记安装事务完成。

## M23 落盘范围

本次已实现并验证 InstallationSnapshot 固定清单读取，接口不写平台路径。Go 全量、vet、skillimport/skillinstall 竞态检查与四目标所有包编译通过，见 [验证记录](../evidence/personal-experience/skill-install-snapshot-20260911/verification.json)。目标文件排他发布、签名操作声明、跨重启恢复及安装确认入口仍按上文方案继续实现，尚未提供“实际安装已完成”的用户状态。本次没有新增 HTTP/JSON 输出或更改既有导入 DTO。

## 第一版提交合同

`local-skill-install-apply/v1` 必需字段为 plan_id、plan_signature、actor_id、confirm_install=true；操作者须与计划一致。install_id 为计划 sip- 前缀替换为 sin-，一份计划只有一次操作。写入前发布 claim/v1，包含完整计划、清单、操作者、时间与签名；清单规范化摘要必须等于计划 artifact_digest。

状态目录保存 `operations/<install_id>.claim.json`、首次 `result.json` 与后续恢复成功的 `recovered.json`，均排他发布。operation/v1 状态为 installed_unverified、rolled_back 或 recovery_required，记录 claim_signature、actor_id、时间及 runtime_verified=false。已成功安装的原请求重试只复验当前目标，不延长授权或重新安装；尚无结果的已声明操作需要显式恢复，不能重新认领目录。后续 Recover 可在权限撤销/到期、原候选损坏时按原签名清单清理，保留最初失败记录。

profile 下 `.siq-agent-security-installs/<install_id>/` 保存不透明 f-xxxx 文件与 d-xxxx 目录归属文件，均不命名为 SKILL.md；目标各自建目录的 `.siq-install-owner` 链接对应 d-xxxx。该保留名称在候选任意路径分量中出现时，提交前以固定 skill_install_reserved_metadata 类别拒绝，供界面明确提示元数据名称冲突。归属文件为 owner/v1，签名绑定 install_id、claim_signature 与 relative_directory。操作副本留作恢复证据，后续清理生命周期由 UX-010 接入。平台目标目录只清理经完整归属/内容检查的对象；未知内容、被修改对象和缺失归属均报告恢复冲突。

本用户开发周期中，目标路径之外写入的例外仅限明确确认计划绑定的 Skill 目标与对应 profile 私有操作目录；准入、授权、签名私钥、原候选和操作日志仍仅位于状态目录。此例外不允许执行候选代码或改动未确认的用户目录。

## M24 提交与恢复核心

已实现 Apply、ReadOperation 与 Recover。正常标记写入失败时，当前进程只尝试移除文件身份仍相同的空目录；真正进程退出后没有这些内存证据，仍保留未标记目录并返回 recovery_required。文件与目录包含未知内容或用户修改时，恢复先停止，避免先删除部分已知内容再发现冲突。目标副本采用硬链接关联本次不透明操作文件，原始候选保持独立。

[本批验证记录](../evidence/personal-experience/skill-install-publication-20260911/verification.json)覆盖正常写入/完整读回、签名与内容复验、期限后原请求只读重试、不激活运行权限、撤权/取消、大小写冲突、操作副本修改、用户文件保留、嵌套文件/入口顺序、保留元数据名称与容量边界。独立 Go 子进程在 spooled、directory_created、file_published、before_result 四处退出，父进程重新打开状态并恢复；这是进程退出实测，不是断电或三系统原生验收。

四份 Go 输出合同样例由 Python 验证，独立重算完整清单摘要并验签 claim/owner/operation。样例引用 M21 的规范化签名计划，不是当前可提交的真实用户目标。核心库尚未接到管理安装按钮，也未运行 Hermes/OpenClaw/WorkBuddy 宿主或修改用户日常配置。下一步接通明确安装确认、结果显示和恢复入口，再完成平台识别及保护验证。
