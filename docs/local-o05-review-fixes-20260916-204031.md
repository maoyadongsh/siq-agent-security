## 结论

已修复本次复核发现的阻断误判、成功路径未恢复策略、批准与策略参数脱节及证据失败误报成功问题。完成本地代码和回归验证。L01 修复后真实行为复测未执行；L02 仍是策略控制面原型，不能作为 O05 沙箱任务执行或 B3 端到端验收。

## 修复内容

1. **阻断证据**：超时、断网、未知 CLI 输出、HTTP 404/500 均不是阻断成功；必须显式 HTTP 403 且关联接收端零到达。两个精确目标均先放行并证明可达，再撤去违规目标的放行。传播等待有上限且只重试明确 403。
2. **真实恢复**：移除仅设置 restored 标记的路径；正控结束、最终成功及失败清理都通过精确操作回执授权回滚、漂移检查及摘要读回。未知漂移不强制覆盖；恢复失败使测试失败。
3. **批准绑定**：仅接受固定 policy_apply 操作参数；目标、全部端点、程序路径、预期修订、唯一已签名 Grant ID/digest 与后端指纹必须与原批准完全一致。原先获批的任意 exec 不能被拿来改策略。Grant 必须验签、未过期、已部署且 subject/platform 一致；不合并其他 Grant 扩权。
4. **写前复核**：完成网关读前检查后，再查当前 Grant、会话及预留身份；撤权时零写入。并发同一次批准只能产生一次写入，不声称跨进程原子性。
5. **证据与范围**：证据、审计或 observation 失败不返回成功，保留已发生副作用及未决预留。已知写后读回失败保留操作映射，后续恢复仍须通过漂移与授权检查。响应明确 scope=policy_apply、task_executed=false；预览只汇总当前有效签名 Grant，不作为写授权。
6. **文档**：增补修复规格和独立未发布 v1 合同；进度文档置顶修正旧 L01 PASS 与 L02 完成口径。历史证据不改写。
