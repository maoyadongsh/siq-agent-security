# Research overview

An agent can choose a plausible tool call while lacking authority to execute it. SIQ Agent Security separates proposals from runtime permission and separates a tool's success message from independently observed effects. It provides an executable research example with structured task intent, registered source provenance, action-bound authorization, signed receipts and scoped completion evidence.

The same recipient text can produce different decisions when one instance comes from a trusted contact source and the other from an MCP result. A delivery tool can report success while the controlled receiver provides no effect; completion then remains incomplete. These are specific implemented checks, not general semantic understanding or universal delivery verification.

Start with [key-free reproduction](../../REPRODUCIBILITY.md). Tracks A/B exercise real runtime components using explicit model fixtures. Real StepFun/Ornith inference is optional track C and has separately recorded historical evidence. The optional enterprise Control API and connectors remain available without becoming prerequisites for the small local demonstration.

Read the [technical report](technical-report.md), [research questions](research-questions.md), [data card](dataset-card.md) and [claims/evidence mapping](claims-evidence.md). The fixed corpus is small and developed alongside the implementation; it is not held out. Earlier failures are retained. There is no paper acceptance, DOI or independent reproduction claim.
