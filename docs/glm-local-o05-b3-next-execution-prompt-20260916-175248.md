### L02：实现 O05 会话执行最小闭环（主开发任务）

1. **预览**：选定已配置后端/目标，展示身份、最终操作及其权限要求、策略修订、可验证保护范围；预览不执行、不扩大权限。
2. **确认与绑定**：服务端从可信状态解析用户/实例/会话/Skill/Grant/目标/最终参数及策略摘要；用户提交的字段仅作请求，不是授权事实。

4. **受控执行**：只用实际存在、版本可验证的后端能力。required 后端不可用、身份不明、绑定不匹配或证据过期时拒绝，不回落 native。未选择 required 的既有 native 用户流程保持原合同。
5. **停止与恢复**：只能停止本次拥有的操作/目标；区分停止请求、停止确认、已发生副作用和未知结果。断线/超时/重启后不能把 uncertain 写成“未执行”，不能自动重放。
6. **结果追溯**：把任务、会话、工具调用、授权/审批/预留、目标/策略修订、实际执行结果和独立证据可靠关联；存储保持脱敏、签名、不可变记录与完整性校验。
7. **界面**：在现有本地管理流程中提供必要的预览/确认、状态和结果入口；不扩展成通用任务工作台。仅配置读回时明确显示“未验证实际执行限制”。

## 6. 候选、证据与资源管理

每批新建时间戳目录，例如：

```text
docs/evidence/personal-experience/local-o05-b3-<YYYYMMDD-HHMMSS>/
```

最少交付：

- `baseline.json`：HEAD、dirty 输入清单与摘要、工具链、OS/arch、归属/依赖；
- `checks.json`：逐项 ID、预期/实际、证据等级、命令或脱敏 argv、退出码、候选 SHA、引用；
- `report.md`：完成范围、失败、未执行、根因证据、解除条件；
- `resources.json`：本批创建/清理/保留的 target、unit、PID/端口、临时目录及归属依据；
- `SHA256SUMS`：覆盖对外证据文件，不包含自身；在提交前确认每个被引用文件没有被 .gitignore 隐藏；
- 性能批额外有测量前冻结协议、逐样本原始数值、失败/污染披露与汇总。

不改旧证据及其哈希，错误结论用 superseding review 纠正。原始私有日志留在 0700 目录/0600 文件，公开材料只保存脱敏必要字段。

候选必须绑定 HEAD + 未提交生产差异及新增源码、构建参数、嵌入 UI、Go 工具链、四目标制品摘要。生产源或嵌入 UI 改动后冻结新候选（先检查命名，选择未占用的版本/目录），禁止覆盖 rc.1/rc.2。新增候选不继承旧实机证明。

临时资源只能按精确 ID 和本批创建证明清理。失联或恢复失败时先保留证据和资源清单，不广泛 kill，不通过覆盖漂移状态强行恢复。普通测试日志、浏览器原始截图、源码包与二进制不盲目加入 Git。
