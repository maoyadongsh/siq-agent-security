# WorkBuddy 接入中断恢复 v1

2026-09-18；补充既有 adapter recovery 规格，不改变授权、会话或 v1 合同。

管理端 `POST /v1/adapter/recover` 接受 `platform=workbuddy`，必须提供发现所得的 `instance_id`。服务端仍从可信 inventory 解析唯一配置根，不接受请求自报路径。管理凭据限定及 `Cache-Control: no-store` 保持。未知、缺失或歧义实例不能触发恢复。

WorkBuddy 的历史操作键保持 `workbuddy`，以兼容已有备份。因此当前根与历史根的比较必须发生在既有 `adapter-write` 跨进程锁内：读取未完成声明，解密并校验完整恢复计划后，以该计划中固定的实例、配置根和宿主配置文件归属，对比本次可信选定的根。不可使用未认证的 claim.Record，也不可用当前环境变量重新推导历史根。已固定实例的计划须同时匹配 Options.Instance 与 Record；旧无实例计划只能从已认证的唯一 settings.json 归属路径恢复历史根。根不同、归属不唯一或元数据矛盾时返回变更冲突，在恢复审计和任何宿主文件写入之前拒绝。其他宿主恢复范围保持不变。

恢复只回滚未完成事务；不续权、不撤销身份吊销、不重建有效授权。每个目标仍按原始前后像核对：未变动的本产品写入可以撤回，用户后来修改的文件必须保留并报告 recovery_required，不能默默删除用户字段。其他用户文件不在计划内，不读取或修改。恢复成功保留原有审计和幂等终态。

验证包括管理 HTTP 接通、缺失及错误实例、决策凭据拒绝；真实产品 Apply 子进程在测试边界退出后的恢复、跨根恢复拒绝（包括篡改明文 claim.Record 无法更换解密计划归属）、外来配置保留、用户另加文件保留以及原有其他宿主恢复定向回归。测试只使用新建临时状态与配置，不启动 WorkBuddy 或调用模型。
