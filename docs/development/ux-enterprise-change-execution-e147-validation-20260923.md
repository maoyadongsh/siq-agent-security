# 企业逐单部署与审计验收（E147）

日期：2026-09-23。承接 E146，继续 ENT-UX-04。总体目标保持 active，外部深度检查 SEC-F01–SEC-F10 仍按用户要求后续排期。

## 本批实现

变更列表新增“部署与审计”入口，直接读取所选变更的部署及关联审计。移除原先依赖全局部署第一页的摘要，旧记录不会因为其他变更较多而被漏判。URL 保留变更标识和结果视图，刷新仍读取同一对象；桌面和手机都可使用。记录过多时内容区独立滚动，“关闭”“刷新记录”保持可见。

每条部署明确展示登记目标、环境、时间、任务状态及验证证据。仅创建下发任务不显示已生效；配置读回与行为验证分别解释。失败、回滚、独立读回不一致或不可达不能沿用旧的成功文案；历史验证不代表当前持续保护。“刷新记录”只是重新读控制面，不暗示已主动探测执行端。

审计通过本变更 ID 及其部署 ID 精确关联，展示动作、账号、时间，技术标识/摘要可展开查看。审计需要独立的 audit:read；环境名称需要 env:read，缺权不暗授权限或泄露审计数量。dev/fake 路径的 deployment.create 过去漏写 resource_id，现与创建状态同事务写入部署 ID；不猜测或补写历史未绑定审计。

部署 POST 返回后，打开结果窗口并独立 GET 核对返回的部署标识，不以响应成功替代执行结果。网络/5xx 等未知结果保留“待核对”状态，同页不直接再次提交；关闭窗口后仍能进入核对，URL 中的待核对提示刷新后保留。明确的前置拒绝仍可修正条件再操作。没有部署记录不能证明后端未执行。

## 浏览器发现并修复的相邻问题

Layout 原本用 pathname+search 驱动整页重挂载。打开或关闭结果窗口会卸载变更页，重置已选部署目标及待核对状态。现仅 pathname 变化重挂载页面，同页查询参数交由页面处理；原候选、环境、审批和工作台流程已回归。部署环境/运行时绑定下拉框补充固定的可访问名称，避免选项内容进入标签后影响准确定位。

首版长记录窗口的底部操作需要滚动整份记录才能看到，已改为独立内容滚动，并用真实手机视口坐标断言关闭按钮始终在窗口内。最终截图关闭有限 CSS 入场动画后采集，避免把动画中间帧当作稳定界面。

## 合同与边界

新增 `change-execution/v1`，路由 `GET /api/v1/change-requests/{id}/execution`。先按验证租户定位再检查 policy:read；部署与审计查询均限定租户和准确对象，GET 不写入审计或业务状态，Cache-Control=no-store。时间统一输出 UTC，前端按本地时间显示。

默认最多 20 次部署、50 条审计；“查看更多”扩大到 100/200。各自截断状态明确，超过上限不宣称已经展示全部。响应不返回原始 receipt、自由格式 verification、异常文本或任意审计 summary，只提供有界字段、验证枚举及合法 SHA-256 摘要。前端拒绝对象错配、重复记录、超限、权限矛盾和未知多余字段。

**剩余边界**：没有新增持久部署意图/幂等任务表，没有证明跨页面/浏览器重启/多客户端情况下的执行恰好一次。完整部署预览、持久重试协议、主动执行端复验、任意深度历史分页仍需后续实现。验证状态来自已有控制面记录；UI 本身不能提升验证强度。
