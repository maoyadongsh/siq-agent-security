# OPT-08 B1：原生 Skill 上下文持久化验证

日期：2026-10-07。状态：B1 组件通过；OPT-08 仍在实施，日常入口尚未启用 v2。

## 功能与实现范围

在 [ADR-056](../adr/0056-native-skill-invocation-authority.md) 约束下新增 `InvocationStore`。上下文与撤销分别保存在独立 `skill-contexts-v2` 和 `skill-context-revocations-v2` 目录；旧 v1 文件、读取器及单 Grant 安全不变量保持。此组件尚未增加 HTTP 端点，也不返回工具调用 allow。

签发从已验证实例推导 Agent baseline，从安装记录推导 Skill Grant；二者必须签名有效、归属一致、生命周期有效。Agent baseline 不得携带 Skill。每次验证重新读取授权、安装记录及内容、session 绑定、可信原生任务/加载与精确父链。回调是可信宿主的必要依赖，未提供则不能打开组件，不使用默认通过实现。测试注入依赖并不表示这些依赖已完成真实宿主接入。

同一次原生加载具有确定性 ID，重复请求仅返回仍有效的原始签名文档，不能更新安装、父链、授权摘要或延长租约。父链最多八层，subject 和 Agent authority 完全相同，子租约不超过任何祖先。返回当前 Skill 与全部祖先 Skill 的独立 Grant 快照，供后续引擎计算交集；不以某个“最新 baseline”替换原绑定。

撤销采用新增 v2 墓碑合同，绑定原上下文完整签名，重复撤销返回原文，不删除原上下文。父节点撤销使后代验证失败。审计成功后才排他发布文件，审计记录不能证明发布已完成；发布失败保留冲突对象，拒绝授予上下文。沿用 daemon 的跨进程状态单写者锁，进程内互斥不替代它。

## 验证内容

| 范围 | 实际验证 |
| --- | --- |
| 持久恢复 | 独立子进程完成签发后直接退出，父进程依靠文件和重新提供的可信依赖恢复验证及撤销；重新打开 Store 后幂等返回原文 |
| 双重授权 | 相同 Agent baseline 下 Reader/Writer 两个不同 Skill Grant 保留完整父链；返回对象修改不影响后续验证 |
| 精确绑定 | 改变 platform、instance、agent、session、task 均不能借用上下文；省略父级、伪造父签名、跨任务或 baseline 漂移拒绝 |
| 活体依赖 | 16 类变化均拒绝验证与重复签发：授权撤销/重签漂移、身份失效/改绑、会话撤销、安装缺失/归属/签名/字节变化、任务结束、加载缺失、租约缩短/到期及时间倒退 |
| 父链 | 八层通过，第九层拒绝；子期限受根节点约束；精确父墓碑传播到叶节点，重复撤销不产生新墓碑 |
| 并发与容量 | 16 个并发相同请求仅一次审计/发布；4096 条容量最后一位可用，下一条拒绝；容量已满仍允许有效原文幂等读回 |
| 文件边界 | 重复键、字段大小写别名、显式 null 父级、未知字段、多 JSON 文档、超限、篡改、POSIX 非私密对象/符号链接和错误墓碑拒绝 |
| 审计及中断窗口 | 审计失败不签发/不撤销；审计之后发布冲突不覆盖既有对象、不产生可验证授权 |
| 版本与跨语言 | 新撤销文档绑定原上下文签名，Go 与 Python 独立签名向量一致，v1 schema/reader 不接受 v2 |
