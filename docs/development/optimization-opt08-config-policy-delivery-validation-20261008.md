## 2. 对实际权限链路的作用

### Provider 恢复必须可确认

恢复前核对固定 CLI、专属候选网关与空沙箱库存，在模型准入排他锁内读取私有客户端凭据、安装 Provider 并读回。凭据不得进入 CLI 参数或报告；读回不符或凭据在恢复期间变化时不报告成功。默认 Provider 清单保持原值。测试采用受控 CLI，不冒充真实在线恢复。

### 业务授权约束每次读取

broker 精确绑定请求的 run、session、sandbox、nonce、scope 和数据分类。查询前以及返回结果前重查业务授权；授权撤回、期限届满、停止或权威查询异常均拒绝返回成功数据，并通知监管者清理。身份注册表先于后端查询检查，旧令牌撤销后不能再次进入数据查询。

市场范围、对象类型和项目向量过滤由服务端核对。跨市场、跨项目和无法证明项目范围的主键读取拒绝。既有一级市场向量隔离门禁没有放宽；绕过该门禁的单元夹具只证明过滤器逻辑，不代表真实一级市场数据已开放。

授权检查不提供数据库读取回滚，也不构成最后一次检查与网络发送的分布式原子性。宿主同 UID 攻击者仍不属于该文件权限边界。

### 请求配置与可写路径保持一致

原生模式显式启用受保护 Skill 加载，并要求批准 Qwen 路由、全新运行状态和独立快照合同；不复制宿主身份或历史会话，不隐式升级旧快照。配置摘要仍为 `unverified`，不能作为真实 Authority 就绪证明。

企业挂载只读映射当前公司和明确公共元数据；唯一业务可写目录限定为 `analysis/runs/<run>`。跨公司、错误 scope、运行标识漂移、穿越／符号链接和危险重叠拒绝。挂载编译不替代业务授权，也不宣称文件计划本身证明内核已应用策略。

### 原生策略保留数据与网络约束

confidential 原生候选只保留固定数据 broker 18794 和认证模型桥 8005，去掉旧插件 relay；文件系统、Landlock 和模型合同继续检查。企业 scope、模型清单摘要、请求标识和精确写路径必须同时匹配。公共研究保留已有出网语义，机密分类拒绝公开读取、未知 JSON 外发及获准列表中的外部模型／搜索服务。

这部分是策略编译与受控 HTTP／DNS 验证，尚不能替代最终同候选运行中的网络效果测评。
