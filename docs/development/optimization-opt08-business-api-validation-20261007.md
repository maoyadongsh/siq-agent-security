## 3. 本批发现与修复

### 3.1 祖先目录身份校验不应要求目录读取权限

真实 OpenShell 策略下，`open("/", O_RDONLY|O_DIRECTORY)` 返回 EACCES，而 `O_PATH|O_DIRECTORY` 成功。原生启动器和 Skill 读取器只需持有祖先目录身份，却额外要求根目录可列举，导致启动失败及 Skill 加载失败。

两处目录句柄改为 Linux `O_PATH`，保留 `O_NOFOLLOW`、`O_CLOEXEC`、真实 inode／设备核对、目录归属／模式及替换检查。Skill 正文仍通过独立 `O_RDONLY` 文件句柄读取，文件权限拒绝仍会关闭读取器。没有向 OpenShell 策略添加 `/` 读取权限，也没有放宽路径来源或符号链接规则。

新增负向验证包括：不授予祖先列举权限时仍可建立可信目录链；目录句柄不能用于列目录；目标文件禁止读取时仍拒绝，且不产生来源观察成功事件。

### 3.2 原生宿主就绪与 HTTP 就绪分阶段确认

原生宿主接管成功后，Hermes 尚需加载并启动 HTTP 服务。旧端点逻辑立即发起一次健康请求，使正确启动被误判为失败。

原生路径增加 30 秒有界就绪等待，只重试连接未就绪。每次尝试重新核对业务授权、原租约和真实转发进程；错误身份、响应内容、鉴权结果不会通过重试被接受。等待中撤权立即终止后续请求，随后按原请求身份清理。旧插件路径保留原行为。

### 3.3 安全诊断与部署一致性

网关失败保留固定阶段、允许列表错误码、操作系统 errno 和输出摘要；不记录原始异常、响应正文或密钥。诊断写入失败不得阻止 containment。启动脚本的子入口阶段也仅输出固定标签。

实际 API 环境此前安装的自有包缺少本轮业务模块。已先备份原分发文件，再以离线、`--no-deps`、copy 模式安装与源码核对一致的两项自有 wheel；第三方依赖未更新。为满足已有私有路径合同，移除业务 `var/` 和 `var/openshell/qwen38/` 的组写权限，分别由 0770→0750、0775→0755；未递归修改数据目录。备份和私有部署材料留在本机受保护状态目录。

## 4. 失败记录与测评器勘误

- v801–v807：真实启动失败，逐步定位到容器内启动器的根目录读取权限问题；v802 起补全失败阶段记录。v801 因早期测评清理器只认识完整端点，临时数据库被保留；后续按原执行记录核对失败终态、origin、Supervisor 和容器缺席后已清理。
- v808：原生启动和 SIQ 宿主接管通过，HTTP 就绪确认未通过。
- v809：HTTP 和模型调用通过，但 Skill 来源读取遇到同类祖先目录问题，任务答案不合格。
- v810：Skill 加载与真实文件读取均获得正确签名回执；业务侧财务证据检查阻断最终答案。没有关闭该检查，也未将本次记录改成成功。
- v811：显式说明为 Hermes 权限联验的公司元数据只读任务，答案和实际文件匹配。此用例不是财务报告生成质量验收。
- v812、v813：原测评器将 `params_excerpt` 当作纯路径，随后又使用了错误的非 ASCII 转义资源编码，造成结果误报。依据签名 `resource_refs` 和既有规范化合同独立重算，确认实际拒绝／允许与文件效果一致。原运行 JSON 与失败复核记录保留；未为修正测评器重复调用模型。

不能将“业务执行状态 succeeded”“HTTP 200”或“模型声称已完成”单独作为权限功能通过依据。本批最终结果同时要求签名决定、对应 Skill、精确资源和独立文件效果成立。
