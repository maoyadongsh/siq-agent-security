# 运行详情中的已采集输出（E153）

日期：2026-09-23。承接 E152 / UX-11，总目标保持 active。

## 用户现在可以做什么

运行详情新增“本次运行的已采集输出”，放在审计折叠区之前。按时间倒序显示记录时间、大小和保留期；点击某条输出、明确确认后才读取正文。正文以纯文本显示，关闭可清除并回到原按钮；刷新页面只读取目录，不自动读取正文。超过 20 条时分批展开。

未开启内容保存、已开启但没有记录、无法确认来源、记录删除/到期、连接失败和快照变化分别解释。读取失败可重新确认后重试，不执行任务；活动快照变化需刷新详情再选。旧任务级记录不冒充本次运行输出。

界面明确区分“已采集工具输出”和“正式报告/业务文件”，不把有输出等同于任务成功，也没有增加报告下载能力。原文保存仍默认关闭，仓级启用与任务授权分别检查；本批不会为用户自动开启保存。

## 实现与安全边界

新增 `local-task-outputs/v1`、`local-task-output-read/v1`、`local-task-output-content/v1` 合同：

- GET `/v1/task-activities/{id}/outputs?view=tasks&snapshot=...` 只返回认证后的元数据，最多 4096 条。
- POST 同一路径的 `/read` 必须携带准确记录 ID、预期正文摘要和 `confirm_display=true`。GET 不读取正文。
- 两个入口均受现有本地管理员会话认证保护，前端不能指定 task、runtime identity、session、binding 或文件路径来替换来源。

服务端先验证活动回执快照，再核对历史签名 binding、intent 和唯一匹配 runtime identity，最后使用 E152 的精确来源查询。读取前后复查活动快照，正文摘要不匹配拒绝，所有响应 no-store。客户端再次严格校验活动、快照、任务引用、记录字段及内容总量，错配不显示。

新增历史绑定查询只用于历史输出管理，不恢复执行授权。身份后来撤销不会凭空删除保留期内的既有内容，本地管理员仍可明确读取；运行时继续被拒绝。旧 task-only v1、同任务不同身份/会话/绑定以及 input 内容不进入本次运行输出列表。
