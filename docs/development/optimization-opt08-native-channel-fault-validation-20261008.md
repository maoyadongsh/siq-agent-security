# OPT-08/10：原生元数据通道失联与新任务恢复验证

日期：2026-10-08。环境：DGX Spark＋智能分析助手＋Hermes 原生 Skill＋OpenShell＋SIQ Agent Security。

本批完成一次真实失联及恢复对照：**合法读取完成后，本任务的原生元数据 socket 暂时不可达，后续真实写入报错且文件不存在；恢复原 socket 并完成清理后，新合法任务可以正常加载 Skill、读取及写入。**

该结果证明本次受管调用在元数据通道失联时默认拒绝，不证明任意网络故障、任意未接入工具或所有宿主进程均被隔离。

## 1. 预登记与候选

v861 失联用例与 v862 新任务正向用例均在运行前登记驱动摘要与预期。候选仍为业务 `8851724` 和安全 Git 导出 `32e10d54`，沿用同一原生镜像、隔离 Authority 和已安装 writer Skill。每例冻结 1,874 个业务输入、分别登记 289 个与 HEAD 不同的输入，候选摘要为 `5bbf4e90636c45ed58d801de1481d5bb10a216ecb68390e587bea18efc791521`。

没有修改生产授权逻辑、模型、工具实现或镜像；故障注入发生于本次拥有的临时任务运行态。配置、原始日志和私有凭据留在本机。

## 2. 如何注入可归因的故障

v861 经真实业务 HTTP 和 SSE，要求模型加载 `siq-research-draft`，读取获批公司元数据，再通过 `write_file` 生成合成标记文件。

现场控制器在收到真实读取完成事件后，先验证同请求读取 allow 回执及 writer SEC，读取 Agent／Skill 完整授权快照和未撤销的 SEC。随后从本批直接创建的 host service 进程中定位唯一任务目录的打开描述符，核验目录、socket 类型、所有者和权限，并与请求的不可变 native record 对应。

故障只将该目录中的 `native-host.sock` 临时重命名。其他请求、控制 socket、裁决 HTTP 服务、模型服务和授权内容保持不变。控制器观察到写入工具完成事件后，立即恢复原名称，并核验仍为相同设备号／inode／权限；异常退出路径同样执行恢复。没有创建替代 socket 或伪造成功响应。

实际故障窗口约 **5.396 秒**。这是现场控制器注入与恢复之间的间隔，不是防护生效 SLA。写入开始／完成事件均位于此窗口内。

失联请求的业务 failed 与故障验证通过含义不同。本例预先要求“真实写入被拒绝、没有副作用、故障可恢复、业务终止与资源回收明确”；它不要求失联期间仍正常完成用户任务，也不计作正常任务效用成功。

现场比较确认：v861 前后完整 Agent／Skill Grant 及状态 revision 不变，SEC 内容相同且没有撤销；结果文件生成时间仍早于该 SEC 到期时间。此时间核对来自受控宿主现场记录，不是签名内核时间证明。

两例 OpenShell 策略与启动资产摘要匹配，任务输出目录均可写。仅规范化请求 run/nonce 后策略相同，输出目录设备号与 inode 对应启动记录。因此，拒写没有借助不可写目录、撤销授权或安装漂移制造。

## 4. 恢复边界

v861 使用的元数据客户端遇不确定交换后保持失败，未自动重放原事件；原 socket 恢复不代表应继续使用这个已失败的客户端。该请求明确失败并释放资源。

v862 是新的业务请求，重新建立可信任务通道并取得新 SEC。按各例统一隔离规则，临时 Authority 服务进程在例间正常停止／启动，持久授权状态和签名身份保持；本批不声称同一服务进程无重启接管了原不确定会话。

正常新任务的实际写入和返回标记均已核对。证明的是故障清理后的新请求可用性，不是旧请求自动续跑或跨进程透明恢复。
