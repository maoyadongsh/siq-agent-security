# 企业候选处理与权限入口验收（E144）

日期：2026-09-23。接续 E143 的环境接入旅程，落实发现→业务角色→确认资产；补齐 ENT-UX-02 的部分操作权限表达、UX-06 的写入结果核对及 UX-08 的小屏展示。总体目标 active，SEC-F01–SEC-F10 保持用户指定的后续顺序。

## 用户可见变化

资产列表采用中文状态，明确区分“待确认”“需人工核查”“已确认”“已纳管”。确认资产不会批准工具权限、部署策略或开启拦截。条数标为“已加载”，保留后端分页覆盖提示及加载更多入口。发现入口进入上一批已经打通的环境接入流程，不再从资产页一次下发宽泛的智能扫描。

候选确认弹窗先说明对象、框架和已有用途，允许填写“研究分析”等中文业务用途；不要求用户输入负责人内部 ID，已有负责人保持不变。驳回会说明只移出候选，不卸载或停止智能体。业务用途是资产描述，不等同组织权限角色。取消不写入，提交期间阻止重复提交与关闭。

提交前重新核对同一资产的状态和更新时间；提交后通过 GET 读回同一 ID 的目标状态，确认时也核对提交的非空用途。写入或读回响应不明时，输入保留、错误显示在弹窗内，改为“核对处理结果”，不自动重发。核对反映当前事实，不声称其他操作者的动作由本次请求完成。它不构成跨进程 exactly-once 或全局幂等保证。

页面视图保存在 URL，进入详情再返回仍停在候选或资产清单。E143 接入结果直接打开候选视图。详情证据请求失败显示错误与重试，不再当成“暂无证据”；切换详情时撤下旧资产信息。小屏使用完整卡片保留名称、用途、框架、状态、来源、时间和操作，避免表格挤成逐字断行。

## 权限与相邻缺陷

新增只读 `GET /api/v1/inventory/access`，合同为 `inventory-access/v1`。验证身份的 agent:confirm、env:read、policy:manage 分别决定候选处理、环境发现入口及详情策略创建入口。无权限时给出联系组织管理员的说明；权限未读到或读取失败不提供写入口。前端投影不代替后端权限检查，也不提供角色分配。

候选确认/驳回统一先租户内定位、再权限检查，跨租户对象返回 404，本租户越权返回 403。实际检查发现，旧驳回路由允许过时页面驳回已确认、信息过时或已经驳回的对象；现仅允许 candidate/needs_review，其他状态返回 409，拒绝路径不追加处理审计。未新增数据库锁或声称解决并发状态竞争。

本轮保留已有策略编辑/审批实现，仅按真实权限控制入口。策略编辑的完整业务表达、审批与部署读回、组织登录上下文、角色首页及负责人目录选择仍为后续任务，不能据此宣称整个企业工作台完成。

## 验证中的修正

参数化 API 测试最初复用了环境名，因测试库跨用例共享而触发真实唯一约束；改为每个参数有独立名称，再完整运行 985 项通过。一次修正命令工作目录错误，未修改文件；随后修正路径并重新验证。失败日志保留。

首轮小屏截图显示表格逐字断行，改为响应式卡片。测试随后因同一文字同时存在于桌面与隐藏卡片中发生严格定位冲突，现只断言当前可见内容，并单独验证小屏卡片。最终两框架使用相同脚本和构建通过。原有构建大包提示与 Starlette/httpx 弃用提示保留，没有以升级依赖掩盖。

## 复验与回滚

从仓库根执行，输出目录必须不存在：

```bash
python3 scripts/enterprise-experience/candidate-review-browser-smoke.py \
  --framework hermes \
  --edge var/flagship/ux-e143/edge-agent-final \
  --connector-dir var/flagship/ux-e143 \
  --web var/flagship/ux-e144/dev-web \
  --out-dir var/flagship/ux-e144/recheck-hermes
# OpenClaw 使用 --framework openclaw，并指定新的输出目录。
```

隔离 UI 显式使用 VITE_DEV_MODE，只用于验收；生产使用正常企业构建与生产身份配置。回滚只逆转 E144 页面、权限投影与候选处理增量并重建资源，不恢复整个脏工作树，不删除既有资产、审计、设备身份或授权。未提交、推送、发布或更新安装版。
