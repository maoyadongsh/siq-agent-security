## 2. 权限与生命周期保证

| 环节 | 本批已验证行为 |
| --- | --- |
| 业务授权 | 每轮先验证实时业务授权及API执行租约，再处理原生续期 |
| 原生启动 | 固定请求、范围、执行绑定、镜像、进程与安装来源；未知启动结果不重复start |
| 准备／运行 | `awaiting_native`仅用于网关准备，不能作为业务运行就绪 |
| 续期 | 使用同一宿主句柄，授权窗口受业务期限、数据租约与固定整体期限限制 |
| 退出与撤权 | SIGTERM、授权撤销后执行收口；真实fork及文件锁验证在途监管不能被另一个恢复者接管 |
| 恢复 | SIGKILL后的持久绑定只用于停止与清理，不恢复业务执行或重新签发授权 |
| 清理失败 | 继续其他资源切断；未确认原生停止或完整收口时保留失败状态 |
| systemd归属 | 检查固定模板、有效命令、私有环境、Invocation、进程状态与就绪记录；旧状态文件不能单独证明恢复成功 |

安装工具只部署明确选择的模板，不自动enable或启动。已有不同配置会被保留并拒绝覆盖。原生请求使用独立协议和受管转发；兼容relay没有因此成为原生路径的必要裁决通道。
