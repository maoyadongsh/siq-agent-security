# 企业变更审查与审批读回验收（E146）

日期：2026-09-23。承接 E145，推进 ENT-UX-04。总体目标保持 active；本批完成审批审查增量，不将完整审批/部署工作台或外部安全检查清单标为完成。

## 已实现

变更清单的直接“批准/驳回”改为“查看并审查”。窗口展示策略名称、版本、保护模式、审批类型、提出账号、处理账号，以及全部编译输入权限域、申请人填写的用途/影响、校验提示和前版本模式。目标使用策略原有技术标识，不未经授权扩展资产目录读取，不把前版本当作运行时事实。

已填写的内容与未填写项目分开展示；未填写项目合并在一个可展开区域，具体默认行为仍需执行后端核验。用途与简单对象列表按人类可读文本显示；复杂策略保留完整有界文本，不丢弃未知配置字段，也不声称已经提供语义化差异或风险建议。

处理方式需明确选择，再确认本次审查。取消不写入。本人不能批准自己的提案；只读账号可看内容和缺权说明，不显示可执行审批控件，也不额外请求环境目录。提出者驳回自己提案保留旧接口语义，不擅自改为另一套职责分离规则。

提交后使用独立 GET 核对同一变更、预期状态及处理账号。响应丢失或读回失败进入“核对处理结果”，不直接重放 POST；核对仍待处理时清除原确认，要求重新审查。其他账号先处理时展示真实处理账号，不将他人结果归为本次操作成功。URL 保留所选变更，刷新后重新读取；失败撤下动作，可重试。移动端清单提供完整卡片与实际审查入口。

部署保留已有接口，增加权限约束下的目标控件、同页提交串行保护和部署列表刷新；仅列出已读取的执行环境及有效绑定。全局部署列表未包含某单时明确说明覆盖范围，不当作“尚未部署”。**部署预览、写入不确定状态、精确逐单执行结果与审批审计直达仍需下一批完善。**

## 后端合同与安全边界

新增 `change-review/v1` 与 `change-review-decision/v1`。GET/POST 均先按已验证租户定位对象，再检查权限；POST 同时要求 policy:read 与 change:approve。严格请求字段，客户端也校验版本、对象、完整章节及权限自洽性。GET 返回 no-store。

审查摘要绑定当前身份、变更状态、申请参数、完整策略和前版本降级判断依据。POST 重新生成摘要；不一致返回 409，拒绝依据旧页面提交。审批仍复用既有 SoD、降级、紧急审批及事后复核语义，审计与状态同事务；审计仅新增 review_digest，不记录策略内容。旧 approve/reject 端点保持兼容，并修正为对象定位后再检查权限；旧端点没有新快照保护。

章节最多 6000 字符、最多 16 项、递归深度最多 16，并限制清理遍历节点。已知敏感字段及当前规则包模式脱敏；脱敏、过长、过深导致审查不完整时，此入口禁止批准但允许驳回。资源配置的 max_tokens/token_budget 不按密钥误隐藏。未知凭据格式识别、上传入口秘密治理与 SEC-F01 仍是独立范围，本批不能视作完整秘密检测。

新写路径在 PostgreSQL 对变更及所关联策略行加锁；本次测试使用隔离 SQLite，**没有验证 PostgreSQL 并发调度**。摘要不持久化为部署门禁，没有新增策略内容编辑接口；不能据此声称封闭直接改库、旧客户端并发及审批后参数变化的所有窗口。
