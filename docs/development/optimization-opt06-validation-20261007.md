# OPT-06 pending 来源事件幂等与重启恢复

日期：2026-10-07；分支 `codex/security-optimization-20261007`。

## 实现

pending 日志的物理行号和完整前缀形成域分离的 SHA-256 来源身份。来源身份只由本地提升器生成，不从未签名 JSON 接收；新回执 ID 包含完整 64 位来源摘要。相同内容的两行仍是两个独立事件；同一行在游标丢失后再次提升时，在验签链中找回既有记录并推进游标，不追加第二份。

Engine 锁覆盖查找与追加。旧 v1/v2 的字段、签名、哈希算法和观察语义不变，新增 ID 仍符合既有 receipt_id 字符串合同。直接没有来源身份的旧接口保留旧行为；已冻结样例没有改写。旧短 ID 不能证明来源对应，遇到同内容旧式记录时明确报告历史来源不明，保留原记录和合法签名供复核。

测试还发现并修复：重启恢复曾把 v2 `local_failure` 当作在线会话记录，缺 session ID 时启动失败。恢复现在跳过此类本地失败记录的在线会话/授权状态重建，仍验签并保留其观察事实。

## 边界

本轮证明进程故障和游标恢复，不声称任意断电条件下跨文件事务。pending 源继续遵循只追加要求，不自动修复日志改写、轮换或人工复制产生的来源歧义。幂等查找当前遍历已验签链，没有引入不可恢复的去重缓存；大型历史的性能仍纳入 OPT-15。已处理行数可包含恢复时找到的既有回执，不等于新增数量。
