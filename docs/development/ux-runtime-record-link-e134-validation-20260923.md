# 自检结果直达运行记录：实现与验收

日期：2026-09-23。接续 [E133 原生接入](ux-hermes-native-journey-e133-validation-20260923.md)。本批补齐真实操作链路，整体目标保持 active。

## 用户得到什么

Hermes 自检产生回执后，可点击“查看本次运行记录”直接进入对应详情。无需复制任务 ID 或翻查回执。详情刷新、返回列表、再次刷新都会保留实际的平台、智能体、会话和任务筛选；查询失败留在原窗口显示可重试提示。历史自检因配置变化失效后，仍可查阅当时记录，但不会恢复通过状态。

## 关联依据与安全边界

新增管理会话限定的 `GET /v1/runtime-checks/{check_id}/activity`，独立合同为 [local-runtime-check-activity/v1](../../packages/contracts/local-runtime-check-activity.v1.schema.json)，原自检结果合同不变。

后端先读取已签名自检结果，再从既有有界完整快照中验签并投影运行记录。全部自检回执必须唯一存在，且属于同一个包含链、平台、智能体、会话、任务、意图和意图摘要的完整绑定。未归属、缺失、重复、跨绑定及完整性失败均拒绝返回引用。返回实际活动 ID 与快照；不从检查 ID 拼接任务 ID。

此前 `/v1/receipts` 最多返回前 500 条，不能作为完整关联依据。新查询不依赖这份分页结果，也不取消完整快照原有预算。超过预算仍报不可用，不能用局部数据生成成功链接。

接口无写入授权能力；查询已通过的检查时，沿用既有配置漂移复验与失效记账。前端核对响应合同、检查/实例 ID、平台、可信绑定及回执数量，查询期间防止重复点击，离开组件时取消请求。业务结果仍需要独立证据，自检通过不提升业务结果状态。

## 实际验证

- **真实浏览器**：从页面安装 Hermes 连接组件、原生 CLI 自检开始，调用新接口进入真实详情，独立 API 核对详情回执与该检查的全部回执一致；刷新详情、返回精确列表、再次刷新通过。
- **失败恢复**：临时移走仅属于隔离测试目录的回执文件，真实接口返回 500，页面留在自检弹窗并提示失败；恢复原文件后原位重试成功。无 HTTP mock，无改写真实用户记录。
- **历史状态**：配置漂移使自检失效；历史引用仍指向原活动，读取后状态仍为 invalidated，不能重新开始或恢复旧权限。
- **关联负向**：Go 测试用真实签名回执覆盖第 501 条之后的匹配；缺少部分回执、重复 ID、不同任务/智能体/会话/意图/摘要、其他平台、未归属及完整性失败拒绝。管理鉴权、只读方法、额外参数拒绝且不创建授权。
- **跨实现合同**：Go 输出样例经 Python JSON Schema 验证；前端使用同一 Go 样例验证精确实例及完整响应，拒绝错误平台、不可信绑定和不完整回执计数。
