日期：2026-10-07。状态：本批组件实现与真实联验完成；认证跨进程业务接线未完成，OPT-08 保持 implementing，总体仍为 9/16。

## 功能与信任边界

按 [native-host-session/v1](../../packages/contracts/native-host-session.v1.md)，`HostSession` 将正式 OpenShellBackend、RuntimeGuard、Verifier 登记、私有通道、DecisionRelay 与 HostLoop 组成一次性宿主会话，避免业务接入者重写启动/清理顺序。它是 SIQ 宿主服务内部接口，尚非对业务仓库开放的认证控制服务。

`BusinessGuard` 在真实 guard 外绑定业务监管者 pidfd、固定整体期限和最多 90 秒的授权心跳窗口。核验前后均检查监管者存活与期限；停止、退出、过期或错误控制后不能续期复活。心跳不会刷新整体期限，也不会批准业务权限。日常 Supervisor 必须先完成原有业务授权和执行租约复查，再报告心跳；本批不宣称尚未被复查发现的业务撤权已即时生效。

会话失败只回收自己取得的资源，不关闭共享 Verifier。停止后先确认工作线程退出，再退出目录上下文、关闭真实 guard 和监管者 pidfd。线程退出未确认时保留其在用资源，允许后续清理再次确认；不会为宣称清理完成而释放仍在使用的资源。Verifier 中旧登记保持失效，不复用历史调用。

资源审查发现：若 Thread.start 创建线程失败，原 HostLoop.close 会对尚未启动的线程调用 join，导致所属启动器无法完成清理。本批仅在确认线程取得 ident 后等待退出，失败仍不可重启；新增负向检查覆盖这一故障路径。原多线程 fork 拒绝测试的 Python 警告保持可见。

真实运行目录为 `var/optimization-20261007/opt08-native-host-session-01`，Go 联验通过，用时 76.602 秒。主运行使用 HostSession 自行完成核验、登记、通道和循环，测试脚本只构造固定候选输入、注入受控撤权及合成业务心跳。沙箱、网络清理成功，原网关配置和 TLS 摘要不变。

真实宿主已在增量线程故障修复前加载 `host_online.py`；该模块的 live 摘要与最终源码摘要在[证据](evidence/optimization-20261007/native-host-session.json)分别记录。新增失败路径由最终 91 项定向验证覆盖，不把不同源码批次说成一次完整同候选验收。HostSession 与主联验脚本在该次运行中未变化。
