# 接入内检查、双平台权限与运行结果验收

日期：2026-09-23。状态：候选实现与本批验收完成，整体目标继续执行。关联 [易用性任务书](user-experience-onboarding-taskbook-20260923.md)，接续 [E131](ux-onboarding-e131-validation-20260923.md)。已安装客户端、用户平台配置及常驻服务未变。

## 用户可见改进

1. 首次接入缺少检查结果时，直接在接入弹窗选择已发现的 Skill，点击“检查并继续”，返回当前步骤继续编辑权限。已有结果时可展开“检查其他 Skill”。无需先退出弹窗，再去资产页查目录。
2. 检查失败保留所选 Skill；目录恢复后可原位重试。隔离结论明确拒绝用于权限参考。检查只写检查记录，不自动创建、批准、部署授权或签发身份。
3. 权限编辑中的主体 ID、检查 ID 与路径协议折叠到技术详情；目录、工具及限制保持可审阅。此批没有合并或跳过批准。
4. 导航统一为“运行记录”“运行详情”，对应实例入口保留真实主体筛选。详情将实际结果状态和原因前置，长任务/会话标识、工具调用、来源、导出和原始记录按需展开。
5. 内部 CI/部署门禁不占默认业务结果区域，保留在技术详情且仍标明未核验。历史完整性失败仍直接提示。没有独立结果证据的运行显示“效果仍未知”，不把一次允许或正常返回显示为任务完成。

## 实测发现和修正

- 旧 OpenClaw 原生证明器只识别旧版 `.js` 文件名及独立 Pi 包，本机 2026.9.5 已采用新的 `.mjs` 入口和打包文件工具。按实际导出补充兼容入口，仍要求函数唯一、真实导出存在，并记录实际载入文件摘要；不替换或 mock 工具实现。
- 初次复验使用了旧测试中的非 UUID 会话代际，适配器正确拒绝。证明器改为明确提供合成宿主 UUID；产品的代际校验没有放宽。
- 目录消失测试初稿没有展开资产清单中的 `~/…`，在隔离路径断言处失败。修正为按夹具 HOME 解析，继续保留目录隔离断言及真实 HTTP 失败/恢复检查。
- `browser-baseline`、`v1`、`v2`、`v4` 的失败与 `v3`、`v5` 的阶段结果均保留并纳入摘要索引。最终同候选 `v6` 才作为本批验收依据。
