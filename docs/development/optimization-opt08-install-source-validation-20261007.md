# OPT-08 D2e：真实安装来源解析与原生读取兼容

日期：2026-10-07。范围：用实际签名安装、运行授权及真实文件替换 D2d 来源解析夹具。本批不启用新身份创建或在线产品入口，OPT-08 仍为 implementing。

## 已解决的问题

来源事件本身只有摘要，不能靠工具声明的 Skill 名称或 Grant 确定权限。新增 [安装来源解析合同](../../packages/contracts/native-install-source.v1.md)、[安装文件读取](../../apps/agentshield/internal/skillinstall/native_source.go)与 [来源解析器](../../apps/agentshield/internal/skillcontext/native_install.go)，从可信启动器固定的映射唯一定位实例与已批准安装。

读取前后均重新验证签名 Claim、批准的运行 Grant、运行绑定、完整导入和安装内容、文件归属及移除状态。主文件固定为清单中的 `SKILL.md`，支持文件由清单路径的摘要匹配，不能提交任意宿主路径。输出仅含安装引用、长度和原始/文本摘要；内部宿主根不进入 JSON，正文不返回给解析 API。

实际安装联验发现了此前未覆盖的兼容问题：Hermes 安装器通过目标文件与私密事务文件的硬链接对验证归属，而默认原生读取器拒绝多链接文件。因此，文件快照与单链接夹具通过并不代表真实安装能读取。现已增加可信 bootstrap 显式启用的受管链接对模式：

- 默认模式继续只接受单链接，旧行为不放宽。
- 受管模式可接受恰好两条链接，来源观察必须验证真实签名安装与私密归属文件，并核对只读挂载后才返回文字。
- 第三条链接以及回调过程中增加链接均拒绝；观察失败使 reader 失效。
- `managed_installations` 只能由受保护启动配置提供，Skill 内容和工具参数不能开启它。

## 真实文件与跨语言联验

测试资产经过真实 `Import → PermissionAdmission → Grant 批准 → Stage → Apply → Activate` 流程创建。没有复制文件绕过安装归属，也没有将目录中任意文件当作已安装 Skill。所有资产均在本次临时目录，未改动真实业务数据。

实际 Python `SkillSourceReader` 读取这些带归属链接的安装文件，生成来源元数据，交给 Go 解析器校验。同步联验通过测试专用 stdin/stdout 通道完成：Python 观察回调等待 Go 对真实安装校验，成功后才能返回正文；挂载校验回调拒绝时 Python 不返回正文。该测试通道不冒充已经接入产品的 D2b 认证通道。

主文件和支持文件均通过联验。BOM、中文和 CRLF/CR 的文本摘要与 Python 一致；另外用 CPython 生成的 22 个固定解码向量核对非法 UTF-8 起始字节、合法但截断的前缀、超长编码、代理区及 Unicode 边界。不能使用会合并连续非法字节的 Go 字符串替换函数代替 CPython 的错误处理。

负向覆盖实例不匹配、未知文件摘要、非规范运行根、源与目标内容变化、撤权、缺失运行绑定、归属文件损坏、符号链接、已取消请求、错误文本摘要、缺失/拒绝挂载验证器和重叠映射。只改支持文件也会令随后主文件验证失败，防止“主文件匹配”掩盖安装包漂移。
