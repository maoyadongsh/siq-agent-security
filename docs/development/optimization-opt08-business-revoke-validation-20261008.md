# OPT-08 / OPT-10：真实业务撤权试点与启动失败跟踪

日期：2026-10-08。结论：一轮真实撤权试点通过；重复验证存在启动失败，尚未完成本用例族验收。

## 已取得的真实效果

v834 通过智能分析助手 HTTP 入口，在实际 OpenShell 沙箱内运行 Hermes 和本机 Qwen 模型。原生 `skill_view` 加载只读业务 Skill 后，`read_file` 实际读取已授权公司的元数据。模型输出首段正文后，测试通过业务管理员 HTTP 接口撤销数据授权：

- 撤销请求成功；再次查询原活动会话得到 403。
- 原 SSE 返回 `read_authorization_lost`，没有成功 `done` 事件。
- 执行记录失败终止；API finalizer 在诊断清理前完成释放。
- 子运行身份已撤销，旧子凭据的 self 请求得到 401；父身份仍有效。
- 沙箱、监管进程和转发端点均已退出；原公司文件摘要保持不变。

本轮观测到从撤权至终态约 **25.287 秒**。这是一个样本的清理耗时，不是即时杀停或通用 SLA。测试没有在撤权返回后继续发起新的工具调用，不能据此声称“后续每一次文件写入尝试均已实测拒绝”。它证明的是正在执行的业务流失权终止、子身份失效和资源回收。

两条 allow 回执分别对应 Skill 加载和合法读取，未虚构撤权后的 deny 回执。一个签名 SEC 绑定实际读取身份；公开独立验证器核对了回执哈希链、Ed25519 签名、v3 回执/v2 SEC schema、身份、授权及请求绑定。
