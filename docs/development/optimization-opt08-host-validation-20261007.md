# OPT-08 D2d：宿主事实与签名权限桥接

日期：2026-10-07。本批完成宿主应用层与真实 Go SEC/调用 Store、receipt.Engine 的组件接线。OPT-08 仍为 implementing；尚未将 Python 原生门禁通过认证通道接到产品 daemon，也未进行本批日常业务验收。

## 已完成

[宿主桥接合同](../../packages/contracts/native-host-bridge.v1.md)与 [NativeHostBridge](../../apps/agentshield/internal/skillcontext/native_host.go) 定义了完整应用顺序：Begin → Load → Prepare → Bind → 裁决 → Finish → End。

- Begin 必须经可信运行验证器确认实际 subject/制品和租约，再登记签名会话与任务。未知任务不回退为无 Skill。
- Load 必须经来源解析器独立匹配真实安装；桥接据此推导 Skill Grant 和 SEC，不接受调用者指定 Grant。切换的父必须等于任务当前加载；缓存重新观察，切回原 Skill 也不能丢弃中间祖先。
- Prepare 只记录最终调用身份、工具和摘要；Bind 核对实际参数后签发精确调用记录。参数不进入宿主元数据状态。一次只有一个在途调用，重复 ID 和重复 Bind 均拒绝。
- 决策继续交给现有 receipt.Engine，保留 Agent、当前 Skill、全部祖先与 Intent 的交集。调用记录本身不授予执行权。
- End 不等待正在运行的验证器，立即使任务失效；允许保留一次晚到的在途结果，不把任务结束当作副作用没有发生。
- 桥接使用新增 `BindFreshCall`：持久目录已有相同调用则拒绝。重启后重新登记同一任务，也不能借底层幂等读回再次执行旧调用。既有 `BindCall` 的文档幂等语义保持。

依赖回调必须有界、线程安全且不重入桥接。签名私钥仍只在 SIQ Store，来源事实不产生权限。运行验证、来源解析、安装验证和审计没有宽松默认值。失效任务不清空、不恢复为无 Skill；重启后的内存宿主事实也不从历史签名文件自动恢复。

## 验证与证据等级

新增八组测试，包含十八个表驱动负向子用例。它们使用真实签名 Store 与真实决策引擎；运行进程验证、来源到安装的解析仍是明确的受控夹具。

| 验证 | 观察结果 |
| --- | --- |
| 从来源自动签发 SEC → 精确调用 → 引擎 | 允许目录 allow，目录外 deny；输出 v3 回执且链验签通过 |
| 两个不同 Skill Grant | 同任务切换不能借较宽 Grant；新的独立任务可正常使用自己的已批准权限 |
| 切换与缓存 | A → B → A 保留三级祖先；返回引用被调用方修改不影响内部证据 |
| 缺来源、错父链、错误参数、重复调用、未知缓存、内容变化 | 拒绝，已登记的失败任务不能继续 |
| Agent/Skill 撤权、租约失效、任务结束、已关闭调用 | 重新验证拒绝 |
| 验证器仍未返回时结束任务 | End 可完成；阻塞调用随后不得继续 |
| 重启后旧调用重新登记 | 已持久化且效果未知的调用仍不可再次绑定执行 |
