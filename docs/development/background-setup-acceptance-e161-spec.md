# E161 Linux 后台接入交付验收

按 E160 收口安排，不扩产品功能。以 E155 客户端为基线增加真实 systemd 用户服务验收腿，复用 `setup --confirm-setup --runtime`、`service-stop/start`、`teardown`，不直接启动 serve 冒充安装。

只创建本轮独有临时状态、合成 HOME 和实例单位。使用现有 linux_service_home 单元内隔离，不修改共享 manager 环境；前后比对共享环境并复验本轮实例登记。配对只经产品 CLI，码/会话仅保留内存，不读取 daemon 原始日志。完整清理确认前不得删除源二进制、状态或 unit 源文件。

验证真实后台 MainPID、ExecStart 程序摘要、状态目录身份、签名身份、配置来源与进程 HOME；重复 setup 不更换 PID/身份；原生 Hermes/OpenClaw 钩子→真实策略→结果→浏览器由此服务承载；重启须新 PID、原身份及输出保持；最终 teardown 注销、保留状态，随后同状态 setup 重入，记录仍可读。失败保留本轮私有现场并报告固定错误类别，不改已有服务。

此腿验证本机用户后台入口和当前候选，不等同于官方发行签名、client-install 发行信任、不同版本升级、模型驱动完整会话或其他 OS 原生验收。正式发布要求保持，不更换内置信任根，也不读取发行私钥。

验收发现两处实际阻碍，纳入本批修复：Linux 服务准备先持主 Writer 建立身份、再创建自身生命周期锁；Hermes 原生卸载规范化 YAML 后再次安装，可复用同一实例已认证且已提交卸载对应的原始恢复副本；副本字节优先从卸载输入核对，旧卸载未记录副本时最多回查 64 条历史中的已提交认证安装封装。后者只适用 Hermes 原生 config.yaml，要求历史封装、实例/配置根、副本路径和逐字节摘要关系均匹配；不重写副本、不信任裸目录存在、不覆盖卸载后的其他配置修改。补篡改/未知副本拒绝与实际原生命令重装测试。
