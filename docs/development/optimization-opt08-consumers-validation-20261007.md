# OPT-08 C2c：回执展示与导出消费者兼容

日期：2026-10-07。范围：已构建本地管理台、既有脱敏导出和追踪投影。OPT-08 保持 implementing；尚未启用新的原生宿主授权入口。

## 交付内容

回执类型新增 `runtime-receipt/v3`、完整 `native_invocation` 及 `controlled_invocation`。回执页使用本次服务端验签结果和整条回执共同派生归属标签。只有验签严格为布尔 true、调用/会话/授权引用完整、上下文链有界且不重复、叶上下文和参数绑定与 Skill 归属一致时显示“调用级可信”。前端只校验展示一致性，不持有私钥、不签发权限、不替代服务端活体校验。

可信宿主明确记录无 Skill 时显示“无 Skill · Agent 基线”；矛盾的 Skill 声明不被接受。签名失败、未知版本、缺失证明、错误绑定、异常上下文等保持“未验证”。旧任务级、会话级归属继续显示，但同样要求本次服务端验签通过。修复旧页面使用 `Boolean(data.verified)` 将字符串误判为验签成功的问题。

详情明确：历史运行上下文证据不证明当前权限仍有效、业务效果或模型指令因果。通过验签的拒绝记录也可以具有可信归属，不能把可信标签理解为该操作获准。表格对长 Skill 标识换行并保留原因列宽，避免长标识挤压整行；验签横幅只描述已展示条数和服务端检查，不宣称独立完整历史证明。

## 导出边界

已有通用、活动导出继续遵守原脱敏合同，保留来源回执哈希及投影签名；本批不从原生回执新增复制调用、会话签名、Grant ID、Skill 名称和参数原文，不改变其他既有导出字段。组件回归使用产品生成的 v3 签名回执验证：新字段参与完整原始链验签；只篡改原生证明也使链校验失败。活动投影在完整来源校验失败时拒绝输出。

旧 v1 追踪来源模型表达的是单个 Intent 绑定 Grant，不能表达 Agent 基线与完整 Skill 祖先交集。新增明确保护：原生 v3 或携带原生证明的回执不再套用此旧来源解析器，其 Skill 来源标记 `unavailable`，保留原始哈希。尤其无 Skill 调用不能把 Agent 基线的准入元数据误标为实际调用 Skill。此边界没有被隐藏成已验证来源；完整权限链仍在原始 v3 回执中可查。未来若提供完整链的可分享脱敏视图，须另行版本化合同。

`controlsync` 当前同步准入候选和证据，没有回执同步入口；本批不假造原生回执已上传控制面的能力。
