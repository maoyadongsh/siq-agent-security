## 4. 具体文档要求

### A. 保持结构

保留 README 章节层级、主要框架和产品定位，只修正失真描述、必要步骤和边界。不要整篇重写、增加大型路线图或第二份安装手册。

### B. 区分证据等级

明确区分源码实现、隔离测试、特定真实环境验证、正式发布。前两项不能替代后两项。缺当前证据时收窄描述，不用历史截图推断当前在线状态。

### C. 安装与发行

根据实际代码核对命令和参数，不编造 CLI、版本、摘要或下载地址。

说明候选包与正式签名包、普通用户安装与开发者构建的区别；控制面/组织/环境/采集范围需确认；注册、首扫、心跳和持续扫描是不同阶段。

持续扫描是否已完整接入，以当前代码和最新记录为准。主线在并行开发，无法确认的功能标明待验收，不预测它已完成。签名发行材料不齐时列为前置条件，不用开发版或 unsigned candidate 替代正式包。

### D. Mac 访问远程 Linux

讲清 127.0.0.1 指向浏览器所在机器，不是远程开发主机；Mac 浏览器和 Linux 服务端是两台机器。使用批准的服务地址或现有受控访问方式。

不得建议默认监听 0.0.0.0、关闭认证、防火墙或安全检查。不要将历史 LAN IP 写成默认地址；使用明确占位符并说明替换。

区分个人管理台会话确认与智能体业务授权。配对时长等参数从实际代码核对，不自行改变。

### E. 功能和安全语义

准确说明支持的框架、角色与技能发现范围；区分目录候选关系、配置声明、安装观察和真实加载。

declared/inferred/observed/effective/unknown 不互相替代。无记录、扫描失败或离线不等于不存在或无风险。人工运行绑定不自动证明归属。共享沙箱、独立 Skill 隔离不能超过现有证据。

批量权限管理保留独立审批和效果读回。不删除既有防攻击能力描述，也不夸大实际覆盖。

在现有 runbook 中核对、补齐必要的简短排查顺序：前端打不开；环境/设备为空；注册后无心跳；心跳正常但无发现结果；采集失败或能力不匹配；策略未生效；升级与恢复前置条件。

卸载区分停止采集和撤销运行保护；不能暗示卸载会自动删除审计或放宽策略。
