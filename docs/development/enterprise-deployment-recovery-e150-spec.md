# E150 持久部署请求与结果恢复

状态：本批持久恢复、浏览器与隔离 PostgreSQL 验收完成；真实运行时与生产身份继续。承接 E148/E149，继续 ENT-UX-04；目标为网络中断/刷新后查询同一部署，不靠页面内存推测。

新增 deployment-submission/v1 请求/响应合同和持久 DeploymentSubmission。调用者提供随机请求键，服务端绑定租户、身份、变更、环境、绑定及预览摘要；同键同参数返回原请求，不重放执行，同键参数不一致拒绝。每个变更最多一个持久提交，数据库唯一约束裁决并发。需要重试失败业务时重新提出/审批变更，禁止旧请求自动释放或超时重执行。

提交先按现有预览流程完成对象定位、权限及摘要重验，在外部执行前同事务持久化请求、pending Deployment 和 deployment.reserve 审计。提交事务成功后才允许执行；请求关联的 Deployment ID 永不改变。执行结果/失败沿用既有部署事务。进程在写入后崩溃或发生未知错误时 pending 记录保留，查询说明“正在处理或结果待核对”，不猜测未执行、不自动重发。没有运行时恰好一次承诺，也不依赖超时回收。

部署准备按变更行锁序列化（生产 PostgreSQL）；旧部署入口也检查已有持久提交，避免在保留请求后绕过。开发 SQLite 的新入口由唯一约束限制重复请求；不宣称 SQLite 旧入口与新入口的全并发等价于 PostgreSQL。生产并发需单独验收。

新增 POST /deployment-submissions 和 GET /change-requests/{id}/deployment-submission。读取先租户定位再 policy:read，返回有界请求状态、准确部署 ID、请求/预览摘要、创建时间；不返回目标路径、凭据或原始异常。状态取关联 Deployment 当前记录，不把配置读回上调为行为验证。未创建时 404，不据此断言之前的网络请求绝对不会到达。

前端确认部署时先保存变更结果页 URL，再提交随机请求键；刷新后通过准确变更读取服务端请求。结果窗口同时展示持久提交状态和已有部署/审计；网络错误可只读刷新。明确的前置拒绝仍可重新预览；已有提交时引导查看原记录。提交阶段不得关闭后再次发起。旧兼容接口保留，不删除历史记录。

迁移 0017 新增表与租户+请求键、租户+变更唯一约束。新增合同先行；验收覆盖重放/参数冲突、并发只保留一个请求、预占提交先于外部执行、审计失败不执行、崩溃记录可读、跨租户/权限拒绝、旧入口拒绝已有请求、API 全量、空库迁移及真实浏览器丢响应/刷新恢复。

实现补充：预占提交后再次读取权限、绑定、策略和 live plan；期间撤权/摘要变化会记录未执行失败，不能沿用预占前的对象快照。仍不声称消除了最后一次检查与外部副作用之间的所有并发窗口。

PostgreSQL 实测发现另一请求键会等待正在执行的变更行锁；在锁前先检查不可释放的持久请求即可立即拒绝，原键直接只读返回。已验证 pre-commit 行锁竞争和 post-commit 重放两阶段。有记录时迁移 downgrade 必须拒绝删表；代码回退到旧版前禁用部署写入口并保留所有请求/审计。
