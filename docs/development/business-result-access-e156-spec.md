# E156 业务结果的独立读取边界

UX-11 的正式结果接入分为业务源授权读取、持久运行/产物归属、控制台连接与导航三段；均完成前不关闭正式报告子项。本批实现第一段，以研究 API 为生产者、安全项目版本化 JSON Schema 为跨仓合同，不跨仓 import 或查询数据库。

研究 API 新增 siq_analysis 的 `/analysis/chat/result` 元数据 GET 与 `/analysis/chat/result/read` 显式正文 POST。必须提供准确 session_id/run_id，验证已登录业务用户、当前机密数据授权及原运行归属，不创建/切换会话，不续租或启动执行。元数据只提供域分离运行/会话引用、业务运行状态、写静默事实、正文大小/摘要和可读性，不提供回复/路径/凭据或猜测报告地址。

POST 严格接收版本、原始运行/会话定位、预期完整结果快照摘要和 confirm_display=true；返回前后复核当前授权、同一 state/route、完整元数据快照，变化拒绝，不读取同会话后一次运行。只读已确认运行与子任务均终态的非空文本，最大 1 MiB UTF-8；状态不能证明报告发布。返回内容明确 `generated_reply`，publication_status 固定 `not_attested`，不存在已验证产物时不伪造报告按钮。

此段复用当前业务运行缓冲；缓冲不存在、进程重启或新运行替换时返回 404，不从历史聊天猜测归属。后续必须补持久运行/产物台账与发布核验，再接安全控制台业务连接；本批不声称完成历史结果或正式报告下载。所有响应 no-store，输入错误不回显输入，授权异常只给固定错误码；正文不进日志或事件导出。负向测试覆盖匿名/跨用户/错运行/撤权/换代/未知终态/快照变化/未经确认及超大文本。
