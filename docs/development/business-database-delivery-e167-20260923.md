# E167：实际业务库完成运行结果迁移

日期：2026-09-23。研究业务端部署所需的 022、023 已应用到在线 API 实际连接的 `siq_app`。此前只是隔离数据库和源码验证；本次完成实际数据库前置步骤，在线 API/Web 代码尚未更新。

## 现场状态与实施

通过 `siq-research-api-candidate.service` 的自有进程树定位实际 Uvicorn 及其数据库连接，仅在内存中使用连接配置，不输出凭据。官方只读迁移审计确认历史为兼容前缀，唯一缺失为：

- `022_create_business_run_results.sql`：创建按租户、用户、profile、session、run 归属的结果表。
- `023_add_business_run_result_history.sql`：增加可空保存时间和归属/时间索引。

数据库约 41 MB；发现 1 条 status=running 的历史记录，但没有未过期 running 租约。本次未修改或删除该记录，不因其租约过期就假定远端执行一定停止。

实施顺序：

1. 固定迁移 SQL、清单、前置基线及官方 runner/auditor 的私有源码快照，限定只允许上述两项尾部迁移。
2. 比较 API 连接与备份容器的 PostgreSQL cluster identity，确认备份来自同一数据库服务。
3. 创建完整 custom-format 私有备份，实际恢复到新建独立数据库，核对恢复后的历史迁移账本与原库完全一致。
4. 在恢复库执行官方迁移 runner，审计为 current，结果表与历史索引存在；只在演练通过后继续。
5. 再次核对实际库账本未变化、在线 API 身份未变化，执行同一快照中的官方带锁/checksum runner。设置锁等待 5 秒、单语句 30 秒超时。
6. 实际库在线审计为 current、001–021 的原账本记录保持不变；再次运行 runner 无新增迁移，重复审计账本一致。
7. 删除本轮恢复演练库，保留私有备份和审计材料。在线 API PID/InvocationID/重启计数摘要不变，健康接口仍为 200。

只新增结果表、保存时间列、索引和对应迁移账本记录；没有执行降级、数据去重、重建旧表或更改业务授权。迁移 SQL 与历史清单未修改，因此没有为本次运维重复跑无关单元测试；本次证据为完整恢复、实际迁移、幂等重跑和只读审计。
