# 运行列表易读展示、筛选与翻页验收

日期：2026-09-23。接续 [E134 记录直达](ux-runtime-record-link-e134-validation-20260923.md)。整体目标继续执行。

## 用户可见变化

运行列表默认展示框架、最近记录时间、调用裁决、回执数和详情入口，按最后回执序号倒序。任务、智能体、会话及回执序号在“查看标识”中展开，不猜测业务名称或角色归属。缺少完整绑定仍进入“未归属活动”。历史完整性失败保持外显。

常用筛选为关键词、平台、调用裁决和时间范围。支持最近 24 小时、最近 7 天及自定义起止时间；快捷范围应用时固定为 URL 中的时间，不在刷新时悄悄移动。精确主体/会话/任务筛选按需展开，从对象入口进入时自动展开已有条件。空结果可清空筛选恢复。

“调用裁决”是历史工具门禁事实，不是业务成功/失败。一次运行可同时出现允许与拒绝；观察记录、审批结果不重复计入调用。历史 hold 显示“需批准”，明确不表示当前仍待审批。业务完成、产物和效果仍需进入详情独立核验。

## 前后端实现

新增只读 `/v1/task-activities/query`，使用独立 [local-task-activity-query/v1](../../packages/contracts/local-task-activity-query.v1.schema.json) 合同。旧列表与 search 接口保持兼容。

查询先对完整且有界的回执快照验签，再按完整绑定、标识、时间和裁决筛选，最后排序分页。指定时间采用最后一条回执的时间，下界包含、上界不包含；未知时间不匹配时间范围。重复参数、非法时间、倒置/相等范围、不支持的裁决和缺快照的后续分页均拒绝。快照更新返回冲突，完整性错误不返回部分成功结果。

发现原详情使用 `from` 保存来源页码，与新增时间下界重名，改为 `list_offset`；历史数字型 `from` 链接继续兼容。详情刷新保留来源页码，取得新快照后再允许返回，防止返回第 2 页却缺少快照。刷新失败且无快照时，返回第一页保留筛选，不生成无效分页请求。

## 实际验证

- 浏览器从页面安装 Hermes、真实原生 CLI 自检开始；“有拒绝调用＋最近 24 小时”找到同一运行，独立读取返回摘要为 **允许 2、拒绝 1、回执 5**，证明未把两条观察回执重复计为调用。
- 详情刷新、返回、列表刷新保持时间上下界、裁决与完整主体筛选。倒置时间提示错误且不改变原结果；指定空时间段返回空结果，清空后恢复真实记录。
- 通过真实决策 API 发送 51 条无授权的合成请求，全部拒绝、无工具执行，产生未归属签名回执。浏览器第 1 页 50 条、第 2 页 1 条；进入详情、刷新详情、返回和刷新列表保持第 2 页，上一页恢复 50 条。
- Go 使用 55 个不同任务的签名记录，验证完整结果筛选先于分页、旧任务新增回执后排在前面、时区等价、时间边界、未知时间、观察/审批记录排除、未归属不猜绑定；鉴权、非法输入、过期快照和篡改负向通过。
- 共享 Go 样例用于 Python Schema 与前端响应边界检查；另复验双平台权限、停用和运行记录链路。

最终候选 v3：**原生自检及列表浏览器 31 项、双平台权限与记录浏览器 49 项、前端 37 文件/249 项、合同相关 3 项全部通过**。Go 全量测试、vet、产品源码格式检查及本地/企业构建通过；同一 Go 源码的 Linux amd64/arm64、macOS arm64、Windows amd64 交叉编译通过（当时嵌入 UI 为末次文案和平台选项更新前版本）。不把交叉编译视为各系统原生验收。

最终结果、源码/候选/合同/截图/日志摘要见 [E135 证据](../evidence/flagship-optimization-20260921/ux-activity-filters-e135.json)。早期浏览器在分页准备时误用管理凭据，服务返回 401；改用隔离测试目录中现有决策凭据后通过，没有放宽产品权限。小屏首轮在侧栏收起动画结束前测量，出现遮挡断言失败；改为等待侧栏移出视口后验证实际命中目标，最终通过。失败与阶段成功证据均保留，不累加为覆盖率。

## 范围与后续

原生 Hermes 0.21.0 采用现有项目补丁和合成 loopback 模型响应，额外分页请求只验证决策 API，不声称是原生宿主调用。测试不修改真实 profile、业务模型、冻结快照或常驻服务，已安装发行版未升级。

业务任务的成功/失败/取消状态筛选、可读业务名称、独立产物结果仍需可信业务合同与事件，不能从门禁裁决推断。统一环境发现、企业引导、安装发行验收与整体上线门禁继续按主任务书推进。
