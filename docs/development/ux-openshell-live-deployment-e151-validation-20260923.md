# 企业页面到真实 OpenShell 执行验收（E151）

日期：2026-09-23。承接 E150 / ENT-UX-04。总目标保持 active；外部检查 SEC-F01–SEC-F10 继续按用户要求放在后续清单。

## 本批完成

在 DGX Spark 上，真实浏览器点击“部署 → 预览 → 勾选确认 → 确认并部署”，通过实际控制面、持久请求和 OpenShell CLI 完成允许及撤销两次策略下发。部署前由另一个账号审批；页面从服务端独立读取对应部署和审计，刷新仍找到同一记录且不再次提交。每次浏览器只有一个提交 POST，随后同键 API 重放返回原请求，部署历史仍只有一条。

同一自有沙箱、同一 `/usr/bin/curl`、同一公开地址 `https://example.com/` 的行为对照结果：

| 阶段 | 控制面操作 | 实际观察 |
| --- | --- | --- |
| 允许 | 浏览器下发仅允许该域名 443、限定 curl 的规则 | 请求成功，HTTP 200，退出码 0 |
| 撤销 | 浏览器下发空网络允许列表，完整策略独立读回通过 | curl 明确报告 HTTP 403，退出码 22；不是 DNS、超时或 exec 启动失败 |
| 回滚 | 实际回滚 API，当前授权与完整摘要核对 | 恢复前一允许策略的准确摘要，同一请求重新获得 HTTP 200 |

探针包含开始/结束标记并核对 curl 返回码，避免把 CLI 或沙箱故障当成拒绝。代理拒绝时 curl 的 `http_code` 输出为 `000`，403 来自其明确错误输出，证据保留两者及摘要，不把 `000` 改写成服务端 403。

## 现场修复

发现并修复 Python、Go 两侧的实际兼容问题：撤销最后一条允许规则后，网关会省略空 `network_policies`，原 writer 对包含 `{}` 的文档计算预期摘要，导致权限已撤销却显示读回失败。

现在实际撤销非空规则时省略该字段，完整策略的其他内容和摘要核对不变。若当前已经为空，无论字段缺失还是显式 `{}`，均保留当前文档并返回 no-op，不额外写入。新增测试证明真实省略可读回、已空策略不重写、静态字段保留、额外策略改动仍被拒绝；没有通过忽略未知字段或放宽摘要比较掩盖漂移。

首轮全量回归发现两个旧 CLI 失败测试依赖“空到空也执行写入”，另一个明确空 map 的 no-op 用例失败。已保留 no-op 语义，并让失败测试使用确需下发的非空规则，继续核验拒绝和临时文件清理。

## 环境保护与结论边界

使用既有专用 `siq-openshell-scope-validation` 网关（HTTPS loopback 17771）及现有 ARM64 基础镜像，CLI 版本 0.0.83；镜像 ID、CLI 摘要固定在证据中。没有拉取/升级镜像。HOME、各 XDG 目录、测试数据库、签名文件与新沙箱 token 均隔离，只复用既有网关证书引用，不关闭 TLS。

仅创建随机唯一名称的自有沙箱，限制 CPU/内存，无 GPU、业务目录挂载或 Provider 凭据；只请求公开探针地址，无模型费用。finally 按准确名称清理，自有沙箱删除已核对；专用网关目录恢复为空，原网关 metadata 哈希不变。未修改业务沙箱、Hermes/OpenClaw 或模型配置，也未替换已安装应用。

API 和页面仍报告 **配置读回**。行为对照是本批特定沙箱/地址/二进制的外部验收证据，不自动升级任意部署为 `enforcement_verified`；沙箱日志未找到可关联的拒绝行，不宣称已经打通网关拒绝事件流。基础镜像沙箱不等同 Hermes 业务任务全链路或全部工具隔离验证。

执行失败/未知仍不自动重试。回退本批源码不能撤销已下发策略；实际策略需经当前授权和准确回执回滚，禁止用旧快照覆盖中间变更。E150 的 0017 持久请求与审计继续保留，降到不理解该表的旧代码前仍需关闭部署写入。本批没有迁移变更。
