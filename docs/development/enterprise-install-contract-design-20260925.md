## 1. 信任与传输

安装包信任来自既有受控发行公钥，而不是扫码页面或设备自报摘要。企业注册信任来自 IAM 验证后的操作者与一次性环境注册许可，运行权限仍由独立策略审批和执行后端决定。

现有 Edge `validateControlPlaneURL` 明确只允许 HTTPS 或回环 HTTP；当前企业浏览器 LAN 地址为 HTTP，**不能直接作为远程 Edge 注册地址**。ENT-002 的 Gateway 转发修复不消除这一传输要求。ENT-004/012/022 必须提供可信 TLS 入口，或者明确同机 Gateway 回环部署并验证访问边界；不能修改客户端为“信任私网 HTTP”，不能启用跳过证书验证来过验收。远程 TLS 的证书/域名按实际部署授权确定，源码开发不依赖现在签发生产证书。

## 2. 拟议合同对象

| 对象 | 产生方 → 消费方 | 必需事实和拒绝边界 |
| --- | --- | --- |
| 安装计划 v1 | 已认证 Control API → 安装器 / Web | 服务端派生 tenant/environment；受控控制面 origin、短期计划 ID/期限、目标 Linux 架构、发行版本/摘要、明确采集范围及用途。拒绝额外字段，不含管理员令牌、设备私钥或业务 grant |
| 发行清单 v1 | 可信发行工具 → 安装器 | 固定源码、Edge/Connector 相对路径、OS/arch、版本/摘要/签名及兼容协议；不从任意 PATH 二进制推断信任。沿用现有发行身份，不另造默认可信密钥 |
| 本地安装状态 v1 | 安装器 → Edge 生命周期 | 安装计划摘要、已确认范围摘要、可信 origin、环境、发行身份、设备身份引用、后台服务类型和阶段；只存必要引用，私密凭据仍在原有 owner-only 设备状态。公开状态接口永不投影 secret/seed |
| 实际能力声明 v2 | 已验证安装清单 + Connector describe → Edge/API | 每个采集器的 ID、版本、制品摘要、协议、已确认范围引用、验证状态；未安装、校验失败、不兼容能力不参与调度。不能只把原四种列表扩到十二种 |
| 进度投影 v2 | Control API → Web | 安装报告、注册事实、最近心跳、任务领取、上报和回执分阶段，带时间/来源/错误码；保护状态来自独立绑定/后端证据，不由这些阶段推导 |

安装计划与能力的具体 API/字段应在实现前以新 schema 固定，旧 `environment-onboarding/v1` 保持可读，新增版本并行运行。旧客户端缺少实际能力证明时标识 legacy，不偷偷升级信任级别，也不让新调度器把 legacy 的硬编码列表当成已安装证明。

## 3. 安装状态与恢复

实现增量：Linux `prepare-install` 开发入口已消费计划文件与显式确认摘要，在写入前检查当前有效期、预期 tenant/environment/origin 及本机架构，再执行固定公钥验签和私密暂存。文档读取拒绝末级符号链接、非普通文件及超限输入；输出仅 `staged_only`、plan_id、计划摘要和暂存路径，固定错误不回显参数。当前只是可调用的准备阶段，尚无简化安装引导或注册/服务恢复，不将这些开发参数作为最终用户操作流程。到期验证发生于准备开始，未来注册/激活前须再校验；本地参数不是服务器身份认证替代品。

顺序为：验证制品 → 展示并确认组织/设备/范围 → 注册（或复用一致身份）→ 安装服务 → 心跳 → 首扫 → 回执核验。各阶段独立持久化，不以服务进程启动替代已注册或采集成功。

- 重试保持同一安装计划和设备身份；范围/租户/origin 变化须重新确认，已有不匹配身份拒绝覆盖。
- 注册响应丢失不能删除本地身份后盲目重注册。需设计公钥绑定的短期响应恢复协议，或明确停在人工恢复状态；禁止将一次性许可改成长效通用凭据。

已实现保守过渡：现有 register 在发送请求前独占创建 `registration-pending.json`（edge-registration-pending/v1），保存 control_plane_url、device_identity、public_key_pem、signer_seed，不保存注册码或返回 secret。目录 0700、文件 0600；Linux 在发送前同步文件与目录。单次注册不自动重试；失败或响应不确定时保留文件，后续注册拒绝覆盖。成功仍以既有 state.json 为已注册事实，待确认文件保留为恢复材料，不自行清理；不得将它上传到企业端。该保护不构成远程响应恢复，网络失败后目前需要受控人工处理，不能推荐用户删除文件重新注册。非 Linux 只验证独占文件保护，不承诺 Linux 的目录持久化保证。
- 注册后安装服务失败只恢复服务阶段，不能重发设备身份；失败日志不包含许可与私钥。
- 设备离线不撤销既有运行保护，不清空资产；到期/吊销后不得领取任务或上传证据。
- 更新失败保留原有可验证制品与状态；回滚不能恢复已吊销凭据或扩大已收窄的权限。

## 4. 首扫和持续调度

注册环境绑定增量：`register --environment ID` 对应可选 expected_environment_id；服务器先比较注册码归属环境再消费，客户端复核返回环境。预期环境在发送前写入本机 pending，恢复必须保持一致。新安装流程必须采用此绑定；旧客户端省略字段仍兼容但不能标记为计划绑定。该值只作预期比较，不参与推导租户或授予权限。

注册恢复增量：服务端新增 [edge-registration-recovery/v1](../../packages/contracts/edge-registration-recovery.v1.md)，要求现有设备公钥验签、原环境匹配、注册后 15 分钟内且未吊销；首次仅在尚无心跳时允许。客户端预先持久化随机恢复 secret，接口仅接收其摘要，通过同事务凭据替换、每设备唯一请求摘要和审计实现相同请求幂等，不返回秘密、不重复更换凭据。已开始心跳后仅允许已记录的原请求只读重试，不能首次恢复。需迁移 0018，原生客户端与线上部署尚未接通；上一段保守阻断仍是当前 CLI 实际行为。

安装范围确认授权的是有限元数据采集，不是业务执行或纳管审批。首扫由服务端在注册/能力验证及范围匹配后生成签名任务；目标设备、环境、采集器、范围摘要和 TTL 必须绑定。API 在线复核吊销及归属；设备复核服务端签名、期限和本地同意范围，未知任务类型拒绝。

重试、断网恢复、多个常驻实例或设备争抢不能重复执行同一签名任务。现有回执恢复复用，不开第二条绕过签名的“安装扫描上传”路径。发现的框架/角色/技能输出先保持 candidate 状态。

待实现前落实：发行清单与现有 package.py 的复用点，注册恢复合同及数据库迁移，能力版本协商与 legacy 的可见限制，可信 origin 的部署配置，Linux 用户服务/系统服务的显式权限选择。不得用简单自动执行现有三条命令替代这些安装与信任条件。

## 6. 安装计划 v1 的固定语义

- 必填服务端 plan/tenant/environment 引用、控制面 origin、UTC Z 签发/到期时间、Linux 架构、user/system 服务模式、发行版本和清单 SHA-256、Connector 列表及 `discovery_only` 用途；各层拒绝额外字段，不承载注册许可或 grant。
- 期限最多 15 分钟，到期瞬间拒绝；结构解析与 `require_current` 分开，以便历史审计。消费者执行前必须显式检查当前时间，不能仅解析成功就执行。
- 采集器需要版本、制品摘要、现有协议版本和范围。相同 ID 即使摘要不同也不得重复；枚举有 12 种仅用于描述现有模块，不表示都已具备安装/调度资格。发行清单和实际 describe 验证仍是独立必需门禁。
- 本切片 scope 表达明确文件根与文件名，根只允许绝对路径或 `~/`，可含终端 `/*`；拒绝整机/用户集合/系统顶层目录、路径穿越、控制字符、嵌套通配和秘密文件名。Connector 原有路径安全/符号链接/读取限额仍须执行，合同校验不替代文件系统验证。
- Docker/process/systemd/Kubernetes 等非文件源仍需专门的类型化范围合同，不能填虚构目录来绕过。后续增加 scope 类型时同步升版/消费者测试，不削减任务书的拓扑盘点目标。
- JSON Schema 负责线格式结构；Python 额外执行 origin 解析/端口范围、重复 ID、时间差及扫描范围的语义拒绝。Go 消费者需对这些语义做对等验证并回灌实际线格式；尚未完成，不以 Python 测试替代。
- 模型中的组织字段不是可信来源：计划生成 API 必须从验证身份和归属查询派生；安装器必须匹配服务端注册返回的环境并核验清单，不能信任用户手写计划或其中自报的摘要。

## 7. 计划生成 API 与受控目录

前端选项增量：`GET /api/v1/environments/{id}/install-options` 在租户环境定位后要求 env:manage 与 edge:manage，返回控制面 origin、可用架构/发行版本、Connector 范围及当前实际支持的 user 服务模式。只读、no-store，不创建计划/注册许可/设备；release_signature_verified=false，不把受控目录当作发行验签。非法/缺失配置或仅 system 模式统一 503 install_options_unavailable；不向页面回显部署目录路径或内容错误。该接口是前端引导的数据源，页面尚未接通。

服务配置生成增量：`service-unit --binary PATH --state-dir PATH --connector-dir PATH` 仅输出用户单元，ExecStart 直接运行 Edge serve，不经 shell；拒绝相对/未规范化路径、控制字符、引号、反斜杠和 `$`/`%` 展开字符。配置 UMask=0077、NoNewPrivileges、有限重启频率、control-group 停止及 90 秒停止期限。systemd 强制停止后的未完成任务仍按原账本/回执恢复边界处理，不能据此宣称业务副作用可回滚。配置不改变个人端或业务执行后端。

用户服务不等于开机即驻留：linger、用户会话管理、安装/升级原子性及权限由后续安装器显式处理，不自动调用 sudo/loginctl。当前生成器不验签/注册/创建目录、不写入用户 unit 目录、不调用 daemon-reload/enable/start，安装器接通前不发布一键安装承诺。systemd-analyze verify 仅为离线语法验证，不计真实重启/登出验收。

生命周期增量：Linux `edge-agent serve` 使用同一已注册身份启动独立心跳与串行任务轮询，周期 30 秒、失败指数退避最高 15 分钟。任务调用原签名/账本/回执链路；Linux `tasks` 与 serve 共享内核排他锁，退出释放锁但保留锁文件 inode。设备目录必须私密，锁文件拒绝符号链接/多链接/非普通文件/非当前用户/宽松权限；非 Linux 旧 tasks 行为不变，serve 明确拒绝。不自动注册、不改权限、不安装用户或系统服务，systemd 安装与升级恢复仍待后续实现。

`POST /api/v1/environments/{environment_id}/install-plans`，Gateway 对应 `/api/agent-security/v1/environments/{environment_id}/install-plans`。请求遵循 `enterprise-install-request/v1`，仅接受 schema_version、target_arch、service_mode 和 Connector ID 列表；不接受租户、origin、摘要和 scope 覆盖。

先按验证租户定位环境（不存在或跨租户 404），再要求 `edge:manage` 与 `env:manage`（缺少 403）。环境和租户字段由后端派生；审计提交成功后返回 `enterprise-install-plan/v1` 和 `Cache-Control: no-store`。重复调用会生成不同的短期计划并分别审计，不创建注册码/设备/采集任务；不是可重放注册凭据或安装操作的幂等实现。

部署配置 `SIQ_AS_INSTALL_CATALOG_FILE` 是绝对路径，指向受部署操作者控制的普通 JSON 文件，文件所有者须为服务用户或 root、不得组/全局可写；拒绝末级符号链接、超 2 MiB、重复键和非法字段。部署者还须保证父目录/挂载不可被不受信用户替换，此版本不声称逐级目录防替换。推荐受控只读配置挂载，不允许浏览器提供文件路径。

目录字段：schema_version=`enterprise-install-catalog/v1`、control_plane_origin、allowed_service_modes、releases。每个 release 包含 target_arch、release_version、release_manifest_sha256、connectors；每个 connector 使用安装计划中的版本、制品摘要、协议与明确范围。每种架构只能出现一次；实际制品清单由受控发行流程准备，不填示例摘要冒充可安装制品。

未配置/不可读/格式异常/无效 origin 返回固定 503 `install_catalog_unavailable`；选择目录不支持的架构、服务模式、Connector 返回 409 对应错误码；请求覆盖字段或重复 Connector 返回 422。错误不回显目录正文、路径或异常详情。计划审计仅保留 ID/摘要/数量/用途，不记录采集路径或凭据。

目录是部署选项来源，**不是发行验签结果**；API 返回中的摘要不能自行证明制品可信。安装器必须独立校验既有发行公钥签名及实际制品，之后才能注册/安装。目录尚未配置到在线实例，接口不代表已发布安装包或自动接入可用。前端范围预览、用户确认、注册恢复和持续生命周期继续按 ENT-004/005 实施。
