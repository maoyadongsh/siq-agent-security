# 未持久化 Hermes 子任务的 API 崩溃恢复验收

日期：2026-09-24。对应原请求运行时合同中的“恢复时未知 child”故障点，不新增产品功能，不修改冻结客户端或企业端候选。

## 触发与验证边界

隔离候选 API 经真实业务 HTTP 登录、合成公司授权及本地 Qwen 完成主任务。诊断包装器再次核验原执行归属和 Hermes 主任务终态，将业务状态置于后处理阶段，显式调用现有 `_run_single_financial_repair`。该函数仍通过正式路由创建 Hermes 子任务；仅诊断输入换成无工具的合成文本。

观察到不同 run ID 的子任务产生真实模型 delta，并由独立状态请求确认子任务仍在 `running` 后，包装器保存私有观察并向自身 API 发送 SIGKILL。故障发生在子任务 ID 返回给修复函数之前；原执行数据库只持有主任务 ID，恢复器没有子任务 ID，也不会从诊断观察文件中补造执行权限。

本用例是**诊断显式触发已有修复函数**。当前主业务代码没有自然调用该修复函数的调用点，因此不将本结果描述为财务问题自然触发修复、模型自主委派或多层委派全部验收。

## 验收要求

**实际结果：以上故障已经触发，同库重启后 123.911 秒完成原执行自动回收，以下检查全部通过。** 原租约未手工修改，数据库没有子任务换绑或重放，模型桥关联主任务 200；临时数据库和两个隔离监听均已清理。

- 同库重启后保持原主任务、会话、owner、pool run、lease 与 scope，等待原租约自然到期，不续租、不重放、不把子任务绑定成主任务。
- API 自身 finalizer 完成整个执行环境回收后，原行才进入 `authority_lost`。独立核验沙箱、监督及转发退出，子身份撤销、旧凭据 401，而诊断父身份此时仍有效。
- 不将未完成后处理的父回复保存成持久成功结果；临时 API、身份服务、数据库全部清理，既有业务 API、模型、桥和预览身份保持一致。

实际执行数据及源码摘要见[脱敏证据](../evidence/flagship-optimization-20260921/business-unknown-child-recovery-20260924.json)，由候选清单（本机私有路径：`var/flagship/unknown-child-recovery-20260924/candidate.json`）绑定。证据复用 E165 家族的新 v5，原 v1–v4 不被覆盖；复用证明器内部 `original_provisional_execution_authority_lost` 检查名在本用例实际检查的是**原已绑定主任务行**，不表示主任务仍处于 provisional 阶段。

## 自动化验证及限制

未知子任务、创建确认和原崩溃证明器组合 **28 passed**；另运行实际修复函数“仅创建一次 run”测试 **1 passed / 118 deselected**。新增两个诊断文件 Ruff 通过。负向覆盖非候选环境、失去父 owner、父任务未结束、复用父 run ID、子任务已结束和没有模型 delta，均禁止注入终止。没有扩大已有模型或正常流程回归。

本证明不承诺某个工具在撤权瞬间即停止，也不使用初次子任务状态推断它在整个等待期始终运行；验证的是 API 失去内存子任务身份后仍完整回收原执行环境。原服务没有部署变更，生产身份、正式审批/事件出口、原生 CI、质量/性能、上线回退及签名发行仍须完成，`production_eligible=false`。
