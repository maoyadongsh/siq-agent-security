# E165：模型输出后 API 崩溃与重启回收验收

日期：2026-09-23。原任务 ML-02 的一个实际故障路径已通过：真实 Hermes/OpenShell/Qwen 请求产生模型输出后，独立 API 被 SIGKILL，同一数据库重启后的恢复器完成原运行回收。没有新增客户端功能，也没有修改已冻结客户端或企业候选。

## 实际验证结果

1. 新建合成企业、隔离 PostgreSQL 数据库和候选 API；真实 HTTP 登录、授权、非管理员越权拒绝通过。AgentShield 使用独立 47811 实例和既有固定二进制，业务 API 位于 18083。
2. SSE 返回原 run/session 和真实 `source=model` 内容，独立查询确认对应执行行仍在运行、短租约有效；随后仅对证明器创建的 API 子进程发送 SIGKILL，确认退出码和监听关闭。未调用 HTTP stop。
3. API 退出后原执行仍是 `running`。使用相同环境与数据库启动新 API；不改执行行、租约或时钟，不调用诊断 finalizer 推进结果。轮询拒绝身份替换或租约续期。
4. 重启后等待约 **113.912 秒**，原执行进入 `authority_lost`；原 120 秒租约已按实际时钟过期，API 恢复健康，正式 finalizer 持久状态为 `released`。这不是即时停止承诺。
5. 在诊断父身份撤销前，独立确认沙箱、监督进程和转发均已消失，子身份已撤销，旧子凭据返回 401，诊断父身份仍有效。模型桥首帧 200、最终 502 表示流被中断，不是完整模型回答成功。
6. 验收结束后临时 API、隔离 AgentShield、临时数据库已清理；候选网关零沙箱、owner 空闲，18083/47811 关闭。既有 API、Qwen 模型和模型桥的进程/调用身份及重启计数摘要保持一致。

## 实现与验证

只修改研究仓库中的验收工具：`scripts/openshell/prove_qwen38_candidate_api.py` 抽出自有 API 子进程生命周期，新增 `prove_qwen38_crash_api.py` 和相邻负向测试。工具不接收待杀 PID，不接管占用端口，不结束未知服务；最多启动原进程及一次替代进程。失败时保留未确认回收的运行和数据库。

恢复、finalizer、原数据库归属、运行协调及四个 HTTP 证明器相邻回归 **141 passed / 275 warnings**；其中新增与原证明器 29 项已经包含在 141 项中，不重复累加。新增测试含真实操作系统子进程 SIGKILL，以及占用端口、非模型通知、错误 run、已有成功终态、原执行被替换和续租的拒绝验证。三个变更文件的 Ruff 通过。

完整测试命令、源码摘要、真实证明结果和启动清理记录见 [脱敏证据](../evidence/flagship-optimization-20260921/ml-02-business-crash-e165.json)；候选清单（本机私有路径：`var/flagship/e165-api-crash/candidate.json`） 绑定本报告与证据。现场原始日志仅保留在私有运行目录，公开记录不含凭据或模型正文。
