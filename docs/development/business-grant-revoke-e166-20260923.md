# E166：在途业务授权撤销与初始输出流修复

日期：2026-09-23。ML-02 的在途业务 grant 撤销已完成实际验收；同时修复原始聊天输出流缺少逐事件授权复核的问题。客户端及企业控制端冻结提交不变，在线研究 API 未替换。

## 发现与修复

既有 `/chat/active` 和重连 SSE 会复核当前业务授权，但最初发起 `/chat/stream` 的订阅没有同等保护。使用真实隔离 SQLite 授权表的负向测试复现：第一段内容返回后撤销 grant，旧实现仍转发后续 delta 和成功 done。

研究端 `agent_chat_runtime_impl.stream_chat_reply` 现在对受保护运行的原始订阅固定原运行/路由，并在每次输出前复用独立读取授权检查；撤权、账户失效、来源变化或数据库检查异常时，只返回 `read_authorization_lost` 并停止该订阅。尚未形成运行归属时不发送模型正文或成功结果。

后台正常收尾可能先从活动表移除运行，再由原订阅读完缓冲的终态事件。为此仅允许已捕获的原始订阅在明确终态、当前没有替代运行、原路由未变且当前业务授权仍有效时读完其事件。重连读取的默认严格语义不变；运行仍活跃却消失、被替换或已撤权均拒绝。

此修复保护服务端后续事件发送；已经发送到网络或客户端的历史字节无法撤回。读取失权与后台执行停止分开验证，不声称撤权操作与所有进程退出同步完成。

## 真机验收

| 场景 | 独立确认的结果 |
| --- | --- |
| 在途撤权 | 真实 Hermes/OpenShell/本地 Qwen 已返回 `source=model` 内容，原执行仍 running；管理员通过实际业务 HTTP 撤销该合成公司的 grant，没有调用 stop、修改租约或杀进程 |
| 读取拒绝 | 撤权前独立 active 查询返回正确原 run；撤权后返回 403。原始 SSE 返回 `read_authorization_lost`，仅 1 个撤权前模型 delta，0 个 done |
| 后台收尾 | 从发起撤权到原执行终态约 **18.735 秒**，状态 failed，API 自身 finalizer 为 released；该耗时为本次测量，不是性能上限承诺 |
| 运行隔离 | 在诊断父身份撤销前确认子身份 revoked、旧子凭据 401、沙箱/监督进程/转发均已消失；诊断父身份仍有效，不能用统一撤销父身份冒充业务撤权效果 |
| 正常流式回归 | 同一源码另起独立合成请求，1 run、1 done、0 error；模型标记正确、终态 succeeded、执行行 completed、模型桥 200，API 自身资源回收通过 |
| 清理与原环境 | 两个临时数据库、候选 API、隔离 AgentShield 均清理；候选网关零沙箱、owner 空闲、18083/47811 关闭。既有 API/模型/桥身份摘要未改变 |

撤权路径的模型桥首帧 200、终止 502 表示流中断，正常路径才有完整 200 结论。所有业务对象与授权均为合成；使用真实本地模型，没有云端回退或实际客户数据。

## 回归与证据

最终组合回归 **262 passed / 402 warnings**，包含读取授权、治理入口、活动运行、机密辅助模型、流式/工具循环及 HTTP 证明器；变更文件 Ruff、差异空白检查通过。初始负向测试修复前失败，修复后通过。额外回归发现旧机密上下文夹具使用无主体的虚构事件；夹具改用真实准备阶段 progress 和合法会话主体，保留原上下文隔离断言，没有放宽授权规则。

研究仓库新增 `scripts/openshell/prove_qwen38_revoke_api.py` 及其负向测试。证明器限定原执行，要求实际模型活动、真实撤权成功、独立读取拒绝和显式失权事件；错误 run、非模型通知、撤销失败、仍能读回、出现成功 done 都不能通过。API 进程与沙箱均不接收诊断管理员凭据。

完整命令、源码摘要、现场脱敏结果见 [E166 证据](../evidence/flagship-optimization-20260921/ml-02-business-revoke-e166.json)；候选清单（本机私有路径：`var/flagship/e166-business-revoke/candidate.json`） 绑定报告和证据。原始模型正文、HTTP 凭据与私有日志不进入公开证据。

## 剩余边界与回退

结合 E165，已补齐“模型输出后 API 崩溃/重启”和“模型输出后业务 grant 撤销”的候选实际验收。创建端点前未知窗口、终态结果提交前中断、故意注入 ExecStopPost 失败后的自动重试、其他宿主检索隔离、生产 IAM/审批/事件、原生 CI 和签名安装升级仍各按原任务验收，整体不记生产就绪。

本轮只在临时 API 加载研究源码，未部署在线 API、未改变数据库结构、Hermes profile 或模型配置。运行测试失败时保留未确认回收的运行和数据库；本次两条路径均已确认并清理。未来部署此修复后若需回退，不应重新开放存在撤权输出缺口的入口，应先关闭相应机密流式入口再恢复旧代码。
