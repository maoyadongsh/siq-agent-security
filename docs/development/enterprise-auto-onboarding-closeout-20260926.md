# 企业自动接入与可视化治理收口清单

日期：2026-09-26。承接 [ENT-001–022 总任务书](enterprise-auto-onboarding-taskbook-20260925.md)，不替换或缩减原目标。用户要求评估剩余工作并转向收口；本轮只整理状态、依赖和验收出口，不授权生产部署、设备上传、业务权限改变或签发发布。

## 1. 结论

已有较多可复用源码和隔离验证，不需要重做导航、权限事实、风险、策略、运行时绑定列表、框架树或审计查询页面。但**尚未进入“只差打包上线”阶段**：角色—技能精确关系、运行时/共享沙箱绑定与完整影响确认仍有明确功能缺口；真实安装、独立审批、OpenShell 行为和恢复链路尚缺本轮交付证据。

停止按零散 UI 优化继续扩张。后续仅执行下方 8 个收口工作包；每个包绑定原 ENT 编号及可复核的结束条件。工作包通过不等于整个 ENT 通过；原任务书所有要求仍需逐项满足。不能以“已有只读页面”“网络权限可撤除”代替完整关系和治理目标，也不能把缺少真实平台证据的要求移到 P2。

M0–M4 当前均不能宣称完整交付：M0 已有基线/合同但需最终冻结重验；M1 缺真实安装服务闭环；M2 缺精确关联和运行拓扑；M3 缺完整运行约束、共享影响及审计闭环；M4 缺本轮可复现签名制品与原生部署/恢复证据。

## 3. 8 个剩余收口工作包

### CL-01：统一源码基线和集成门禁

对应 ENT-001、003、020；贯穿 M0–M4。主责：主开发者，涉及 Gateway/Platform 时各仓独立验证。

- 清点并行交付和当前在途文件，形成“文件→责任线→合同版本→验证结果”清单；同一文件只留一个在途责任人。
- 收完配置历史面板：浏览器、正式模式构建、身份切换、分页/重试和长内容验收。接旧快照对照时只复用已实现接口，不再扩展新的历史产品形态。
- 当前前后端、Edge、实际修改 Connector、安装/发行工具、迁移、跨语言 wire 全量门禁一次贯通；记录命令、源码摘要、原始输出和跳过原因。旧 /tmp 样本须重新生成并校验来源，不能仅复用历史绿灯。
- 在隔离 PostgreSQL 验证现有数据升级、租户约束、批次 CAS/幂等/并发及审计失败回滚，不以 SQLite 单测替代生产数据库证据。
- 冻结候选源码身份前不提交/签发；明确当前工作树与将来提交身份的对应关系，保护已有历史制品。

出口：单一可复现基线、无未解释失败、合同生产者/消费者对齐、在途文件全部有状态。没有通过则不进入正式交付。

### CL-02：可信安装与后台自动接入闭环

对应 ENT-002、004–007、012、017、021；M1。主责：主开发者（Edge/release），部署侧后续经授权由 Platform/Gateway 配合。

- 复用现有 setup、计划验签、交互范围确认、能力实测、serve、首扫、注册恢复和服务诊断；核对普通安装用户是否仍需源码、Go 或手工准备 Connector，补齐实际缺口。
- 从可搬运候选安装产物执行完整旅程：确认控制面/组织/环境/范围→注册→后台服务→心跳→指定设备任务→配置和技能上报→前端结果。明确区分浏览器 Mac 与执行 Linux。
- 原生 systemd 用户服务验证登录/退出/重启、单实例、断网恢复、失败退避和升级；不擅自启用 linger 或 system service。持续扫描需要明确周期/资源预算，实际确认重扫可发生，而非仅首扫或手工下发。
- 覆盖错误目标、过期/重放、错误租户/环境、取消、丢响应、制品篡改、能力变化、吊销、未决日志恢复；范围外读取默认拒绝。
- 用受控 CLI+网关方案复核 TLS/身份/版本/能力；保持缺配置、失联失败关闭，不给 Edge 增加隐式策略发布权限。

出口：获准测试目标中安装到前端盘点自动完成，用户无需分别执行 register/heartbeat/tasks；各阶段失败可恢复且不假报“已保护”。正式签发和真实设备操作留在授权门禁内。

### CL-03：框架—角色—Skill 关系与漂移收口

对应 ENT-008、009、011、018；M2。主责：主开发者合同/采集器，前端只消费冻结投影。

- 保留已验收框架树、角色来源、独立技能位置身份及历史证据；将有证据的 Skill 安装/manifest 版本接到对应角色，而非按同名、同设备或单一目录猜测。
- 明确区分目录候选关系、配置显式选择、安装观察与真实加载；共享、未关联、未启用、不可读分别展示。没有证据必须保持未知，不能为“完整树”补造节点。
- 补齐 Hermes 与 OpenClaw 要求的默认/显式根、多 profile/agent、项目/工作区、显式技能关系。先做支持矩阵和缺项测试，不再无条件扩大框架覆盖；不支持的布局必须明确报错或未知，不能算完成。
- 接完旧配置快照选择与已有对照 API；明确双侧观察时间，不把最新技能观察称为历史重建。
- 验证重复扫描、改名、修改 manifest、共享技能、失败扫描、权限不足、卸载后再出现；失败不清空旧资产，未观测不自动等同卸载；批量确认/驳回保留人工边界。

出口：两框架的既定用例从受控合成采集到真实 API/界面贯通，稳定身份、版本、来源和漂移可解释，所要求的搜索/筛选/批量选择可操作且不扩大权限。

### CL-04：Linux/DGX/OpenShell 拓扑和运行时绑定

对应 ENT-010、012、013、014；M2→M3。**当前核心功能缺口之一。**

- 将既有进程/systemd/容器采集线索与框架角色做证据限定关联；区分宿主、容器和远程视角、实际 DGX/架构识别及用户环境标签，不扫描整机或默认读取 Docker socket。
- 补齐角色/Skill 摘要、设备、实际执行身份、沙箱及 revision 的绑定和变更失效联动；不把人工 active 登记或用户 attestation 当作归属证明。
- 明确共享沙箱覆盖对象；只有一条数据库绑定不能证明独占。继承、交集、冲突及后端不可表达限制必须有可执行判定。
- 将完整影响确认与执行时复验绑定，不能把当前 `registered_binding_only` 报告变成可执行确认。无法单独隔离 Skill 时清晰展示并拒绝承诺独立约束。

出口：目标替换、跨租户/环境、设备漂移、Skill 变更、revision 变化、吊销和共享影响均有正负测试；外部写入前复验，未知归属不被 UI 或模型绕过。

### CL-05：批量权限到实际效果的闭环

对应 ENT-014–016、018；M3。依赖 CL-03/04。

- 复用当前权限事实、跨策略网络撤除申请、独立审批、批次预览/持久预约/执行/未知结果恢复，不重建第二套流程。
- 核对原需求中各权限域与后端实际可表达粒度，形成支持矩阵；网络撤除已实现不能代表全部权限完成。对当前不支持独立 Skill 限制的情况保留显式限制，不能以“未来支持”假关单。
- 收窄/撤销闭环先收完，再核对权限扩大与策略模板是否能通过既有独立审批完成；提出者不得自批。批量仍逐项绑定操作者/目标/版本/期限/预览摘要。
- 将共享影响确认、CAS、审计事务与执行复验接通；丢响应不盲重放，部分失败/未知结果可读回；离线撤权不显示已生效。
- 在受控真实 OpenShell 目标上独立读回 revision/摘要，并执行允许与拒绝行为对照；恢复/回滚同样审批，禁止自动复活过期授权。

出口：前端选择→影响→独立审批→实际约束→逐项结果全部有同一业务链证据，而不仅是 POST 返回成功。

### CL-08：正式签名制品、部署与文档一致交付

对应 ENT-004、021、022；M4。制品准备可先行，正式交付依赖前述门禁。

- 复用 enterprise_candidate/finalize 与独立验签工具，固定源码、能力清单、ARM64/AMD64 制品摘要、版本与发行身份；生产安装不能使用模拟身份构建。
- 确认受控签发入口、可信公钥及发布位置。签后组包工具不会自己签发；本轮未查找/读取私钥，也不假定签发入口已经可用或不存在。
- 最终签名产物在原生平台复验安装/升级/验签/恢复；测试候选通过不自动外推到签后产物。
- 经明确授权在已有部署拓扑切换，复用 DGX 环境而非重复创建；迁移、服务切换、回退和运行版本可查。
- README 中英、Skill 安装说明、运行/升级/卸载手册与**同一实际制品**同步；保持 README 主体结构，不用新文案覆盖未实现能力。
