# E159 业务生成回复查看页

在研究业务 Web 内增加 `/analysis/run-result?session_id=...&run_id=...`，沿用业务登录和同源 API。分析助手成功结束的结构化 run/done 事件若明确来自 OpenShell/confidential_local，可在对应回复旁提供“查看运行结果”；仅使用服务端事件的准确 run/session，不从正文、报告 URL 或旧聊天猜测绑定。历史消息没有该绑定时不伪造入口；安全控制台跨业务连接仍须后续实现。

实际聊天完成后会重新加载历史，因此本批仅以服务端审计编号与同一会话的精确匹配保留已获得的运行绑定，不使用既有按正文匹配的审计回退来关联结果。没有服务端审计匹配时不保留链接。绑定当前只在页面会话中，刷新后完整历史入口须由业务侧持久关系/目录接续；已保存的结果深链接可独立刷新读取。这不是完整历史目录交付。

页面先读取 E156 元数据，用中文区分运行中/整理中/已结束/失败/停止、空结果/待确认/超限/可查看。正文须用户点“查看正文”才 POST confirm_display=true，完整校验身份引用/快照/字节数与摘要，再以纯文本显示；不渲染模型 HTML，不自动发布或下载。刷新状态、关闭正文、切换运行、切换业务身份、隐藏页面或卸载时清空正文并取消请求，迟到响应不得复现。刷新不自动重读正文。错误给出明确中文原因及可行操作。

复用既有界面语义色/字体，不引入展示型仪表盘；主要动作至少 44px，键盘可用，状态与错误有读屏提示，窄屏不横向溢出。登录后深链接沿用原登录返回机制。用户可返回智能分析，不自动切换业务会话或启动运行。

实现先定规格，v1 HTTP 合同不变。验证实际 API + 隔离授权库 + 浏览器链路（合成业务身份，不冒充生产 IAM 或真实模型），补请求竞态、拒绝、正文校验、显式确认和结构化消息绑定测试；前端类型/lint/构建。不改在线 profile/模型、业务库或已安装客户端。终态提交前恢复、正式产物和安全控制台业务连接继续。
