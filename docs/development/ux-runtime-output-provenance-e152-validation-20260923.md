# 运行输出来源关联（E152）

日期：2026-09-23。UX-11 继续实施，总目标保持 active。

## 发现与实现

检查运行结果页及业务发布接口后发现：原生采集入口已经验证运行身份、会话和授权绑定，但密文只保留 task_ref。直接将这些任务级记录展示为“本次运行输出”，会把同一任务下其他会话的内容也归进来。现有 SIQ connector 只有匿名引用，也不具备业务正文读取权限。

本批补齐可信来源基础：

- 新增 `local-raw-task-content-envelope/v2`，把运行身份、会话和绑定的 SHA-256 引用与正文一起纳入 AES-GCM 认证数据；来源和密文一次原子落盘。
- `CaptureWithPermit` 仅从已经复验的元组派生来源，不接受模型或正文携带的来源声明；现有原生采集 API 与 Hermes/OpenClaw 钩子无需改请求格式。
- 新增内部 `ListRuntimeOutputs` / `ReadRuntimeOutput`，同时匹配 task、runtime identity、session、binding，并只选择 output 类型。列表只给认证后的元数据；读取重新检查来源、密文与保留期。
- 旧 v1 仍能在任务原文管理中读取，不重写、不补猜测来源，也不会进入运行级输出集合。元数据/读取 HTTP 合同保持原有形状。

采集仍默认关闭，启用仓与任务授权仍需分别满足；本批不会替用户打开采集。来源证明仅说明内容在哪个已授权运行上下文中采集，不能证明内容正确、报告已发布或业务任务成功。

## 验证

| 验证 | 结果 |
| --- | --- |
| Go 全量 | 44 包通过 |
| 来源与原生采集路由 | rawcontent / server 定向测试及 race 通过；实际路由授权、采集和存储路径，无替代 writer |
| 跨语言合同 | 269 项通过；Python 按 Go 生成的 v2 样本实际解密，修改任一来源字段均无法通过 GCM 验证 |
| 兼容 | 原 v1 字节级确定性样本继续通过；v1 可按任务读取，但不能匹配运行输出 |
| 生命周期 | 重新打开存储后来源保留；同 task 不同身份/会话/绑定及 input 不混入，过期拒读、删除后消失；到期使用注入测试时间，并非真实等待一小时 |
| 负向 | 来源篡改、来源缺失、伪造降级到 v1、跨任务/运行读取被拒绝；异常记录不会被静默过滤成空列表 |
| 构建 | vet / 改动文件 gofmt / Ruff / diff 检查通过；Linux arm64/amd64、Darwin arm64、Windows amd64 编译成功；本机 arm64 候选 version 运行成功 |

## 兼容与继续开发

旧版本对 v2 envelope 会严格拒绝读取，不能通过删来源或改 schema 来降级。回退前停止新采集，完整保留状态并用兼容版本读取；旧程序新增的 v1 也不能被新版本猜测归入某次运行。全局目录格式不升级，v1/v2 兼容由原文仓自身处理。

本批完成来源存储与内部查询基础，**用户可见的业务输出功能仍未完成**。下一步将活动回执的可信绑定解析到该来源，增加只读输出目录及显式读取接口，结果页支持读取失败、过期、空记录与刷新清除，并用真实浏览器/原生钩子验证；报告文件下载、业务名称和生命周期继续单独接业务系统权限，不借本地管理权限旁路业务授权。
