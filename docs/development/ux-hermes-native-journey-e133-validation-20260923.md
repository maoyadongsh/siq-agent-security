# Hermes 页面接入与原生自检验收

日期：2026-09-23。状态：候选实现与本批验收完成；最终结果见 [E133 证据](../evidence/flagship-optimization-20260921/ux-hermes-native-journey-e133.json) 为准。整体目标继续执行。

## 本批交付

首页完成 Hermes 接入后，重新读取后端实例诊断，再提供“验证刚接入的实例”。按钮打开该实例的原生自检预览，用户确认后才启动测试。回调使用实际应用的操作；在接入弹窗切换为卸载、恢复中断操作或读回未就绪时，不误显示安装成功的下一步。

刷新页面后，可从对应卡片的“验证连接”恢复后台自检，读取同一检查 ID，不重复启动宿主或创建授权。自检时间采用中文、24 小时制。既有允许读取、越权写入拒绝、拒绝后继续读取、签名回执核验与临时材料清理保持原语义。

## 验证方式

使用独立候选二进制、真实 Chromium、真实管理 API 和本机 Hermes 0.21.0 公共 CLI。测试从未安装连接组件的临时 profile 开始，通过页面点击安装和原生启用，不再由测试脚本提前调用安装 API。

模型端是产品自检使用的临时 loopback 合成响应服务，Hermes 的原生 agent loop、插件和文件工具实际执行。未调用付费云模型、未读取真实业务内容。宿主安装已有项目适配补丁，此证据不是未修改上游版本的认证。

| 用户操作 | 验收事实 |
| --- | --- |
| 接入此实例、确认应用 | 后端配置读回 ready，原设置及其他 profile 保留；没有自动创建日常授权 |
| 验证刚接入的实例 | 精确绑定刚安装的实例；打开预览不创建临时授权 |
| 确认并开始自检 | 原生 Hermes 完成读取允许、写入执行前拒绝、拒绝后读取允许；5 条关联回执可见 |
| 关闭、刷新、再次验证连接 | 管理会话恢复；同一检查 ID 与结果读回，只有一份测试授权 |
| 重新预览 | 修改配置后旧结果失效且不能启动；恢复配置后仍不复活旧结果 |
| 取消自检 | 后端读回测试授权 revoked，页面显示撤权及材料清理完成 |
| 切换卸载、确认应用 | 自有插件移除；验证入口与安装继续按钮消失 |
| 小屏及键盘 | 390px 弹窗内容适配，底部操作可滚动到达，Tab 留在弹窗；浏览器无脚本异常、存储无管理凭据 |

**最终候选 v2：原生自检浏览器 20 项、双平台权限浏览器 49 项全部通过；前端 35 文件/243 项回归、本地及企业前端构建、候选编译、Ruff 和差异检查通过。** v1 中间结果与 v2 最终结果分别保留；v2 同时包含中文日期修正。

同时复验 E132 的双平台权限旅程，包括页面编辑/批准/安装/停用、后端持久化、真实工具允许/越界与撤权后拒绝，以及运行记录/详情/刷新/返回。两份浏览器检查存在重叠，不相加作为覆盖率。

## 复验入口

先构建本地嵌入前端和独立候选二进制，再执行：

```bash
python scripts/personal-experience/runtime-check-browser-smoke.py \
  --binary var/flagship/ux-e133/siq-agent-security-v2 \
  --hermes-cli /home/maoyd/siq/hermes-agent/.venv/bin/hermes \
  --out-dir var/flagship/ux-e133/browser-next
```

Python 需可用 Playwright/Chromium。输出目录应使用新名称；失败只记录异常类别与代码行，不导出原始响应或异常文本。脱敏证据索引包含候选、源码、日志和截图摘要，以及基线/中间结果。

## 剩余边界

- 这条 UI 旅程证明连接组件到真实 Hermes 工具门禁；日常业务权限旅程沿用 E132 的单独验证，不能合并声称完整真实模型业务已验收。
- 自检回执到精确运行详情的一步直达仍需补齐，不能猜测任务 ID，或只读取前 500 条回执后把遗漏视为无记录。
- 完整模型会话、业务结果产物、统一 OpenShell/模型发现、企业接入向导与新安装包仍按任务书继续实施。
- 未升级已安装发行版，未重启用户常驻服务，未修改冻结 Hermes 快照或真实 profile；整体候选仍不具备生产验收资格。
