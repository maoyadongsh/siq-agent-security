# E159 业务生成回复查看入口

已接通研究业务前端的“查看运行结果”到真实结果 API，并补齐显式正文读取和登录返回。源码候选未部署；这不是安全控制台的业务连接或正式报告发布功能，总目标 active。

## 用户可见行为

分析助手通过结构化 run/done 事件获得准确运行、会话与 OpenShell/confidential_local 来源后，可在相应回复旁打开结果页。聊天结束会重载历史，本批用**服务端审计编号 + 同一会话**精确关联保留绑定，不按相同正文猜测。没有可靠关联的消息不显示入口；完整历史目录仍需后续实现。

结果页先展示中文运行状态及结果是否就绪，不自动读取正文。用户点击“查看正文”后，实际 POST 确认读取；引用、快照、字节数与 SHA-256 都匹配才显示纯文本。模型中的 HTML 不执行。空结果、未停止写入、超限、撤权、缺失、状态变化和读取失败都有独立说明及恢复操作。正文已显示时，提示同步变更，不再要求点击不存在的按钮。

关闭正文、刷新状态、换运行/身份、隐藏页面会清空正文并取消请求，迟到响应不恢复正文；刷新需要重新确认。接口请求有 15 秒时限。未登录打开深链接时保留返回位置，登录后回到原运行，仍由业务 API 校验权限。“返回智能分析”只导航，不启动运行或更换业务会话。

沿用既有界面、语义色与字体，运行标识默认折叠；操作按钮至少 44px，错误/状态有读屏语义。已查看 1440px 和 375px 实际截图，正文及恶意长标签按文本换行，无内容区横向溢出。本批使用 ui-ux-pro-max 与 React 最佳实践检查交互，没有引入无关配色、图表或新依赖。

浏览器身份来自显式测试依赖覆盖，登录响应和聊天 SSE 是合成夹具；没有调用模型、Hermes/OpenShell 实例或真实生产 IAM。结果数据确实通过 E157 存储保存，运行内存缓冲已清空，页面走真实授权读取路由；夹具的撤权操作修改实际隔离 grant 表。UI 不使用安全控制台管理员身份替代业务权限。

首次组件测试的文本断言被换行规范化影响，改为核对正文区域的原字符串；首次聊天绑定测试发现历史重载丢失字段，修复精确关联后通过；首次浏览器夹具遗漏真实 `/api` 前缀，按实际代理路由修正后通过。一次从仓库根执行 Vitest 因目录错误失败，最终均从 `apps/web` 运行。没有将这些初次失败记为通过。

## 当前边界和后续

- 这是研究业务端的生成回复查看页，`publication_status=not_attested`；没有新正式报告下载/发布按钮。
- 已保存结果的深链接可刷新后重新授权读取；聊天内绑定目前来自本页已见事件及精确审计关联，刷新后完整历史目录尚未完成，不能将缺绑定消息的链接补造出来。
- 安全控制台的显式业务身份连接、可信运行映射、持久历史目录、正式产物归属与发布核验继续。
- 终态到结果提交前的崩溃恢复、生产 IAM、安装发行验收继续；已展示内容不能被远程“收回”，新的读取会实时重验权限。

回退本批新页面/路由、结果客户端、消息绑定及登录返回增量即可，不删除 E157 结果表或历史数据，保留用户原有 Settings/ProviderForm 改动。未提交、推送、部署或替换已安装客户端，SEC-F01–F10 保持后续顺序。
