# OPT-08 D2a：原生身份的版本化读回与消费者保护

日期：2026-10-07。对应 ADR-056。范围为已签名身份的管理/运行读回、前端 API 边界和旧 Hermes 插件拒绝新协议；OPT-08 继续 implementing。

## 问题与实现

D1 已将必需原生 Skill 校验固定到签名身份，但旧摘要和会话响应不包含这项策略。若沿用旧响应，会把新身份表述成普通身份。因此本批先版本化合同，再同步实际投影和消费检查。

| 响应 | 新原生版本 | 行为 |
| --- | --- | --- |
| 根身份发行 | `local-runtime-identity-issued/v3` | 摘要含必需策略；当前只验证产品响应投影，管理创建入口仍关闭 |
| 请求级身份发行 | `local-runtime-request-identity-issued/v2` | 继承父策略，保留原请求生命周期、幂等及凭据路径返回规则 |
| 身份 self | `local-runtime-identity-self/v2` | 只返回认证后身份元数据，撤销/取消后不返回 active |
| 会话登记 | `local-runtime-session-enrolled/v3` | 返回签名身份固定策略；登记不等于原生宿主已验证 |
| 管理列表 | `local-runtime-identities/v3` | 容纳原有 POSIX、Windows 和原生身份；至少含一条原生身份，版本不因排序降级 |

所有原生读回均保持 `runtime_state=unverified`。摘要、self 和会话响应不包含 token、credential hash 或签名；发行仍仅返回本机凭据文件路径。原身份/响应合同和冻结样例不改写。

前端允许读取符合合同的混合列表，但拒绝必需模式丢失、伪称可选、未知制品摘要、大小写别名、Windows/平台冲突、超出 512 条预算以及旧响应夹带策略。既有普通身份创建流程不接收原生身份响应，不擅自升级授权流程。本批改变 API 数据读取，不新增“已保护”标签或原生身份创建界面。

Hermes 旧路径插件已具备精确字段和版本检查，本批不放宽该检查。新增九组负向场景（三种模式 × 三种响应变体），证明即使模拟后端准备返回 allow，新版会话、旧版本夹带策略或缺少策略的新版本也不会进入 `/v1/decide`。这项兼容拒绝不替代后续可信宿主接入。

## 验证结果

| 验证范围 | 结果 |
| --- | --- |
| 实际服务处理器与身份存储 | 根/子身份 self、混合列表、会话、请求签发重试、取消、撤销及私密字段排除通过；根身份通过组件创建，新 HTTP 创建仍拒绝 |
| 跨语言合同 | 相关 Python 合同 300 项通过；包含五组由 Go 实际投影归一化的新公开样例及混合列表、降级/字段错误反例 |
| 前端 | 117 个文件、1,082 项测试通过；新增 20 项使用实际 Go 样例验证读取和拒绝行为 |
| Hermes 旧路径身份测试 | 69 项通过，包含新增九组模式/版本反例；未执行真实模型或日常业务任务 |
| Go | `go vet ./...`、`go test ./...` 通过，44 个测试包、10 个无测试包；runtimeidentity/server 身份、请求和原生相关定向 race 通过 |
| 构建 | 生产与本地 Web 构建通过，嵌入资产已更新；最终嵌入检查和 linux/amd64、linux/arm64、darwin/arm64、windows/amd64 构建通过 |
| 格式 | 定向 Ruff、gofmt 与 `git diff --check` 通过 |

Go 样例只归一化生成的 ID、摘要、时间、TTL 和凭据路径；版本、字段存在性、策略和状态与实际投影相同。请求身份与父身份使用不同合成 ID。样例用于合同，不是可部署凭据或签名执行证明。根身份发行样例来自产品投影函数，不能宣称已通过新管理创建入口。

日志、构建产物保留在本机 `var/optimization-20261007/opt08-readback-*`，不提交原始日志或二进制。Python 有既有 Starlette/httpx 弃用提示，本地构建有既有大 chunk 提示；均未导致失败。本批没有页面交互变更，未新增浏览器效果测评；既有浏览器结果仍按其原范围解释。

已检查固定业务镜像的 Skill 加载路径：重复加载可走缓存，使用计数/通知是 best-effort，不能直接作必需 Authority。后续必须接通可信宿主事实与凭据隔离，覆盖首次加载、缓存命中、最终调用、任务切换和关闭，再进行 `serve` 接线及两个真实 Skill 的日常业务验收。本批没有修改业务仓库、替换运行镜像或启用原生执行，不能计为 OPT-08 完成。全部适用优化任务及门禁完成后按授权推送远端。
