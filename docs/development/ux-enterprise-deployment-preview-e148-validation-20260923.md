# 企业部署预览与提交重验（E148）

日期：2026-09-23。承接 E147 / ENT-UX-04，总目标保持 active；外部检查 SEC-F01–SEC-F10 保持后续顺序。

## 用户可见变化

点击部署后先核对策略名称/版本、执行环境、登记目标、保护方式、执行后端和实际操作。勾选确认后才提交；取消预览不创建任务。手机窗口操作区保持可见，技术标识默认折叠。开发测试后端明确说明只创建下发任务，不显示 OpenShell 已生效。

提交重新读取批准状态、策略、绑定、目标和执行端版本，并比对身份绑定的预览摘要。内容或版本变化拒绝旧预览，要求重新核对。提交后的独立结果读取及响应丢失核对沿用 E147；不会因预览成功宣称策略已生效。

浏览器验收发现后端 FastAPI 的 `detail` 错误码未进入前端 ApiError，导致拒绝原因显示为泛化提示。已修复为只接受有界机器码，并用精确中文映射解释；自由格式异常内容仍不展示。该修复有实际 HTTP 响应解析测试和浏览器过期预览负向验证。

## 实现与安全边界

新增三个版本合同：`deployment-preview-request/v1`、`deployment-preview/v1`、`deployment-preview-submit/v1`。新增只读预览 POST `/api/v1/deployment-preview` 与执行 POST `/api/v1/deployment-preview/submit`；旧 `/deployments` 保持兼容。

两条新路由复用真实部署前置检查和编译流程，先按租户定位变更/策略/环境/绑定，再核对权限；额外要求策略和环境读取权限。修正登记绑定后端与当前配置后端不一致仍可部署的问题。预览不 apply、不创建 Deployment/EdgeTask、不写审计。

摘要覆盖当前身份、审批参数、完整策略、环境和绑定、编译制品，以及 OpenShell 的目标、计划类型、版本、基准策略摘要和网关调用指纹。新 OpenShell 路径要求稳定指纹和已验证握手。执行使用重新检查后的同一计划，保留既有 revision/digest 检查；部署创建/失败/验证审计与状态同事务写入 preview_digest，不存策略内容。

本批没有增加持久部署意图/幂等表，不证明跨客户端执行恰好一次，也不声称消除了数据库与执行端之间的所有并发撤权窗口。旧兼容接口不因新 UI 存在而自动要求预览。持久恢复、生产 PostgreSQL 并发、完整差异/建议及主动行为核验继续待办。
