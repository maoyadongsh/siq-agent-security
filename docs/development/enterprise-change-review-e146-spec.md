# E146 企业变更审查与审批读回

状态：本批实现与隔离验收通过；完整 ENT-UX-04 继续。承接 ENT-UX-04；优先体验主线，SEC-F01–F10 仍在后续清单。

## 用户链路

变更清单 → 查看策略名称、版本、模式、提出者、审批类型 → 逐项核对目标及权限内容 → 明确批准或驳回 → 独立 GET 核对同一变更单 → 后续选择部署目标。批准不等于下发或生效。用户关闭审查不产生写入；无权只读、本人不能批准本人提案。

本批补齐审批工作台；部署操作的独立预览、运行时效果及组织 IAM 接入继续留在 ENT-UX-04/02，不能借本批标为全链路完成。

## 新合同

- `GET /api/v1/change-requests/{id}/review`，`change-review/v1`：先本租户对象定位再 `policy:read`，返回精确变更 ID、状态、策略名称/版本/模式、审批类型、提出者/处理者、内容章节、当前账号可执行动作与原因、快照摘要。章节覆盖编译输入全部权限域，以及申请人填写的影响说明；空值明确表示未配置，不推断默认权限。目标只显示已在策略中的标识，不扩大资产目录权限。
- `POST /api/v1/change-requests/{id}/review-decision`，`change-review-decision/v1`：严格 body（版本、approve/reject、64 位摘要）；同租户定位，重新检查 `policy:read` 与 `change:approve`。摘要绑定身份、租户、变更状态及审批参数、完整策略及前一版本的降级判断依据。内容变化返回 409，客户端重新审查，不自动重放。
- 复用既有批准/驳回逻辑、SoD、降级和 break-glass 语义；审计与状态同事务，并仅增加摘要（不记内容）。保留旧批准/驳回接口兼容性，旧调用方不自动获得快照保护。
- PostgreSQL 新写路径锁变更和策略行；SQLite 验收不冒充生产并发证明。没有新增策略内容编辑接口或持久批准摘要，亦不声称消除管理员直接改库/历史客户端的全部竞争窗口。

## 内容与交互边界

审查章节输出有界纯文本 JSON，由 React 文本节点显示；敏感字段名及当前规则包已知密钥模式脱敏。任一章节脱敏、超长或过深均显式告知并禁止本入口批准，驳回仍可用。规则脱敏不替代入口 Secret 校验，也不声称检测所有未知密钥格式。每章节最多 6000 字符、最多 16 章节，嵌套深度最多 16；不返回完整原始内容备用字段。

UI 不根据角色名称猜权限。审查期间串行提交；POST 超时或独立 GET 失败时保持待核对，只提供 GET 核对结果，不直接再次提交。刷新得到仍待审批时清除勾选，需重新审查后才能操作。状态由同对象 GET 读回；不能把别人的处理说成自己操作成功。页面错误使用稳定中文说明，不直接输出服务端内部异常。

## 验证

合同样例、完整权限域覆盖、跨租户/缺权限/本人审批拒绝、旧摘要/状态变化/策略变化/前版本变化拒绝、敏感和过长内容禁止批准、审计摘要与单次状态读回、旧路由回归；真实隔离 API 浏览器验证取消、批准/驳回、响应丢失核对、刷新保持结果、只读入口及移动端。无模型或真实 OpenShell 下发参与本批审批验证。
