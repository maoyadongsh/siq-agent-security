# OPT-08 D1：签名身份固定原生 Skill 管控策略

日期：2026-10-07。范围：身份存储、请求级身份继承、必需模式选择、引擎查询桥接和发行回退预检。OPT-08 保持 implementing；本批不是原生 Hermes 日常业务验收。

## 实现与安全含义

新增 `local-runtime-identity/v4` 根身份与 v5 请求级身份，使用独立的 create/v3 合同。原身份 v3 已用于旧式请求身份，继续保持其原有含义。新身份签名固定 `native_skill_policy.mode=required` 和运行制品 SHA-256，只接受 Hermes、无 Skill 的 Agent baseline。原 v1/v2/v3 不增添可选策略字段，不改写历史签名。

请求级身份继承父身份策略的独立副本，父摘要覆盖完整策略；签发和认证继续检查父签名、撤销、Grant、会话、租约及请求取消。子身份不能删除策略、替换制品摘要或再充当根签发器。策略只声明管理员要求，不能单独证明真实宿主加载了该制品。

`NativePolicy` 从有效签名根身份读取必需模式，独立于 SEC、原生会话和调用文件是否存在。受管 hri 主体的根身份缺失、损坏、冲突、撤销、实例解析失败或 Grant 失效均返回错误，不能用“没有调用记录”解释为旧式模式。普通 Agent 与明确有效的旧式身份保留原路径。

`NativeCallStore.RequiredLookup` 将此身份策略连接到已有原生调用校验：每次查询先核验策略，再验证精确会话、调用及上下文，并比较会话运行制品与身份固定摘要。查询错误属于必需 Authority 失败，block、warn、audit_only 三种模式均拒绝。实际会话制品事实仍必须由后续可信宿主回调提供，测试夹具不替代此信任来源。

管理 HTTP 仍不接受新的 create/v3 请求。对于组件内部创建的新身份，若服务尚未配置原生查询，HTTP 决策认证返回固定 503 `native_skill_runtime_unavailable`，不进入旧决策路径。本批未给 `serve` 接入原生调用验证，也未向模型或工具下发管理凭据。

## 回退兼容

原生身份可能早于第一条原生会话出现。因此，候选 reader/writer 低于 5 时，发行预检也检查 `runtime-identities`：发现 v4/v5、未知/异常字段、非法记录或不安全文件即拒绝。保留原私密目录快照检查，最多 512 个条目、每条 16 KiB；检查失败不放宽。不改写存储 marker，不删除新记录来迁就旧程序。

预检是有界格式兼容检查，不冒充身份签名认证，也不约束同 UID 用户绕开产品工作流直接启动旧二进制。当前尚未发布的 reader/writer 5 能力涵盖本批新身份；历史发行清单保持冻结。
