# OPT-08 D3u：原生 Skill 业务请求的在途授权撤销

日期：2026-10-07。OPT-08 保持 `implementing`，完整验收任务仍为 **9/16（56.25%）**。

## 1. 真实故障与修复

在 DGX Spark＋本地 Qwen＋Hermes 原生 Skill＋OpenShell＋智能分析助手链路中，v817 已加载真实只读 Skill、读取实际公司元数据，模型开始输出后，管理员调用业务授权撤销 API。原测评器记录 `candidate_revoke_http_failed`，未得到撤权成功确认。本次未保存该 HTTP 响应的状态和正文，因此不宣称观察到了某个具体状态码。

源码复核和新增回归复现了接线缺口：业务授权先落库撤销，但后续执行身份隔离只读取旧 `agentshield_identity`，无法处理原生 v6 的 `agentshield_native`。失败后业务续期检查仍拒绝，原请求与临时资源最终完成清理；清理成功不能替代撤权接口的完整确认。

业务侧 `apps/api/services/openshell_grant_revocation.py` 已补齐原生分支：先核对原数据库 ownership、完整 execution binding、租户／用户／项目／公司及对象范围，再按准确原生记录经公开 API 取消请求子身份。共享父身份保持有效；未知版本、混入旧引用、绑定变化或下游服务失联均不报告成功，也不回退旧实现。已经落库的业务撤销保持，不因为后续确认失败而恢复权限。

## 3. v818 实际结果

| 检查点 | 观察 |
| --- | --- |
| 撤权前的真实业务 | Skill 加载和公司元数据读取成功，读取回执归属已验证的只读 Skill；已观察到模型输出 |
