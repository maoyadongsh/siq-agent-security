# E152 运行输出的可信关联

状态：来源存储与内部查询基础已验收，页面/API 接续待实施。承接 UX-11，先补产物查看所需的来源事实，再接页面；不能把任务级原文或工具成功回执冒充某次运行的业务报告。

现场检查：Hermes 原生钩子已有经当前运行时身份、会话、绑定和单独原文授权验证的采集入口，但存储只保留 task_ref，丢失已验证的 session/binding/identity 关联。同一任务下不同会话的原文不能直接放入单次运行的“结果”。SIQ connector 只有脱敏观察，不提供正文读取权限。

本批实现范围：

1. 新增 local-raw-task-content-envelope/v2 存储合同，在 AES-GCM AAD 中绑定 source 的 runtime_identity_ref、session_ref、binding_ref；来源仅由 CaptureWithPermit 已复验的元组派生，不能由内容字段或模型声明注入。
2. 旧 v1 原文继续按任务查看，不填补或猜测来源，不重写旧文件。无运行时来源的管理采集仍为 v1。现有元数据/读取 API 合同不变。
3. 新增内部按完整 runtime identity/session/binding/task 筛选输出元数据和读取的方法；v1、不匹配来源、非 output 一律不视为该次运行的输出。筛选不返回正文，读取仍检查保留期、密文认证与凭据过滤。元数据需完整认证，伪造来源不能改变归属。
4. 验证同 task 不同 session/binding/runtime identity 隔离、来源篡改拒绝、旧 v1 可读但不能归属、输入和结果分离、到期/删除、服务端原生采集路由保留来源、重启读回及跨平台编译。
5. 后续接单次活动来源解析、只读列表/显式读取 API、中文结果面板及真实 Hermes 浏览器链。此批不宣称完成报告下载、业务生命周期或正式业务结果核验。

隐私与兼容：新增的来源仅为哈希引用，不持久化身份原文。采集仍默认关闭，仓级启用和任务级授权缺一不可；签名 permit 仍不是独立凭据。v2 文件与内容同时原子写入，不产生先有正文后补来源的窗口。旧程序严格解码会拒绝 v2，不删除或降格文件；回退前停止采集并保留完整状态，使用兼容版本读取，不修改 schema 字符串或解密迁移。未升级全局状态目录版本，v1/v2 由内容仓自身严格识别；旧程序产生的 v1 始终不能进入运行级输出集合。
