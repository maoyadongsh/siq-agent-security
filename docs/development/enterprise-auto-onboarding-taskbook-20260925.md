# 企业自动接入与可视化治理优化任务书（2026-09-25）

## 1. 授权、目标与状态

用户要求：企业端面向 DGX Spark + Linux + OpenShell，安装后能够便捷接入当前环境，发现框架、智能体角色、技能及权限，通过前端批量管理，并保留此前防攻击、运行时绑定和可追溯审计能力；随后明确要求“落盘所有优化任务”。

初次交付仅为任务规划，全部实施任务初始为 `todo`。**后续用户已明确要求设为持续目标并持续开发，当前已启动源码实施与验证**，详见[开发记录](enterprise-auto-onboarding-progress-20260925.md)。这不等于生产切换、公开发行、真实设备上传或业务权限变更授权；这些操作仍须按当时实际指令明确范围。

产品目标：普通用户完成“安装 → 确认组织及采集范围 → 自动接入 → 查看资产”。注册、心跳、采集器安装和调度由程序处理，不要求普通用户分别执行命令。安全审批仍保留，不能把“自动接入”解释为“自动获得业务权限”。

首个交付范围是已有企业控制面与 Linux 设备，DGX Spark/Linux ARM64 为首验平台，Linux AMD64 为第二验收平台。Mac 浏览器访问远程 Linux 属于必测场景，不等于本阶段支持 macOS 原生企业采集安装。Windows/macOS 原生安装、Kubernetes/云账号全自动接入另列后续范围，不借用交叉编译结果宣称可用。

## 3. 目标体验和安全边界

### 3.1 安装与接入

- 企业端为已认证管理员提供“接入设备”；现有 DGX Spark 环境可直接复用。新环境可由有权限的管理员在安装准备阶段创建，不依赖用户预先理解环境类型。
- 安装入口携带可验证的控制面地址、组织/环境引用和范围说明；凭据不嵌入公共包、URL、命令参数或 shell 历史。一次性凭据经安全交互传入，设备安装后只保留自身最小权限身份。
- 安装程序识别实际执行所在主机，不识别浏览器所在 Mac 为目标设备；容器视角、宿主视角和远程目标明确区分。
- 一次范围确认后自动注册、配置后台服务、持续心跳、领取签名任务、首扫和增量盘点。额外用户目录、Docker/Kubernetes 控制接口、系统级权限另行确认。
- 前端分别显示“已安装、已注册、在线、已盘点、已纳管、保护已核验”；任一步失败或未知都不可合并为“已保护”。

### 3.2 资产与权限

默认导航围绕“资产、权限、安全、审计”，环境、运行时绑定、策略/变更和高级诊断保留可达入口。资产按环境/设备 → 框架实例 → 角色 → Skill 展示；共享、未关联、未启用、不可读和疑似对象单独标记。

权限区分声明、推断、运行观察和后端有效读回；角色/Skill 的权限必须绑定实际执行身份与后端粒度。共享沙箱策略对多个对象生效时必须展示影响范围；无法独立约束单个 Skill 时显示“不支持独立隔离”，不得用 UI 勾选制造不存在的安全边界。

批量治理统一“选择 → 影响预览 → 确认/审批 → 部署 → 逐项核验”。收窄、撤销与扩大权限分开处理；扩大权限保留独立审批。紧急操作沿用已有职责分离规则，不能因批量或管理员账号绕过。

### 3.3 必须保留的安全能力

1. IAM 是租户、用户及权限事实源；设备注册范围由验证身份及注册许可派生，个人浏览器配对不是企业身份。
2. 保留攻击检测、提示注入/凭据外传识别、准入隔离、污点与 Authority/provenance 校验、审批后复验、运行身份、撤权、签名回执和审计。不能为安装方便关闭 required gate、改成宽松模式或放宽既有 fail-closed 行为。
3. 采集不执行 Skill/配置内容，不导入或 eval；秘密正文、提示词和业务结果默认不上报。只上传获准范围内必要的脱敏元数据、摘要、引用与证据。
4. 自动发现不等于纳管，纳管不等于业务授权，策略提交成功不等于后端生效。模型输出不能决定批准或 effective 状态。
5. 不默认授予 root、Docker socket、整盘或其他用户目录访问；不将控制面容器改成 privileged、不默认关闭 AppArmor，也不批量复制宿主 OpenShell 密钥。
6. 既有个人端、运行身份、权限、审计和防护保持独立连续；企业接入采用版本化 API/导出合同，不直接读写个人台账或兄弟仓库数据库。

## 5. 批次顺序与结束条件

1. **M0：基线与合同。** ENT-001、003，启动 ENT-020；确定接口、数据范围与回退方式。只做文案调整不能关闭本批。
2. **M1：安装后自动接入。** ENT-002、004–007、012、017 及对应安全门禁。普通用户不再手工运行三条 Edge 命令，真实设备首扫及页面结果读回通过；本批仍不冒充完整技能治理。
3. **M2：看清环境与资产。** ENT-008–011、013–014 及 ENT-018 资产部分；完成多框架/多角色/技能归属和保护状态的证据限定展示。
4. **M3：管控与追溯。** ENT-015–016、018 剩余部分、019；完成批量变更、独立审批、真实执行约束、逐项结果和审计关联。
5. **M4：可复现交付。** ENT-021–022、ENT-020 最终回归；通过原生安装/升级/恢复及实际部署后才声明完整目标已交付。

后续 P2：macOS/Windows 原生企业安装，Kubernetes/云账号自动接入，更广框架覆盖及规模化设备管理。保留当前已有 Connector，不删除这些能力；但新增自动接入需独立合同、最小权限及原生验收，不作为首轮 Linux 的隐含承诺。

不使用累计测试数或主观百分比作为结束条件。完整目标完成必须同时具有：可信可复现安装包、真实自动接入、证据支持的关系盘点、后端有效权限、行为正负验证、批量审计、原防御不退化及可恢复部署。
