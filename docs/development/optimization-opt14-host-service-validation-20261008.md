# OPT-14 独立扫描服务与真实容器验收

日期：2026-10-08。机器：DGX Spark / Linux arm64。分支：`codex/security-optimization-20261007`。
本批基线：`6412cefd`。源码摘要、镜像与原始日志摘要见

## 结论

OPT-14 的容器部署缺口通过可选独立宿主扫描服务关闭，记为 `done`；总体主任务完成
**11/16（68.75%）**。Docker 内直接创建 bwrap namespace 仍被默认安全配置拒绝，
本批没有解除该限制。采用 [ADR-060](../adr/0060-host-isolated-scan-service.md) 的
非 root 宿主服务与 UID 认证 Unix 通道，逐次运行原有 bwrap worker。

实际容器控制面正常扫描、恶意规则命中、资源失败后的恢复以及服务失联后的失败关闭通过。
这是开发身份与隔离 SQLite 的真实 HTTP/进程/容器集成验收，未宣称生产 OIDC、
PostgreSQL 同次部署、其他 OS 或其他 Docker 安全策略已经验收。

## 改动与安全边界

| 层 | 本批行为 |
| --- | --- |
| 通道 | 新增 scan-service v1 帧；保留 worker v1 JSON，单连接单请求，强制 EOF，无自动重试 |
| 身份 | Linux SO_PEERCRED 双向 UID 核对；宿主服务 1000、容器 API 10001，错误 10002 拒绝 |
| 文件 | socket 0660、目录 0710，客户端只读挂载，拒绝符号链接、权限漂移或不可信所有者 |
| 准入 | 服务默认并发 2（显式 1–8），无应用等待队列；原 API 配额保留 |
| 预算 | 通道绝对期限 8 秒、输入 4 MiB、输出 2 MiB；worker 最多 5 秒/CPU 3 秒/256 MiB |
| 结果 | 控制面继续绑定任务、scope、输入、规则摘要和版本；失败与错配均不写成功事务 |
| 镜像 | 规范打包源码读取权限，保留 root 归属与应用不可写，修复工作区 0600 源文件导致的启动失败 |
| 清理 | 停机等待有界处理器，只删除本服务仍持有的 socket；保留其他主体替换的端点 |

服务不持有控制面数据库、签名或治理凭据，不执行样本。服务所有者与 root 是部署信任主体；
UID 核对不构成程序签名或抵抗管理员的证明。开发 `process` 不具备 OS 隔离，生产继续拒绝。
服务忙/失联保持既有 503 失败语义，API 进程配额仍使用 429。

## 实测与回归

| 验证 | 结果与证据解释 |
| --- | --- |
| 相关 Python 回归 | 187 项通过，无跳过；扫描/配额/配置/规则/威胁/事务/设备证据/独立命中 oracle |
| 最终服务专项 | 35 项通过，其中 33 与上行重叠、2 为补充停机资源验证；本批相关独立用例合计 189，不能相加成 222 |
| 原生 bwrap | 宿主合成私有文件不可见、程序挂载不可写、宿主接收端不可达；不是样本动态执行 |
| 实际 HTTP | 普通和恶意输入 200；恶意规则产生 Finding 与 outbox，扫描审计存在 |
| 内存故障 | 1 MiB Python 重复语句返回 503；Finding/审计/outbox 无新增，资产摘要未半提交，治理健康正常 |
| CPU 故障 | 请求局部病理规则耗尽 worker 预算而失败；同期真实健康 HTTP 在 1 秒测试门限内返回，下一正常扫描成功 |
| 身份与端点 | 实际容器 UID 10002 拒绝；宿主目录改为组可写后 API 拒绝且无成功事务；权限恢复 |
| 服务生命周期 | 服务停止后扫描 503、无成功事务；新服务启动后相同容器恢复正常扫描，无自动重发 |
| Docker 防护 | `docker-default (enforce)`、Seccomp=2、NoNewPrivs=1、cap-drop ALL、rootfs 只读、network none |
| 镜像独立复核 | 八个运行时源码摘要与工作区相同、root 所有且应用不可写；同镜像内直接 bwrap 仍拒绝 |
| 交付工具 | Ruff、Dockerfile 锁文件守卫、Compose 源码与渲染检查通过；配置渲染不冒充实际 Compose 部署 |

真实运行 `003` 汇总为 13 个布尔检查，存在组合与重叠，**不是 13 个独立攻击样本**。
普通/恶意/语法错误三种输入与既有静态分析器对等；这些不是模型攻击成功率测评。
CPU 故障使用请求局部测试规则，不写 API 已安装规则包，未修改共享 Python/Go 规则文件。
失联后的 inode 数值被文件系统复用（原始字段为 false）；重启恢复证明来自服务确已退出、
socket 已移除与随后真实 HTTP 成功，不能把 inode 数值当作跨重启唯一身份。

## 失败记录与修复

1. 最初定向回归出现 1 项断言失败：恶意尾随请求在 Linux 关闭时返回 RST，而测试要求干净 EOF。
   固定拒绝帧已收到、第二个 worker 未启动；修正为明确允许拒绝后的 EOF 或 RST，未放宽成功路径。
2. 实际运行 `001`、`002` 均在容器启动阶段失败，不记通过。`002` 明确保存了
   `operation_registry.py` 的 PermissionError：Docker COPY 保留工作区 0600 权限。
   修复仅规范镜像内打包源码读取权限，不改工作区文件模式、不使应用拥有代码写权限。
3. 镜像重建后 `003` 完整通过。所有轮次自有服务/socket/容器均已清理，旧记录保留。
4. Compose JSON 渲染省略 false 字段，初始检查误将省略视为缺失；同时验证源 YAML 的
   `create_host_path: false` 与渲染无 true 值后通过，未修改隔离配置。

原始材料在 `var/optimization-20261007/opt14-host-service-00{1,2,3}.json`、
`opt14-host-service-image-check.json` 与 `opt14-host-service-logs/`；不提交原始运行目录。
公开摘要保留原始文件 SHA-256、最终镜像及代码身份。前批
[原生 worker 证据](optimization-opt03-opt14-validation-20261007.md)保持冻结，不改写旧通过分母。
