### 6.3 必须有的负向回归

- 策略读回正确但执行平面未加载、加载确认过期或指向别的目标；任务启动计数为零。
- 旧 CLI 不支持等待、加载超时/非法结果、后端失联；不降级为无等待执行，不回退本机 native。
- 等待中撤权、换会话、换 Grant/argv/cwd/目标；批准后更改计划均不能复用批准。
- 并发同任务与不同权限任务，恢复基线超界，预检后基线变化，任务失败后的锁释放。
- 新执行路径不破坏旧策略接口：旧请求的 `task_executed=false` 和无命令副作用保持。

安全修复应先用负例复现旧错误，再验证新行为；不以纯 mock 返回“已加载”作为真实能力证明。

## 7. F02：停止、恢复与对账

### 7.1 先核实能力，再设计实现

阅读 `task_exec.go`、`openshell_task_track.go`、相关 schemas 与驱动。记录实际 CLI/网关版本、官方文档或本机 help/协议、请求/响应字段，核实是否存在**绑定单次执行身份**的状态查询/停止能力。引用上游信息时查阅与实际版本匹配的一手资料；不得仅信代码注释或从版本号推断。

必须区分：

| 事实 | 可以声明 | 不可以声明 |
| --- | --- | --- |
| 本服务在 spawn 前已拒绝 | 本次未启动任务 | 整次操作没有任何策略副作用 |
| 本地 CLI 被停止或连接断开 | 本地观察结束、远端结果未知 | 远端命令已终止 |
| 远端明确确认对应执行结束 | 对该执行的停止/退出事实 | 已撤回停止前的外部副作用 |
| 独立证据确认文件/接收事件 | 对应已观察效果 | 所有潜在副作用均不存在 |

停止响应按现有合同读取 `stop` / `status.stop`，添加字段误读回归。若上游确无所需能力，记录可复核依据，保持 `stop_requested`/`uncertain` 并明确 UI；不得删 sandbox 模拟停止单个任务。

### 7.2 持久状态与安全恢复

- 复用签名追加记录与预留重建投影；不能把可编辑 JSON 成功标志作为事实源。
- 状态转换、能力边界和终态定义先写规格/合同；审批、执行发生与结果可核验性分别建模，不由 HTTP 200 推断任务成功。
- 启动验签失败、缺历史密钥或状态格式不兼容时拒绝写入，不创建新身份掩盖故障。
- 覆盖：预留后；策略提交未确认；加载完成未 spawn；远端已接受但响应丢失；退出结果未持久化；停止已发送未确认。
- daemon 重启后默认只读对账，不自动再次发起未决任务。已消费批准不能因失联/重启被重新释放为可执行。
- 对账绑定操作、预留、任务摘要与管理员身份；保留原事件，新增有证据的结论。管理员点击不能把未知事实强行改成“已证明未执行”。
