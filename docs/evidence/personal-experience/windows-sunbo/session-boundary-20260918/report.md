# Windows 管理会话实例边界原生验证

受测源码 `185a0d6b9c8d6e17e00e169855273d2644c11a0f`，原生二进制 SHA256 见 summary.json。这是 PR #74 的实现候选；不能代表最终集成候选。使用当前用户专用 ACL 保护目录和两个独立状态目录，没有提升权限。

P01-11：分别将全新测试状态配置为其他 HTTP 服务端口、另一 SIQ 状态目录的实际端口。原生 `status`、`pair`、`ui --print` 均退出 1 且 stdout 为空；真实 `start-local.py` 拒绝已占用端口并明确报告未终止任何进程。状态文件逐一摘要前后一致，两个 SIQ 服务仍正常。其他服务只收到探测 GET，没有 Authorization 或 POST。

P01-12：两个真实 SIQ 服务分别通过原生 pair 与实际 `/v1/pair` 建立管理会话。同实例 bearer 访问成功，跨实例 bearer 返回 401。原样转移恢复 Cookie 返回 401；进一步把外来恢复密钥放进目标实例所要求的 Cookie 名称，仍返回 401。各自正确恢复返回 200。凭据仅留控制器内存，不记录响应正文、配对码或 Cookie。

复现步骤：核对构建来源及 SHA256；建立专用私有状态 A/B，在两个空闲回环端口 init/serve；按上述顺序实际配对、正向访问和跨实例负向；启动第三个自有 HTML 响应服务，执行两个错误状态的 CLI 与启动器探测；比较状态摘要；撤销本批管理会话，正常停止两个 SIQ 服务及 HTTP 夹具。r4 完成 20 条 CLI 检查，控制器退出 0，两个服务均正常退出且监听端口关闭，无强杀、无付费模型调用。

历史异常保留：r1 在服务启动前因控制器名称遮蔽失败；r2 的同实例恢复发生一次 WinError10054，原因尚未确认，两个服务仍正常收尾。r3 未复现；r4 增加目标 Cookie 名称负向和严格正向恢复断言后通过。后两轮不抹去 r2 异常，也不能证明异常原因已修复。

本证据覆盖 Windows CLI、启动器与真实 HTTP API 的实例边界；不覆盖浏览器刷新、新标签页、自然认证过期或最终候选全量验收。此次新增 P01-11/12 两项通过，固定台账为 67/303 通过、4 失败、8 受阻、224 未测；3 项系统中断测试按用户要求排除。
