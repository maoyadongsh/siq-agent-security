# Windows Intent 私密授权记录

生产修复 `44813a9`，受测干净源码 `a968d6194e41f4924653b39684a7fa4d8dfd0bcb`（另含旧 Skill 回归结果文档），Windows 产物 SHA256 `4724100e1b74aa16960e7f1b9eb2e9f7a80f7bd05d5d3ebee4aa7692e1bf1d1b`。

## 问题和修复

旧实现只检查签名，没有检查 Windows 记录文件、目录和状态根 ACL。撤销目录变宽或缺失可被当作没有撤销记录，缓存 Store 仍能解析会话授权。原生产 f2ab8a7 仅添加测试/规格，复现4项顶层失败、11个子场景失败，另有独立的缺失撤销目录场景。未把不安全状态解释为外部环境阻塞。

intents、intent-bindings、两类 revocations、context-assertions 的新目录和文件改用显式私密边界；目录枚举检查实际目录句柄，文件读取检查实际普通单链接句柄和大小/身份，先检查状态根及记录父目录。目录缺失/不安全不能降级为记录不存在；安全目录下确实缺失的记录保留原语义。引用的本地 evidence 也经过私密有界读取。不可变发布复用不覆盖的原子移动，保留原签名/摘要/冲突/撤销语义，不改历史合同或Windows资源授权语义。

开发复验还发现新发布逻辑会在同一Intent重试时留下暂存文件。添加存在性预检后由原调用方读回验签，稳定重试不再分配暂存；真实发布失败的未知暂存仍保留，不按名字删除未知对象。该中间缺陷和修复结果均保留。

## 验证

- privatefs/statefs/intent 三包整包：45顶层、87子测试通过，1个符号链接夹具子测试因本机权限跳过。这是最终重试预检前的开发树结果。
- 实际receipt引擎定向回归：4顶层、62子测试通过。Windows ACL变宽通过真实Intent Store触发拒绝，覆盖optional/required及block/warn/audit_only，拒绝回执均有签名且链校验通过；没有用单纯注入错误替代新ACL链路。
- 重试缺陷修复后受影响回归：9顶层、13子测试通过，含私密正负向、不可变重试、上下文并发、绑定并发与撤销。开发树结果没有重标为干净候选整包结果。
- 干净源码fmt空、vet、四平台构建及Python合同Schema全部退出0；每个平台产物内嵌SHA/dirty标记与哈希逐一核对。
- 原生SIQ服务43断言、19次HTTP调用通过：重复签发同签名且不新增暂存；独立.NET核对7类对象ACL；5类权限漂移拒绝且原记录/配置/ACL保持；恢复后Authority再次valid；撤销目录缺失拒绝；显式撤销后继续deny。正常签名stop、服务退出、端口关闭，CLI verify成功。
- 独立Python json/sha256及cryptography Ed25519核验13条回执的内容摘要、连续链接和签名，包含7条invalid-authority deny。只在本机使用合成测试seed派生公钥，不输出或提交seed/凭据；公开材料只含公钥指纹和校验结果。

## 范围与还原

本批验证原生SIQ管理/决策API和实际NTFS状态；未启动真实Hermes/OpenClaw/WorkBuddy、未调用模型，不作为宿主工具执行证据。原生基线证明Authority有效，不声称无Grant的合成会话获准执行工具；实际allow与三模式deny由receipt组件回归分别覆盖。

夹具ACL和临时改名目录均还原；仅专用服务启动并已停止，没有系统重启、默认提权或日常数据修改。合成签名记录和回执保留作证据，详见cleanup-audit.json。run-native-api.py固定源码及产物身份，只在新空专用根运行；read-fixture-acl.ps1只读描述符。

此证据不覆盖runtimecheck/effectevidence等其余私密记录、运行时适配器token缓存、真实第二身份、Windows资源路径授权或最终候选全量回归。FILE-22及Issue #42仍未全部完成。旧6a6e47c的Skill整包结果已单独补齐：105顶层通过、1失败、1跳过；128子通过、1失败、1跳过，退出1（符号链接构造缺权限），没有超时。不得把历史结果合并宣称当前或最终候选整体通过。
