# F06/B04 真实墙钟到期与清理复核

Linux 本机在旧候选二进制 SHA256 `c8048691276590a064b5314837e35c80a2e8fba48471f1bf12c434f6b9ae9853` 上完成两份独立隔离种子的 **seed → 真实等待 → verify**。r2 的过期时间为 2026-09-17 10:32:16 UTC，r3 为 10:35:46 UTC；两次 verify 均在真实到期之后执行，未调系统时钟、未使用 `--skip-wait`。两次命令均退出 0，各 **19/19 检查通过**；脱敏逐项布尔结果和私有原件摘要见 [`verify-summary.json`](verify-summary.json)，总体状态见 [`status.json`](status.json)。

两次均观察到：到期前隔离 daemon 重启并重新配对到同一状态目录；过期的两条记录在 purge 前显示 `expired`，密文文件仍在；24 小时保留腿仍为 `active` 且可解密读取。调用产品 `purge-expired` 后仅两份过期密文与 metadata 被删除，r2/r3 各删 2 条、释放 1700/1702 字节；保留腿的密文、metadata 和可读性不变。状态目录外的 Grant、撤销、回执、活动等文件保持，允许的审计追加必须保留旧字节前缀；导出成功、未知 ID 404、无管理凭据 401 也通过。后者的旧字节前缀校验是本轮对 runner 的强化，负向测试防止把篡改误判为合法追加。

种子第一次尝试因相对 run-dir 与可执行路径组合在 daemon 启动前失败，私有原件保留；修正为绝对路径后 r2 seed 成功，r3 再用相对 run-dir 做独立回归并成功。失败尝试没有被写成通过，也没有计入上述两次 verify。私有 seed、状态、密文、配对与原始 verify JSON 仅在被 Git 忽略的 `expiry-private/`，目录 0700、文件 0600；公开摘要只含检查名称、布尔结果、时间、计数及私有原件 SHA256。公开 `SHA256SUMS` 不收录私有文件。

证据等级为**真实墙钟 + 本机隔离 direct-process daemon + 产品原文 API**。它证明到期清理、存活保留与导出边界；不证明 OpenClaw 宿主在原文 Grant 自然到期之后的新原生调用零捕获，也不证明桌面通知视觉或其他 OS。此腿使用旧候选，不能直接转移为新增沙箱 UUID 绑定候选 `ceddc59c…` 的验收。
