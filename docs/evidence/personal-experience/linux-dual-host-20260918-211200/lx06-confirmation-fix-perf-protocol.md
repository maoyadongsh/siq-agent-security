## B2 doctor 控制面

使用 `openshell-b2b3-perf-protocol.py` 固有 v2 协议与既有预算，不改驱动：三轮、每场景每轮 15 样本、每腿 2 次预热、旧/新交错顺序为 `old,new,new,old`、`new,old,old,new`、`old,new,new,old`；另有 5 次辅助恢复样本。最近邻秩 p95；`doctor_readback` 与 `doctor_unreachable` 绝对 p95 ≤15,000 ms，辅助恢复 ≤60,000 ms；`doctor_readback` 新/旧 p95 比 ≤1.30。旧、新二进制、CLI 和真实沙箱在协议内逐一哈希绑定。任何失败样本使整腿无效，全部原样保留。

B2 只证明 CLI doctor 的真实网关读回及辅助恢复；该驱动输出的 `B3=not_measured` 必须保持原样，不能改名为任务执行或网关拦截验收。

## S1–S4 真实任务执行

使用 `openshell-o05v6-taskexec-perf.py`，第四代与第五代按顺序、各在独立同镜像沙箱和独立输出目录执行。每腿三轮、每场景每轮 2 次未计时预热；S1/S3/S4 每轮 15 样本，S2 每轮 5 样本。第 1/3 轮顺序为 S2 → 未计时就绪调节 → S1 → S3 → S4，第 2 轮为 S2 → 调节 → S3 → S1 → S4。单请求并发；S3 用逐样本唯一 token 的获批只读命令，必须核对真实执行的 stdout 摘要，不能把缓存或重放当成功。

| 场景 | p95 上限 | max 上限 | 证据边界 |
| --- | ---: | ---: | --- |
| S1 doctor 读回 | 15,000 ms | 30,000 ms | 控制面 |
| S2 同内容策略加载并等待 | 60,000 ms | 60,000 ms | 控制面写入与加载 |
| S3 已批任务提交和真实执行 | 2,000 ms | 15,000 ms | 产品执行路由与真实沙箱 |
| S4 已持久执行状态读回 | 1,500 ms | 15,000 ms | daemon 状态投影 |

分位算法为最近邻秩 `ceil(p*n/100)`，全部样本入账；只有协议预先定义的预热不计。失败、超时、拒绝、回执/执行摘要不一致或资源干扰使该腿无效，不剔除样本、不择优重跑。两腿使用同一份冻结协议文本；完成后才可计算逐场景新/旧 p95 比，**S1–S4 无冻结相对预算，比例仅描述，不作合格门槛**。不能把不同候选的历史结果拼入本次对照。
