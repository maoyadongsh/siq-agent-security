## 实际发现与修复

当前主线原始 `client-install` 在可信清单验证后先把程序发布到 `client-releases/`，再调用 `setup`。新状态尚未生成本地签名 seed；暂存文件使签名保护将缺失身份视为历史密钥丢失，首次安装返回 `installation not confirmed`，未注册 unit。隔离运行的初次失败保存在 `lx00-private/b02-console.log`，后续只读 `service-prepare` 返回 `identity_missing_restore_required`；未修改共享服务。

修复在可信清单与源二进制校验之后、暂存发布之前建立或读取**持久**签名身份。无效发行不创建身份，已有历史却缺失原密钥仍拒绝。后台安装拒绝仅存在于调用进程环境中的临时签名 seed，避免 systemd 启动后的身份漂移。实现同时更新 `docs/agentshield-dev-spec-v1.md`，加入验证顺序、拒绝场景及跨重启要求。

旧程序已留下的“暂存文件存在但签名 seed 缺失”状态不会被本修复自动清空或重建身份；它仍需核实归属后按受信备份/恢复流程处理。本批清理的只是本批新建的隔离失败 fixture，不代表用户历史目录可以直接删除。

最小 Go 测试验证了可信校验 → 身份准备 → 暂存的顺序、无效发行零落盘、历史身份丢失 fail-closed、临时 seed 被拒。`go vet ./...`、`go test ./...`、安装相关 `go test -race` 在修复后均退出 0；Linux amd64/arm64、macOS arm64、Windows amd64 的 CGO=0 构建也通过，摘要见 `cross-builds.json`。交叉构建不代替另外两个 OS 的实机验收。修复前的全量 Go 回归也通过，说明原缺陷此前未被组件测试检出。
