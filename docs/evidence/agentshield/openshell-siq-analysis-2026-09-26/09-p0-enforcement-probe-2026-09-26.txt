§0 这份留痕的边界（先读）
--------------------------------------------------------------------------------
本文件回答一个问题：**「`enforcement_verified` 这个级别，能不能只由边界内的真实
行为观测产生，而不是由任何夹具的自述产生」**——以及这个性质能否被测试**否证**。

- 本轮的结论档是 **隔离验证通过**，不是「实际交付」。工具**从未**在真实目标上运行过；
  全程**未**联系任何网关、**未**执行 `sandbox upload` / `sandbox exec` / `policy set`、
  **未**新建或删除沙箱、**未**读写任何真实策略。
- 唯一的真实 IO 是两个本机 127.0.0.1 回环套接字（一个监听、一个已关闭端口），
  用于让"可达性对照"与"探针形态词表"成为**实测**而不是声明。
- 本轮**不产生**任何 `enforcement_verified` 事实：所有证据都是合成的；
  校验器接受它们，只说明**判定逻辑正确**，不说明任何真实策略在拦人。
- 未接线：没有任何门禁/接口调用新通道；`verify(probe_evidence=...)` 的调用方仍为 0。

§2 三条设计不变量（逐条落成可测事实）
--------------------------------------------------------------------------------
1. **观测必须在边界内发起**：`ALLOWED_PROBE_ORIGINS = {sandbox_exec}`，且是
   **拒绝式**白名单——不在集合内的一切原点（`fixture` / `simulated` / `self_report` /
   `script_self_report` / `config_readback` / `gateway_self_report`）逐个点名拒绝。
2. **判定不在夹具里**：边界内探针只报告形态与耗时；`self_report` 形态一律拒绝。
   探针**没有**"预期"输入（实测：`--expect blocked` 直接报错退出）。
3. **不确定就不升级**：三臂不齐、臂内形态矛盾、绑定不匹配、读回**明确**说
   warn/audit_only —— 全部落到固定判别码，绝不产生该级别。

§3 差分结构（主方案 = 同 endpoint / 双 binary 路径 / 同一份内容）
--------------------------------------------------------------------------------
  允许臂（边界内，路径 A）→ 必须 `connected`
  拒绝臂（边界内，路径 B，**同一个** endpoint）→ 必须是"被拦"形态
  可达性对照（**边界外**，控制面主机）→ 必须 `connected`
A 与 B 是**同一份脚本**的两个副本（摘要相同），因此唯一变量是策略按 binary 路径的归因。
"被拦"必须是签名而非"没连上"：`timeout` 形态**不能单独成立**（也可能是路由黑洞），
只有该 endpoint 在同一 run 内被对照臂证明是活的才接受。

覆盖到的**否证**，逐条为可执行断言（不是声明）：
  - 六个非法原点逐个拒绝；对照臂必须来自边界外；
  - 指纹 / revision / digest / 探针脚本摘要 逐项绑定不符即拒绝；

§6 实施期自纠的三个缺陷（都写出来，不藏）
--------------------------------------------------------------------------------
(a) **纸面门禁（最严重）**：初稿要求"读回的执行模式必须是 block"，否则不升级。
    但 CLI 路径的 `read_effective_policy` 刻意恒填 `unknown`（`cli_backend.py:542-544`，
    P1-11：`policy get --full` 输出里根本没有模式字段）——这道门在**真实路径上永远打不开**。
    改为**矛盾时从严**：只在读回**明确**为 `warn`/`audit_only` 时拒绝；`unknown` 不作为
    否决理由（边界内拒绝臂真的被拦住，是比读回更强的直接事实），并在证据里如实保留。
(b) **计划与实际分叉**：计划模式打印的 `exec` 写死 `--timeout 0`，而通道实际发的是
    `int(timeout*attempts)+60`。已改为复用通道的 argv 构建器（单一事实源），
    并新增"计划 argv 逐字等于 dispatch argv"的断言。
(c) **拒绝路径上的多余动作**：工具原先先 `upload` 再校验允许规则，导致拒绝时已发生
    两次跨边界写入。已把全部只读前提（握手/指纹/读回/允许集）前置，
    拒绝路径上**一个跨边界动作都不发生**（测试断言 dispatch 表为空）。
