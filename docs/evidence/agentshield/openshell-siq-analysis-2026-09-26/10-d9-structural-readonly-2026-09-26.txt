§1 结构性结论（本文件的主要答案）
--------------------------------------------------------------------------------
**网关的网络策略模型把「允许哪些二进制」作为规则的**必填一等字段**，而且目标自身的
策略**正在使用**它。** 这不是"我们写进去它才回显"，而是既有载荷里本来就有。

两个 canary 的 `--full` 载荷结构**逐项相同**：

  顶层段：version / filesystem_policy / landlock / process / network_policies
  network_policies 下的规则**只有三个键**：`name` / `endpoints` / `binaries`
    （endpoint 内为 `host` / `port`）

  ┌──────────────────────────┬───────────┬──────────┐
  │ 规则条目                  │ endpoints │ binaries │  二进制路径
  ├──────────────────────────┼───────────┼──────────┼───────────────────────────────
  │ siq_agentshield_relay    │     1     │    1     │ /opt/siq/hermes/venv/bin/python
  │ siq_data_broker          │     1     │    1     │ /opt/siq/hermes/venv/bin/python
  │ siq_egress_guard         │     1     │    **4** │ /opt/siq/hermes/venv/bin/python
  │                          │           │          │ /usr/bin/curl
  │                          │           │          │ /usr/bin/git
  │                          │           │          │ /usr/local/node/bin/node
  │ siq_internal_services    │     4     │    1     │ /opt/siq/hermes/venv/bin/python
  └──────────────────────────┴───────────┴──────────┴───────────────────────────────
  合计：规则 4 条 / endpoints 7 个 / binaries 7 条；**缺 binaries 的规则：0 条**。

三条要点：
  ① **必填性**：4/4 条规则都带 `binaries`，无一条缺省。结合本仓适配器
     `policy_safety.gateway_network_to_rules`（`policy_safety.py:217`：`binaries` 为空即
     `openshell_gateway_network_unsupported`）与 R09.15 实测该读回**解析成功**（§4），
     可交叉确认：**这个网关的每一条网络规则都绑定到具体二进制路径**。
  ② **粒度**：`siq_egress_guard` 一条规则同时列了 4 个二进制（python / curl / git / node），
     而 `siq_internal_services` 一条规则覆盖 4 个 endpoint、只列 1 个二进制 ——
     两个维度（endpoint 集合 × binary 集合）是**独立的**，这正是"按 binary 归因"的形态。
     若网关不按 binary 区分，这两条规则的写法没有意义。
  ③ **后果**：行为 fixture P0 的**主方案**（同一 endpoint、同一份内容、两个不同 binary 路径
     的副本，看是否一个通、一个被拦）**在结构上是有意义的**——它测的正是这个模型被声明
     出来要多做的事。**P0 的方案不是因为"模型根本不支持"而作废的那一类。**

§2 仍然**没有**回答的部分（本文件最重要的限度）
--------------------------------------------------------------------------------
**"schema 里有、且被使用" ≠ "运行期真的按它判定"。** 本次拿到的是**声明面**。
决定性的一步是**执行面**：某个 binary 真的去连那个 endpoint 时，网关是否**按 binary**
放行/拒绝。本次**没有**任何执行面证据。

而且：本候选上**唯一可能承载执行面证据的只读通道被已知缺陷封死了。**

§3 只读通道的实际可达性（两条硬结果）
--------------------------------------------------------------------------------
（a）`logs` —— **不可用**，被冻结的既有缺陷挡住：
    $ openshell logs siq-analysis-canary-27d1289f98fa -n 200 --source gateway
    rc=1，370 字节，全部是错误：
      Error: status: Internal, message: "failed to decode Protobuf message: Sandbox.id:
      SandboxResponse.sandbox: invalid string value: data is not UTF-8 encoded"
    → 与兼容矩阵里 `sandbox_list_decodable: 期望 False / 实际 False` 是**同一条**缺陷，
      并已由 `06-` §四在 `sandbox get` 上复现过。也就是说：**这个网关版本上，
      "查运行期日志/沙箱状态"这条只读路是不通的**，在它修好之前，
      执行面证据**只能**靠行为探针（upload/exec）产生。
      另注：`logs` 的客户端退出码映射本身也不可靠——同一命令在通过管道读取时出现过
      `rc=0`（错误正文照旧），故**不得**以退出码单独判定"读到了日志"。本文件没有
      取得任何日志正文。

（b）`policy get --global --full` —— **不存在全局策略修订**：
    rc=1，`NotFound: "no global policy revision found"`。
    → 该网关未设全局策略锁（与 `policy delete --global` 的语义对应）；
      故"全局层是否另有按 binary 的规则"这个问题在本候选上**不适用**，
      策略面**只有沙箱级**，已由 (a) 之外的两份 `--full` 完整覆盖。
