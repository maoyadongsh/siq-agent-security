## 6. D01：先设计执行合同与状态机

### 6.1 可复用的实际代码入口

| 功能 | 当前路径 |
|---|---|
| Go 后端客户端/政策写入/有界子进程 | `apps/agentshield/internal/openshell/{client,command,bounded_command,policy,policy_state,identity}.go` |
| 现有策略操作 HTTP | `apps/agentshield/internal/server/openshell_session_{exec,binding}.go`、`openshell_http.go`、`server.go` |
| 决策、预留、写前重验与对账 | `internal/receipt/hold_execution.go`、`hold_execution_recheck.go`、`hold_reconciliation.go` |
| 运行身份、会话、Skill 归属 | `internal/runtimeidentity/`、`internal/skillcontext/`，以及既有 Authority/Intent 实现 |
| 结果与追踪 | `internal/effectevidence/`、`internal/server/task_activity*.go`，先搜索实际入口 |
| 前端 | `apps/web/src/local/{api,types,confirmations,taskActivities,staleGuard}.ts*`、`local/pages/` |

当前 `/v1/openshell/session-executions` 路由名字像任务执行，实际只应用策略。**不得静默改变该 v1 请求的副作用**：保留旧路由语义，或按版本化兼容迁移；真正执行采用独立版本/操作种类，调用方必须显式选择并批准。路线先写入新规格与 `packages/contracts/`，增加请求/响应 schema 和样例。新文件名和路由由实际设计决定，以下需求是约束而非虚构现有 API。

### 6.2 必须明确的设计决策

- 身份绑定：平台/实例/agent/session/task、后端指纹、sandbox target、当前签名 Grant digest、策略修订、命令参数摘要、审批和预留共同构成操作身份。来源必须来自可验签的服务端记录。
- 初版不扩展任意 target 映射：沿用当前可信约束；需要异名映射时，先增加持久可验证绑定及拒绝用例，不能让客户端自行声明归属。
- 不复用 `siq-openshell-policy-apply` 的批准来执行命令。网络授权列表是资源描述，既不是命令授权也不是后端协议；必须分别验证命令、参数、工作目录、网络目标及文件权限。
- 命令传递优先为 argv 数组；固定 CLI 操作，拒绝选项注入，使用后端支持的参数终止符。不把调用方字符串拼接进宿主 shell；如沙箱内部需要解释器，解释器和脚本本身必须纳入授权、摘要及受限权限。
- 不创建第二套权限来源；预览/管理员登录/模型输出均不能生成执行授权。先确定新请求如何兼容现有 Authority、SEC、Intent 和 Grant 解析，不绕过其 required 规则。
- 正式定义准备、待确认、已预留、策略加载、运行、成功、失败、停止待确认、结果不确定等状态和允许转移。单独记录政策副作用与任务副作用，不能因为任务未启动就断言整次操作无副作用。
- no_op 和配置读回不等于已加载或行为受控。若新任务走 no_op 路径，仍须取得适用于该修订的加载确认；不能用固定 sleep 或一次旧 readback 代替执行前置条件。
- 锁定策略与任务的并发关系。不得在任务运行中由另一个本进程操作扩大同一 target 权限；跨进程/后端缺少原子能力的窗口必须明确威胁边界和可检测条件，不宣称全局原子 CAS。
- 停止请求必须绑定任务操作身份，不能仅凭 PID 或 sandbox 名。核实 CLI/后端是否能确认远端任务停止；杀掉本地 CLI 不等于沙箱进程停止。
- 断连、daemon 重启和未知执行结果的恢复规则；哪个状态可以证明“未发生”、何时只能 uncertain、哪些动作必须重新批准；恢复默认只读对账，绝不自动重放旧操作。
- 输出上限、超时、退出码、脱敏摘要、原文按任务 opt-in、保留期限；不得让 stdout/stderr 原文默认进入普通审计或 UI。

D01 完成必须落盘状态转移表、错误码/HTTP 映射、权限矩阵、崩溃点表、兼容说明和威胁边界。若后端缺少远端停止或执行身份能力，应记录具体限制并设计可实现的保守状态；不能虚构接口，但可继续其他可验证部分。

## 7. D02：真实执行器与批准绑定

执行顺序应保持以下不变量，具体实现复用现有包：

1. 严格校验请求形状和大小，服务端重建最终计划；核对会话、SEC/Authority（合同要求时）、唯一当前 Grant、命令与资源范围。
2. 将最终参数、目标和策略摘要绑定到人工批准的决策；差异需要新确认，不能审批 A 后执行 B。
3. 外部副作用前追加持久预留；并发重复请求只能一个进入执行，不使用仅内存的去重标记。
4. 应用所需策略并等待确认，保留修订/摘要校验；预留后、实际发起任务前再次检查当前授权与会话。加载等待期间撤权/会话失效不得继续启动。
5. 策略已经改变但任务未发起时，记录分阶段事实；恢复策略也要重验权限及漂移，不能强制覆盖外部变更。
6. 通过真实后端执行有界任务；拒绝在 required 后端断连时回退到本机 native。
7. 根据可验证的执行回执、退出结果和独立效果记录返回状态。持久化失败、传输中断或结果未知都不能报成功，也不能自动重试。

验收：一个真实无付费模型调用的安全 canary 任务可被批准执行，参数漂移/未批准/撤权/后端不可达均阻断；源码不再只由测试 helper 调用后端任务执行。真实驱动与测试必须共享生产执行器，不得另写一条测试专用绕过路径。

## 8. D03：持久追踪、停止、恢复与对账

当前 `osExecBindings` 和政策操作 registry 是进程内状态，不能直接支持新任务的跨重启恢复。优先扩展既有签名回执链/状态仓库：追加事件，签名绑定，启动时验签重建只读投影；禁止另建可修改的成功标志作为事实源。

至少覆盖下列故障注入点：预留后未发起；策略提交后未确认；加载完成但任务未发起；后端已接受任务但响应丢失；任务结束但结果未落盘；停止已发出但无法读回。恢复后不得重复执行，不能把不确定状态改为“从未执行”。

停止语义分清停止请求、远端停止确认、退出结果和可能发生的副作用；不能删除沙箱来冒充停止单个任务。无法确认时保留 stopping/uncertain，提供管理员证据对账入口和可理解的提示。

对账必须绑定 operation/reservation/hash 与当前管理员身份，保留原始记录；仅对有证据支持的事实结案。对账后旧批准不可重新消费，另一次运行要重新取得有效权限和预留。外部策略漂移下拒绝自动回滚。

## 11. D06：性能协议与最终候选

- 先确定最终代码与 embed，构建一个全新唯一候选；rc.6 为历史基线，不覆盖。记录 commit、dirty 源清单/摘要、工具链、编译参数、二进制 SHA、后端与宿主版本。
- 现有 `openshell-b2b3-perf-protocol.py` 的 doctor 对照和 auxiliary control-plane restore **不包含真正任务 B3**。扩展驱动时增加独立 scope，不能改名假装既有测试已经覆盖。
- 参考已有 O00/O04 协议：先冻结配置、基线选择、场景、样本数/预热/轮次/次序、并发、最近邻秩百分位、预算与失败处理规则，再运行；每轮保存全部原始样本。
- 固定等工作量才做相对对比；旧候选没有任务执行能力时，该场景相对值为 not_comparable，不能以旧策略操作对比新任务运行计算提速。
- 不预设一个未经依据的“全通过”预算。旧等价场景沿用已有预算；新场景在首次测量前依据现有操作超时、等待上限和用户等待目标说明预算理由并冻结。测后不得放宽，必要修改另立协议版本并保留原失败。
- 分别统计客户端/API、策略加载、远端执行、记录结果及用户可见总耗时。p50/p95/p99/max、失败率、CPU、RSS、进程/请求/写入计数按可观测能力填写；不可得用 null + 原因。
- 禁止为性能缓存旧权限、取消写前复核、降低 fsync/签名/等待/日志保护，或通过重跑选优掩盖回退。
- 测量结果不佳时先定位属于产品开销、后端等待还是环境干扰；修改源码后生成新候选和新结果，不覆盖原报告。
