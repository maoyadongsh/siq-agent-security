## 2. 产品目标、架构选择与本轮范围

**保留两个交付面。** 个人端保留离线可用的 Go 单文件和本地文件态；企业端保留 FastAPI/PostgreSQL、Edge 和 Web 治理。二者经版本化 API/事件/导出连接，不跨仓导入实现、不直连兄弟仓库数据库，也不为本轮加固新增一套微服务或强制云依赖。

**明确两种本地信任配置。** 默认桌面模式防御不可信 Skill 内容、错误权限及跨身份误调用，但必须公开同 UID 自动化可访问其可读文件的边界。若交付“被注入的 Agent 也不能自批或卸载门禁”，推荐新增受管配置：管理身份与 Agent 执行身份通过 OS 权限/隔离挂载分离，审批凭据和私钥对 Agent 不可读。首个参考实现限定 Linux；macOS/Windows 继续按实测能力标示，跨平台强管理隔离属于后续扩展，不用 TTY 或第二个同 UID token 替代。

**能力等级和证明强度分别表达。** L0 盘点/审计、L1 安装门禁、L2 运行时决策/回执、L3 现有执行后端策略应用遵循 ADR-011。L3 的配置读回不等于实际网络行为已被验证。页面与导出同时记录后端、绑定对象、策略摘要/版本、验证方法、时间及失效条件；过期或不可读回就显示 unknown/stale。

**检测服务于最小权限。** 出网、sudo、写文件和工具调用首先形成 declared 能力事实；只有符合恶意欺骗、指令注入、凭据外传或完整性失败等规则才 quarantine。共享规则与证据语义要对等；不同产品策略采用明确 profile，不强行让所有判定完全相同。

**本轮不新增的产品扩张。** 不重写 OpenShell、不自研通用沙箱、不扩大到所有 Agent 平台、不引入模型自动审批、不为了规则数量重构整套检测器。先证明已有 OpenClaw/Hermes/CodeBuddy 路径，再按支持矩阵扩展。

## 4. 可直接拆成开发切片的任务说明

<a id="dev01"></a>
### DEV01｜历史任务签名材料与信任撤销

**来源：S1。目标：证明暴露过的历史材料不再授权任何在役任务。** 已确认的是历史路径可达；现役部署信任未知。不要在日志或工单复制私钥，也不要把它与发布签名、Edge 身份签名混为一谈。

由安全负责人先建立“用途—公钥指纹—签名端—信任消费者—生效/撤销时间—证据”台账，覆盖在役、离线和待重新注册的 Edge。用受控流程比对公开指纹；若历史 key 仍被信任，生成新任务签名身份，更新受信分发并撤销旧根。不能通过仅由已暴露旧 key 签署的新根公告建立新信任；需要已认证管理/注册通道或带外确认。无法联系的设备暂停任务信任或要求安全重新注册，不能无限保留兼容。

**验收：** 台账中所有在役设备都有新信任证据或明确隔离状态；旧 key 签名的合成任务被拒，新 key 合成任务通过；停用旧根后离线恢复不会重新接受它。若证明历史 key 从未用于当前设备，也必须记录可复核证据，不能只写“应该已轮换”。

**处置边界：** 本任务文档不执行生产撤销、对外通知或 Git 历史重写。历史清理单独形成可审阅操作单，列出备份、受影响引用/克隆和执行授权；它不是安全关闭的替代条件。先撤销/更新信任再考虑清理的顺序参考 [GitHub 官方处置说明](https://docs.github.com/en/code-security/tutorials/remediate-leaked-secrets/remediating-a-leaked-secret)。

<a id="dev02"></a>
### DEV02｜本地 HTTP、凭据分权与高影响审批

**来源：R02、S2a、S2b。位置：** [server.go](../apps/agentshield/internal/server/server.go)、[grant CLI](../apps/agentshield/cmd/agentshield/grant.go)、本地 Web bootstrap。

先关闭无认证 `/ui-config.json` 返回管理 token 的路径，替换为不含 secret 的配置响应。Host 严格解析后只接受配置中的 loopback 地址/名称和端口；对浏览器写操作校验 Origin/CSRF，拒绝无效/异常来源。Fetch Metadata 仅作辅助，不替代身份认证；明确非浏览器 CLI 的合法请求方式。

将 decision/observe 能力与 approve/revoke/config-downgrade/adapter-uninstall/export 等管理能力按端点分开。桌面 UI 采用有尝试预算、短时、单次的可信启动配对，再建立有期限的管理会话；凭据不放 localStorage、URL、日志或无认证配置接口。配对只解决初始化，管理请求仍要逐次校验权限；多用户同机不得凭 loopback 获得他人的管理会话。

高影响批准证明绑定 grant 摘要、主体、工具/资源范围、expected revision、随机挑战、到期和单次消费；正文变更必须重新批准。受管配置将管理身份/私钥放到 Agent 无权访问的 OS/服务边界中。普通桌面 same-UID 模式只能诚实表达人工声明，不宣称防止同 UID Agent 直接 CLI 自批。TTY/ModeCharDevice、一次性码或新文件 token 单独都不构成这一强边界。设计方向参见 [OWASP 高影响操作完整性](https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html#high-impact-action-integrity-controls)。

**验收：** 未认证 GET/HEAD 不能取管理凭据；决策凭据调用全部管理端点被拒；坏 Host/Origin、跨站写、过期/重放/参数替换批准均拒绝且无状态副作用。用隔离的多 OS 用户/执行身份验证受管凭据不可读。S2b 在第一迭代记录实际浏览器版本、权限设置、DNS 条件与结果；不能用一个 HTTP 单测冒充完整浏览器攻击验证。

<a id="dev03"></a>
### DEV03｜本地状态提交、回执与一次性决议

**来源：R01、R09、M-G3、M-G4a、M-G4b；原报告 stale lock。位置：** [state](../apps/agentshield/internal/state/)、[receipt](../apps/agentshield/internal/receipt/)、server 管理路由和 CLI。

落实 daemon 单写者，CLI 优先经认证管理 API 提交；保留离线操作时必须取得同一写入所有权。O_EXCL 冲突不能返回成功，幂等必须比较同一操作 ID 与内容摘要；版本变化用 expected revision 作 CAS，旧状态请求显式冲突。先交付最小“不丢写、不伪成功”切片，再完善跨文件提交协议。

设计标准库可实现的持久化提交记录：状态文档/审计准备、写入与 Sync、提交标记、恢复重放和投影可见性。暂存文件不能被普通读者当成生效版本。明确每种文件系统的 rename/durability 保证；多个 JSON 文件不因分别原子 rename 就自动构成事务。只有持久化状态与必要审计都完成，才能返回成功；磁盘满、签名失败和审计失败均受控失败。

Chain 的 append、head/seq 与读取快照采用同一同步边界；读者不读取正在追加的半条记录。hold 建立 pending/resolved/expired 与版本条件，同一决议幂等返回，相反决议冲突，过期拒绝。grantAction 遇任何 JSON 校验错误立即终止，拒绝未知/不支持字段按合同执行。锁恢复要校验实例身份与所有权，覆盖 PID 重用，禁止无条件删除 serve.lock。

**验收：** 原 100 写入实验变成“全部独立持久化或明确冲突”，每个成功响应可查到相符内容；多进程批准/吊销交错、掉电阶段、部分行、磁盘满、崩溃后双实例启动均不产生伪成功。race 检查通过。重复 hold/相反 hold、部分可解码的坏 JSON 不能新增未授权决议。

<a id="dev04"></a>
### DEV04｜可信发布、Skill 完整性与一致安装入口

**来源：H1、H2、H3、M-D4。位置：** [skillmanifest](../apps/agentshield/internal/skillmanifest/)、[release CLI](../apps/agentshield/cmd/agentshield/release.go)、[Skill scripts](../skills/siq-agent-security/scripts/)。

区分“数学签名正确”与“发行者可信”：Go 发布验签以受信 key allowlist/明确发行身份为准，`signed_by` 只能选择已信任身份，不能自行授予信任。允许本地测试 signer 时走显式开发模式，结果不能标成官方发布已验证。建立任务签名、发布签名、规则包和本地身份四类用途与轮换边界。

发布默认要求匹配当前 OS/arch 的清单和摘要；源码开发允许本地覆盖，但必须显式选择并显示未获发布验证。bootstrap 与 adapter 共用验证路径，校验将要执行的精确对象。Python bootstrap 补与 Go HashSkillDir 等价的内容验证；Go 已有比较必须保留。不得调用未经验证的目标二进制来“证明它自己可信”。私有 staging 副本应在复制后重新验证，并按 threat model 保证验证到执行期间不可由低信任主体改写。

明确清单未知字段、重复字段、格式版本和签名输入规则，与 DEV09 一起冻结；根轮换走受信分发。规则包保留当前“不低于内置版本”的真实语义，修正文档；若增加最高已接受版本/防回滚，是单独版本化策略，不把合法同版本重复安装误当攻击。

**验收：** 自签陌生 root、正确签名但内容被改、错架构、缺制品、错误摘要、未知格式均失败；真实发布向量通过。bootstrap/adapter/Go/Python 判断一致且不执行未获允许制品。正常源码开发可用，但 UI/日志诚实标注。验证器/公钥分发的信任起点必须在发布 runbook 中可追溯。

<a id="dev05"></a>
### DEV05｜扫描器特殊文件与枚举预算

**来源：M-G1a、M-G1b、M-E4。位置：** [admission](../apps/agentshield/internal/admission/)、[directory Connector](../connectors/directory/directory.go)。

用 filepath.Ext 等有定义的操作替代负索引切片，保留无扩展名能力判断。打开前拒绝 symlink/FIFO/socket/device 等非普通文件；打开后再次验证文件类型与范围并使用有界读取，处理检查后替换。只做 Lstat 然后无约束 ReadFile 不足以证明完整路径安全。与只用标准库和跨平台约束冲突的 race-free 文件访问方案，先立 ADR 明确支持保证。

### DEV16｜快照、会话与运行指标

**来源：M-G6a、M-G6b；原报告 snapshot IO/静默错误。位置：** [ledger_http.go](../apps/agentshield/internal/server/ledger_http.go)、inventory/ledger、receipt engine、Web 查询。

将 GET 读投影与 inventory/lifecycle 写入分开：后台按变更/受控 refresh 构建有 revision、生成时间与健康状态的快照；读取按版本/游标分页，不每次重算全量历史。损坏、扫描未完成和刷新错误显式传播，旧快照可读但标陈旧。导出采用流式/分段与总量预算，不能把内存切片上限当磁盘读取上限。

sessions 定义容量、生命周期与过期持久状态；污点信息按安全合同保留。容量不足时拒绝新决策或要求新受控会话，不能 LRU 删除污点后把同一 session 当“干净”。配置预算要有范围和可观测拒绝计数。

优先采集 decision 延迟、写入失败/冲突、扫描耗时/截断数、最旧任务年龄、uploaded 滞留、JWKS 刷新与验签失败、outbox 积压、最后有效读回时间、快照年龄和 session 数量。日志只含 ID/类别/摘要，不记录正文与 secret。

**验收：** 在记录硬件/版本的环境用 1 万/10 万回执、1 千/1 万资产和并发查询建立 p50/p95/p99、RSS 与 IO 基线。第一轮确定可实现阈值写入配置/性能合同，后续版本在相同数据与硬件下比较；不预填未经测量的毫秒保证。读取延迟不随完整历史线性重扫，取消释放资源，坏文件不变成空集成功。

### DEV17｜可复现构建、供应链与发布结果

**来源：M-P3、M-P5e、M-C1a—b、M-C2、M-C3a—b；原报告 CI 建议。位置：** [Control API Dockerfile](../apps/control-api/Dockerfile)、[workflows](../.github/workflows/)、[nginx](../apps/web/nginx.conf)、site 和 release scripts。

镜像使用受检 uv.lock；建议固定 uv 工具链与基础镜像 digest，用 `uv sync --locked --no-dev` 或已验证导出锁+安装方式，区分构建/运行阶段。Node 使用 npm ci；二进制、UI、manifest 关联源码 commit 和构建参数。先重建本地 UI 并检查 embedded 摘要，再编 Go，不能只构建企业入口。

Actions 固定完整 SHA 并记录来源版本，按 job 最小权限，设项目级合理 timeout。OpenShell 工具下载指定版本/摘要/允许来源，workflow 输入经 env/参数传递与校验，避免直接插入 shell；运行自定义路径只在受信手动任务中开放。Mermaid 优先固定自托管资源，避免动态外部脚本成为发布时变化项。

保留现有 secret scanning，补历史任务签名材料复发用例和敏感制品策略。不能把 gitignore 当 secret 防线，也不能未经评估把所有 .seed/所有 secrets 路径中的公开测试数据禁掉。增加 Go 漏洞可达性检查、依赖审核、race 和关键负向用例；锁定工具版本并记录数据库时间。检查不可用标“未执行/失败”并按发布门槛阻断，不能变绿。

企业入口按真实 TLS/代理拓扑落实 CSP、frame 限制、nosniff、Referrer-Policy 等；HSTS 仅按 HTTPS 交付要求设置，本地 HTTP 与开发 Compose 不照搬。产出 SBOM/构建来源证明以及源码—依赖—UI—二进制—manifest 对应关系，不把附加证明文件等同于已经可信，消费端需验证身份与摘要。

**验收：** 清洁环境按同一锁可重复确定依赖；本地 UI 漂移、未知制品 hash、secret fixture、依赖扫描不可用、必要 OpenShell 实测缺环境均不出现“所有门禁通过”。执行合理权限的 CI job 验证，发布包可离线校验其签名与对应元数据。单纯新增 govulncheck 不代表 CVE 清零。

### DEV18｜威胁模型、真实能力矩阵与交付 runbook

**来源：M-T1、原报告深扫/生产验证缺口、R02/R07 的产品承诺。位置：** [threat-model.md](threat-model.md)、ADR、本地规格、README、支持矩阵、release-check 和部署文档。

统一威胁模型：远程网页/网络客户端、同机其他 UID、同 UID Agent、恶意 Skill/配置、受损 Connector、企业低权限用户、可信管理员、控制面/发布 key 分别拥有何种能力。逐条写出资产、入口、边界、控制、证明、残余风险与交付 profile；已有 SECURITY.md 缺口可通过正式安全政策任务补齐，但必须与实际维护能力一致。

建立每个 OS×平台×后端版本的能力矩阵。编译成功只算制品可构建；hook 运行、安装阻断、运行时拒绝、配置读回和实际网络阻断分别有证据。OpenClaw/Hermes 优先，CodeBuddy 后续；无 hook 平台只标审计。L3 复用现有 OpenShell 接口，在隔离环境按 policy hash/revision 验证 DNS/IP、重定向、IPv6、允许/拒绝出网、后端失联、替代进程路径；仅通过配置读取不能声称网络强制已经通过。

企业生产 runbook 包含受控入口/TLS、OIDC、Secret 注入、PostgreSQL 迁移/备份恢复、设备注册/吊销、任务/worker 运维、证书轮换、监控报警和事故处置。集成 SIQ 时遵循 Platform/Gateway 所有权，只经版本化合同，不改兄弟仓代码/数据库来绕过本仓缺陷。

**验收：** 每条对外能力承诺可回链到版本、环境和正负测试；未测能力明确标 unsupported/unverified，不能以跳过计通过。在具备托管只读 worker 权限前提的环境完成独立安全扫描与修复验证；当前深扫未启动的缺口在取得真实产物前持续保留。对高风险修复作独立对抗复核，不以本文或 Kimi 的肯定语气代替证据。

## 6. 合同、数据与密钥迁移方案

| 变更面 | 迁移步骤 | 兼容/回退边界 |
| --- | --- | --- |
| 本地凭据分权 | 先定义端点权限，发布支持新 decision/admin 会话的服务/适配器/UI，再轮换旧单一 token；旧凭据撤销时间有上限 | 不能为兼容保留无认证 ui-config 或给 decision token 管理权；版本不兼容时 block 明确拒绝并提示升级 |
| 文件态单写者 | 只读检查旧目录、生成受控备份和 manifest；建立提交记录/版本索引；验证后切换写者 | 迁移不改写已签文档；旧 CLI 不得绕过新写者；退出时只停止新写入并从可验证快照恢复，不删除审计 |
| 签名/Schema v2 | 固定测试向量→先双读消费者→新生产者写 v2→观察 v1 剩余→有期限退休 | 历史 v1 按原始字节/算法验证；不得把旧 grant 的批准自动迁成新范围批准。坏签名不降级到无验签解析 |
| 已暴露任务 root | 经未受损的认证通道下发新信任；撤销旧根；未更新设备隔离/重新注册 | 不提供无限双信任；不能为了回滚恢复暴露 root；密钥处理与普通格式兼容分开 |
| PostgreSQL 状态字段 | expand 添加正交字段/索引，读旧写新并收集差异，依据可信历史回填，消费者切换后 contract | 在真实 PG 演练旧数据升级与备份恢复；缺失原终态标 unknown/人工核对，不猜测；旧程序不理解新状态时拒绝混跑 |
| 事件 null 引用 | 统计受影响事件和可恢复关联；基于事务/对象证据追加修正事件与映射 | 不覆盖原审计、不把相关时间接近当同一对象；不可恢复记录保留原因和影响 |
| receipt/checkpoint/export | 保留原链；新检查点和派生导出各用明确 schema、用途与来源摘要 | 校验历史前缀与完整性分开；派生脱敏文档不能复用原数据签名来宣称等同原件 |
| 规则/模式 | 同版本重试维持现合同；新最高版本/新 disposition 经版本化和正负语料发布 | 禁止用回滚配置悄悄将 block 变 warn；有意政策变更经独立批准 |

每个涉及状态的 PR 附“旧版本读/写兼容、切换顺序、失败中止点、数据校验、恢复命令”。真正的生产密钥撤销、历史重写、备份恢复和数据库变更以单独操作单执行；本文只规划，不意味着已经对真实环境操作。

## 7. 测试矩阵与证据要求

### 按风险选择验证，避免实现与测试互相证明

| 层次 | 必须验证的内容 | 可用手段 | 不能替代的证据 |
| --- | --- | --- | --- |
| 合同/算法 | canon 固定向量、schema、状态转移、能力/恶意区分 | 独立 Oracle、跨语言差分、属性/变异测试 | 真实入口的身份和执行行为 |
| 本地真实进程 | 多进程单写、强杀恢复、锁所有权、文件预算、安装恢复 | 临时目录与合成用户配置、独立进程、race | 其他 OS 的文件/权限保证 |
| HTTP/浏览器 | 管理/决策分权、坏来源、错误响应、正文超时、页面状态、会话切换 | 真实本地 HTTP + 浏览器旅程 + 合成身份 | 真实 OIDC/部署拓扑的边界 |
| 真实 PostgreSQL | 迁移/现存数据、租户隔离、注册并发、事务/outbox、worker lease | 可丢弃数据库与合成数据、崩溃注入 | SQLite/fake 的通过不能代替 |
| Edge/Connector | 超时、输入输出预算、范围、凭据脱敏、任务重试恢复 | 隔离进程、临时文件树、批次/回执断言 | 所有 Connector 不能由 directory 一个测试代表 |

| 供应链/独立审查 | 发布身份、摘要链、依赖检查、已接受漏洞修复 | 干净构建、产物验证、独立安全复核 | CI 全绿不代表未运行的检查通过 |

## 9. 开发切片、复核与关闭方式

建议一个 PR/会话对应一个 DEV 子切片，例如 DEV03-A 先修版本冲突，DEV03-B 再落实单写者和恢复；不要把 18 项合成一个重构 PR。每个切片沿“证据→合同/设计→最小实现→负向及合法路径→真实边界验证→独立复核”推进。子切片可以先交付，但父任务验收未满足就不关闭。

| 字段 | 每张开发卡片必须填写 |
| --- | --- |
| 来源 | R/Kimi 原始 ID、仲裁结论、受影响 commit/path |
| 范围 | owning module、输入/输出、受影响消费者、明确非目标 |
| 设计 | 不变量、状态/权限/错误、版本、迁移与恢复；未决业务取舍显式记录 |
| 实现 | 最小切片、责任人、估算、依赖、状态；默认待实施 |
| 验证 | 旧行为反例、合法路径、真实环境、命令、产物及未测范围 |
| 关闭 | 独立复核结论、发布门槛、剩余风险、文档/合同同步、回滚说明 |

待正式记录的架构选择已有明确推荐：桌面与受管身份 profile 分开、Linux 先交强边界、break-glass 复核正交、任务至少一次投递配逻辑幂等、历史完整性靠可选独立锚点增强。它们是本计划的推荐方案；尚未冻结的业务语义不会在实现中默默落地。常规缺陷修复、回归测试和文档对齐可在现有授权内继续，不需把每个技术细节重新提交用户确认。
