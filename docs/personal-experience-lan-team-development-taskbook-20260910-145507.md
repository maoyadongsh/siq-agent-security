## 1. 任务目标与实施边界

在现有 SIQ Agent Security 项目上做增量优化，先完成个人用户的完整体验，再建设局域网团队多设备管理。

个人版应让用户能够：

1. 发现本机已有智能体、平台实例及 Skill，并看清相互关系。
2. 为智能体和 Skill 设置可理解、可执行的权限范围。
3. 安全导入、安装、更新和移除 Skill。
4. 在已授权范围内正常使用原有智能体；需要新增权限时由用户确认。
5. 追溯执行主体、使用的 Skill 版本、授权、操作、拦截及结果证据。
6. 在安装、启动、刷新页面、重启电脑、升级和故障恢复时获得连续、准确的体验。

团队阶段沿用个人客户端，加入设备注册、团队归属、集中资产管理、组织策略与执行回报，避免让用户重新安装和维护另一套客户端。

### 1.1 必须复用的工程基础

- 本地 Go 程序：`apps/agentshield/`。
- 本地管理前端：`apps/web/src/local/`，由 Go embed 提供正式运行入口。
- 准入、授权、决策、回执、来源与效果核验：现有 `internal/` 模块。
- 平台适配器：`adapters/runtime/` 与 `internal/adapterinstall/`。
- Skill 安装引导：`skills/siq-agent-security/`。
- 企业控制面与采集链路：`apps/control-api/`、`edge/agent/`、`connectors/`。
- 数据合同与设计依据：`packages/contracts/`、现有开发规格及 ADR。

新增代码应放入所属模块；需要新增桌面启动器或公共模块时，先说明现有模块无法承担的职责及技术选择。不能通过复制一套前后端或绕过既有决策引擎实现体验功能。

## 4. 用户流程与交互要求

### 4.1 首次安装与接入

1. 安装客户端，验证程序来源、完整性、系统兼容性和安装位置。
2. 完成本机管理身份确认，打开现有本地 UI。
3. 说明默认扫描范围及本机保存方式，用户开始发现；支持选择额外目录。
4. 展示平台实例、智能体、Skill 及关联关系、检查结果和能力限制。
5. 用户选择接入对象，确认权限、配置改动和必要的重启。
6. 备份并应用适配器配置，执行无真实外发副作用的正常/拒绝自检。
7. 返回真实状态，并提供下一步操作与恢复路径。

不得因发现资产自动批准现有权限，不得将模型建议直接变成授权；接入需要重启智能体时，应让用户选择时间，不能中断正在运行的任务而不说明。

### 4.2 日常运行与额外权限

- 已授权范围内正常运行，不为每次普通工具调用重复弹窗。
- 缺少可申请权限时创建待确认操作；硬性禁止或无效必需 Authority 仍按现有规则拒绝，不用弹窗绕过。
- 系统通知只引导打开 SIQ 中对应申请。
- 确认窗口显示平台实例、智能体、Skill 版本或归属未知状态、操作、目标、附件/资源、期限和授权范围。
- 默认选项为“拒绝”“允许本次”；“本次任务同类操作”必须展示具体限制；长期权限进入单独编辑。
- 批准绑定主体、动作与关键参数摘要、资源范围、策略版本、期限和一次性使用条件。
- 关键参数改变、策略撤销、版本改变或申请过期使旧批准不可使用。
- 在执行前最后可用检查点重新校验；不把非原子检查点描述成 OS 级原子执行保证。
- 等待期间不能提前执行；未回应按明确期限结束，不能视为默认同意。

### 4.3 新 Skill 安装

`选择目标智能体 → 输入链接/目录 → 安全获取副本 → 静态检查 → 权限预览 → 用户确认 → 安装具体内容 → 平台识别与保护验证`

- 对来源解析、下载、解包、检查和安装分别记录状态与失败原因。
- Git 固定 commit，下载对象固定摘要；所有重定向重新校验来源与网络访问范围。
- 不执行仓库钩子、Skill 脚本、依赖生命周期脚本或安装程序来完成静态检查。
- 依赖安装或其他必须执行代码的准备动作，单独纳入授权与受控执行。
- 防止路径穿越、符号链接逃逸、解包炸弹、超大文件和检查后内容替换。
- URL 中的凭据不进入日志；私有源认证只使用隔离、可撤销的凭据引用。
- 检查通过只表示指定检查项通过，不表示任意行为绝对安全。
- 第三方原生安装入口是否能前置拦截必须实测；仅可事后发现时准确显示。

### 4.4 Skill 更新与移除

- 自动检查新版本，展示来源、版本、内容和权限变化、受影响智能体与检查结果。
- 用户确认后才更新；未确认时保留旧版。旧版被判定失效、被撤销或存在完整性问题时，不以“保持可用”为由继续允许受限制动作。
- 审批内容与实际安装内容一致；进行中的任务保持明确版本，避免中途替换。
- 更新新增权限不自动继承；无权限增加也不跳过用户已要求的更新确认。
- 支持失败恢复和经校验的回退，防止不兼容状态或已撤销版本重新获得权限。
- 移除智能体对 Skill 的关联与删除共享文件分开处理，明确其他使用者。

### 4.5 任务与结果追溯

按任务展示发起者、智能体、Skill 版本、用户授权、操作、决策、结果证据和完整性状态。

- “工具报告成功”“结果已观察到”“结果已核验”分开显示。
- 没有可信任务或 Skill 关联的调用保留为未归属活动，不凭时间接近强行拼接。
- 文件产物可展示位置、摘要和相关证据；外部发送需对应接收端或服务证据。
- 不能把现有演示的受控接收端证据外推为所有 SaaS 发送都可核验。
- 记录缺失、签名损坏、观察冲突、权限撤销及失败均有可理解说明。

### 4.6 故障恢复

| 情况 | 期望行为 |
| --- | --- |
| 服务未启动 | 启动器提供启动入口；页面不假装可凭空启动原生进程 |
| 端口被其他程序占用 | 核验身份后显示冲突，不终止其他程序；调整端口须同步受管理配置 |
| 管理会话过期 | 重新验证管理身份，不要求重启保护服务 |
| 适配器失效 | 标记受影响对象，提供诊断、修复或还原 |
| 决策服务不可达 | block 模式拒绝受控动作；保留既有 warn/audit_only 合同与硬拒绝规则 |
| 记录写入失败 | 按现有安全合同失败关闭或记录明确缺口，不生成伪成功证据 |
| 用户关闭窗口 | 不等同于停止保护；退出后台服务须说明影响 |
| 产品升级失败 | 保留可恢复版本和状态，不混跑不兼容写者 |

## 6. 权限、身份与数据设计约束

### 6.1 权限关系

概念上允许范围由“智能体授权上限 ∩ 当前 Skill 版本授权 ∩ 当前任务约束”决定，并叠加独立硬性拒绝规则。此表达用于解释产品行为，不直接替换现有 Grant/Intent 决策算法。

- 同一 Skill 被多个智能体使用时，各自绑定权限，不共享一个无主体的全局开关。
- Skill 调用链不能通过合并全部权限扩大当前动作授权。
- 显式区分主体、资源、动作、版本、期限及授权来源。
- 不相信模型自报的 Skill 名称；可信归属应来自宿主可验证事件或受控执行上下文。
- 无法可靠归属时，不能套用更宽的 Skill 权限；需要严格 Skill 边界的操作暂停、拒绝或进入已验证的受控路径。
- 普通命令钩子不自动等价于文件/进程/网络的 OS 级隔离；复杂 shell 命令不能只靠工具名称判断完整效果。

### 6.2 管理授权与会话

- 管理会话、适配器决策凭据、效果观察凭据保持分权。
- `/ui-config.json` 不包含凭据；浏览器不得将 token 放入 localStorage、页面 URL、通知或诊断包。
- 刷新恢复方案应比较受限会话 Cookie、本地启动器协助恢复等选项，评审 Origin、Host、CSRF、DNS rebinding、过期、注销及浏览器关闭后的行为。
- 重新配对不能变成无认证地向任意网页提供管理权限。
- 跨平台通知/深链接只传待办标识，点击后仍验证管理身份和当前申请状态。
- OS 凭据存储、一次性挑战或统一 UI 本身均不能直接证明防同 UID 恶意进程。若需要更强隔离，受控启动与凭据/服务边界必须形成 ADR 和实测证据。

| 对象 | 需要明确的字段或关系 |
| --- | --- |
| 平台实例/智能体 | 稳定标识、平台版本、运行位置、配置目录、主体与接入能力 |
| Skill 制品/安装实例 | 来源、commit/摘要、版本、安装位置、使用者、检查结果 |
| 使用授权 | 主体、Skill 版本、资源范围、期限、状态、修订号 |
| 待确认动作 | 任务/动作关联、关键参数摘要、有效期、策略版本、消费与终态 |
| 安装/更新操作 | 当前/目标版本、审批依据、暂存与提交状态、失败恢复信息 |
| 任务追溯投影 | 已有事实引用、归属置信与依据、结果证据、完整性状态 |

实现时优先扩展或投影既有对象。合同变更先设计兼容读写、版本迁移、异常恢复与回退限制，再生成测试向量。保留单写者、CAS、不可变版本和既有多文档提交恢复机制。

### 6.4 隐私与原文记录

- 默认只保存操作元数据、授权依据、摘要、脱敏限长片段和结果证据。
- 原文记录作为用户显式选择的独立能力，限定对象/任务、时间和范围，界面持续显示开启状态。
- 原文不能进入现有不可变审计、回执链、默认日志或默认导出包；与身份密钥、决策凭据隔离。
- Secret、认证凭据及私钥即使开启原文记录仍不得采集。
- 原文加密、访问控制、保留期与删除方案需先评审；删除可选原文不破坏保留的审计完整性。
- 现有规格禁止持久化原文，因此 UX-013 必须先完成规格与安全边界更新，不能直接加一个保存开关。

| AC02 | 有效会话刷新可恢复；过期可重新验证而无需重启保护服务 |
| AC03 | 发现结果包含真实实例/Skill 关系，扫描不执行被检查内容 |
| AC04 | 用户批准后才接入；配置预览、备份、验证和还原可用 |
| AC05 | 同 Skill 在不同智能体下可有不同权限，不能借用或伪造归属扩大授权 |
| AC06 | SIQ 确认绑定具体动作；拒绝、超时、撤销、参数变化与重放不会执行 |
| AC07 | 三种 Skill 导入入口按支持范围工作；实际安装内容与批准一致 |
| AC08 | Skill 自动检查更新，用户确认后切换；共享关联与任务版本正确 |
| AC09 | 运行操作和结果可追溯，未知/缺失/冲突不显示为已核验 |
| AC10 | 默认不保存原文或凭据；按需原文隔离、安全可控且不污染审计链 |
| AC11 | 各系统/平台真实组合分别有证据，功能缺口可见 |
| AC12 | 企业入口、本地 embed 与既有 CLI/合同兼容性无未解释回归 |

### 10.2 安全负向测试最小集合

| 场景 | 预期 |
| --- | --- |
| 跨站请求、错误 Host、伪造管理身份 | 不能取得或使用管理权限 |
| 决策 token 调管理 API | 被拒绝 |
| 已消费/过期批准重放，批准后参数或策略变化 | 被拒绝且有正确记录 |
| 两个窗口并发批准或更新同一对象 | CAS/幂等规则保证一致，不重复生效 |
| Skill 标识伪造、版本替换、多 Skill 权限混用 | 不扩大允许范围 |
| 待审批期间先执行、撤销后继续执行 | 执行前可用门禁拒绝；宿主限制单列 |
| 决策服务失联、二进制缺失、宿主超时 | 分别验证；block 不静默放行，未覆盖边界明确 |
| 恶意仓库钩子、自动执行脚本、路径逃逸、超大解包 | 检查阶段不执行；限制与拒绝生效 |
| 外部下载跳转内网、URL 含凭据、检查后内容替换 | 每跳校验、敏感信息不落日志、摘要不匹配拒绝 |
| 文件/收件人等资源经别名、符号链接或平台路径差异绕过 | 按统一规范化与实际访问边界校验 |
| 回执篡改、原文意外进入导出、磁盘写入故障 | 检测与正确失败状态，不能生成伪成功 |
| 更新中断、进程强杀、旧版写入新状态 | 可恢复或明确拒绝，不破坏授权与事实链 |
| 团队设备跨租户、已撤销凭据、任务错设备 | 被拒绝，不污染其他设备结果 |

正向用例与负向用例成对。测试不向真实联系人发送消息，不调用付费模型或真实外部变更操作来替代确定性验证。真实宿主测试需保留版本和隔离测试配置。

### 10.3 工程验证命令

按实际修改范围运行，不能仅运行前端测试就宣称跨平台完成。Go 版本以各模块 `go.mod` 和工具链要求为准。

Web：在 `apps/web` 中执行：

```bash
npm ci
npm test
npm run build
npm run build:local
npm audit --audit-level=moderate
```

本地运行时：在 `apps/agentshield` 中执行：

```bash
gofmt -l .
go vet ./...
go test ./...
```

交叉构建覆盖已确定目标架构；输出到隔离的构建目录。每个正式支持组合还需原生安装与 E2E，交叉构建不能替代。

企业 API、合同与规则变更：在 `apps/control-api` 中按仓库约定执行：

```bash
uv sync --dev
uv run ruff check app
uv run pytest
```

数据库变更补迁移与恢复验证；共享规则变更补 Python/Go 对等测试。Edge 与 Connector 修改在所属 Go 模块执行 vet/test。UI 流程补有意义的浏览器旅程、键盘/焦点与显示适配检查。

每批完成后在仓库根目录执行：

```bash
git diff --check
git diff --stat
git status --short
```

### 10.4 体验指标

UX-000/UX-015 应记录以下指标的当前基线与优化后实测值；本文不虚构性能目标或生产 SLA。

- 从已有可用安装包到首次发现结果的耗时、手动步骤数、终端操作次数。
- 从选择智能体到验证接入的步骤、耗时与失败原因。
- 页面刷新、后台恢复、过期重新认证的成功率。
- 正常任务的权限弹窗数量、重复通知数量和误打扰原因。
- 每次决策新增耗时的 P50/P95、启动耗时、空闲资源、事件量增长下存储占用。
- 每个入口的安装/更新成功、取消、失败恢复与卸载还原情况。

硬性要求：不以隐藏错误减少步骤，不以放宽权限减少弹窗，不以关闭记录降低开销。

### 11.1 第一批可执行工作

1. 运行只读现状核查，保护已有工作区改动，完成 UX-000。
2. 获取目标真实系统与平台版本清单，首先验证 WorkBuddy、Windows 原生/WSL 和 Skill 归属能力，完成 UX-001。
3. 回写会话、启动器、授权和必要受控启动的规格/ADR，完成 UX-002。

5. 交付 M1 可运行版本和验证结果，再依次推进后续任务。

不能因为某个目标系统暂时不可用而伪造验证。可继续独立开发事项，相关发布门槛保持未完成，记录需要的环境或产品决策。

## 13. 完成定义与交付格式

### 13.1 每个任务的完成定义

只有同时满足以下条件，任务才能标记 `done`：

- 需求、规格、合同和实现一致；迁移与恢复有说明。
- 对应正向与负向测试通过，实际执行命令与结果可查。
- UI 描述与真实能力一致；未知、降级、等待和失败可见。
- 不破坏管理/决策分权、单写者、不可变事实、权限撤销及已有模式语义。
- 适用的平台/系统有真实验证；未覆盖项明确保留。
- 没有意外凭据、原文、生成产物、依赖变化或其他任务改动进入交付。

### 13.2 建议任务记录模板

```text
任务 ID：
状态：todo / doing / blocked / done
负责人：
对应决策与验收项：
基线提交与工作区说明：
实际修改文件：
规格/合同变化：
实现后的用户行为：
验证命令与结果：
真实平台/OS/架构/版本：
证据位置：
未验证边界与阻塞：
恢复/回退方式：
```

### 13.3 阶段交付包

- 可运行代码和清晰的变更范围。
- 更新后的现有规格、合同与必要 ADR。
- 对应安装包或测试构建，以及准确版本/摘要。
- 四个关键页面的真实流程演示与验证材料。
- 支持矩阵、测试与负向证据、已知限制。
- 安装、使用、更新、诊断和卸载说明。
- 团队阶段另附真实设备清单、受控入口、身份、数据库恢复、组织策略和撤销验收。
