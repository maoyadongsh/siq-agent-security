四、不可妥协的验收原则
1. 预览、模型输出、管理员登录不创造执行授权；审批策略操作不授权任意命令。严格字段和最终参数摘要绑定，变化重新确认。
2. 使用既有唯一预留，写前/执行前重查撤权和会话；禁止第二套权限、仅内存去重、重启自动重放。
3. policy set 提交或读回不等于已加载；加载确认不等于通用行为保护。保持 --wait 和完整 revision/digest 核对。
4. 真网阻断只能由明确 HTTP 403 + 独立接收端零到达证明，并先证明两个精确目标可达。未知/网络错误/超时不能算阻断，不对禁止请求重试到绿。
5. required 后端失联不 native fallback；任务与政策半完成分别记录。结果存储失败不报成功；不确定恢复只做对账，不自动再执行。
6. 停止必须验证目标任务归属和后端确认，不能用删除整个 sandbox 替代。能力不足应 partial/blocked，继续其他任务但不造成功。
7. 参数/输出默认只存脱敏摘要；按任务明确 opt-in 原文，授权期限与保留期限分开，历史密钥缺失不可自动重建新身份。
8. 新任务不复用旧 rc.6 工件身份；先 build:local，再生成唯一候选与源/工件/UI 摘要。不得覆盖历史制品、证据、失败和签名记录。
9. 跨进程原子 CAS、任意后代进程停止、exactly-once 等未证能力不承诺。并发 target 的权限冲突须有明确串行/拒绝方案和边界。
10. 不接触其他协作者工作树，不代做 Windows/macOS，不启动 T01–T06 团队开发，不拉入条件 O06。
