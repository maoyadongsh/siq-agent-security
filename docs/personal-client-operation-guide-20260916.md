# 个人客户端操作手册

适用范围：当前个人体验开发分支。Linux 已有阶段性实测；Windows/macOS 由协作者独立验收。发行就绪状态以[当前收尾台账](personal-experience-closure-progress-20260913.md)为准。

## 1. 选择入口

- 想先体验：使用 [README 的 Linux 源码启动步骤](../README.md#个人管理端linux-源码体验)。构建后的 Go 服务已经包含个人界面，不必另外启动企业 Control API。
- 已取得受信任发行清单和对应二进制：按[本地操作指南](../AGENTSHIELD.md)安装。测试构建及测试签名用于开发验收，不代表正式发行包。
- 在智能体中安装 Skill：Skill 是接入入口，实际管理界面和决策由本机 SIQ 服务提供。只复制 Skill 文件不能证明运行时权限已被限制。

本文命令使用 `siq-agent-security` 表示实际二进制路径。每次操作必须选择同一个 `SIQ_AGENT_SECURITY_STATE_DIR`；它保存身份、配置、授权和历史。

## 2. 启动与配对

前台体验可运行 `siq-agent-security start --port 47611`，保持终端运行，然后访问 `http://127.0.0.1:47611/overview`。如果端口已被其他实例占用，先确认实例归属，不要结束不明进程。

**先确认浏览器在哪台电脑。** 普通个人用户推荐将服务安装在自己的电脑，直接打开上面的地址。如果服务装在远程服务器，浏览器里的 `127.0.0.1` 指向你的电脑，不是服务器。需要在**浏览器所在电脑**执行下列模板，将 `SSH_USER@SSH_HOST` 替换为自己的 SSH 登录目标；保持终端打开后再访问上面的管理地址：

```text
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:47611:127.0.0.1:47611 SSH_USER@SSH_HOST
```

需要已有 SSH 权限和客户端，不能跳过主机密钥核验。若实例端口不同，同时替换三个端口值；转发两端保持同一端口，以满足 Host/Origin 检查。本地端口已占用时先确认归属，不终止未知进程。不要把个人服务改为监听所有网卡，也不要将管理 URL 直接替换为服务器 IP。新版 `ui` 在 SSH/无图形环境只显示指引，不尝试在服务器打开浏览器；`ui --print` 为兼容工具仍只输出本机 URL。

2026-09-25 源码增量支持 Skill 辅助连接：在页面点击“通过智能体连接”，复制页面生成的连接请求交给已安装的 SIQ Skill。智能体使用同一实例的已安装程序和状态目录执行 `connect --request <请求 ID> --confirm-connect --port 47611`，确认后原浏览器自动进入管理台；用户不必查找或传递配对码。连接请求有效期为 5 分钟，取消、过期或服务重启后需重新发起；请求 ID 不是凭据，其他浏览器不能凭它领取会话。连接不等于给智能体授权。

新版管理会话固定有效 24 小时，刷新页面可恢复但不延长有效期；主动退出、服务重启或到期后需要重新连接。不提供永久免登录。该增量尚未进入 `0.3.1` 或本机 `0.4.0-rc.2` 签名包，旧程序仍按原行为工作。

远程场景中，浏览器在用户电脑发起请求，但 Skill 的 `connect` 命令仍在**服务机器**上、使用安装时的同一状态目录执行。安装包复现必须使用包含该功能的新版本二进制和 Skill；现有旧包不能通过修改说明自动获得新能力。

没有 Skill 或使用旧版本时，展开“手动配对 / 旧版本连接”，输入本机生成的一次性配对码。过期或用过的码不能重放；在使用相同状态目录的终端运行 `siq-agent-security pair --port 47611` 获取新码。不要把码、管理会话或完整 daemon 日志发到群聊或 PR。

“未连接”“决策 API 不可达”表示前端无法访问个人服务。检查服务是否运行、端口是否一致、是否误开了企业界面。单独运行 `npm run dev:local` 只会启动开发前端。

后台服务与前台体验分别管理：Linux 安装由产品 CLI 操作 systemd 用户单位；开发实测使用 `--runtime` 注册，不能据此推断已配置登录自启。不要通过修改共享 systemd 管理器的 HOME 来切换测试环境。

## 3. 发现与确认保护

进入“智能体”页查看实际发现的实例、平台和接入状态，再检查“权限”与授权记录。先核对目标实例，确认必要的工具、读写路径和网络范围，再按界面确认。

发现了目录、安装了钩子、用户批准了权限，是不同阶段。只有对应运行时接入成功并有允许/拒绝的实际证据，才能判断该组合上的限制是否生效。未接入或不支持的能力应显示其真实状态。

需要额外权限的任务在 SIQ 确认中心处理。审批通过后仍需合法的执行预留和有效身份；超时、撤权和重放不能当作重新执行的授权。对可能已产生副作用的操作，先检查回执及观测，再按恢复流程处理。

## 4. 安全导入与安装 Skill

使用“Skill 导入”查看支持的本地目录、仓库或下载来源。检查分析结果、来源、内容变化与权限要求后再确认目标实例和安装。

来源不可访问时保留失败原因。当前网络若把公开域名解析为保留或私网地址，不能关闭来源校验、伪造 DNS 或放宽 HTTPS 来继续。成功导入的本地快照也不代表生产托管来源已经通过真网验收。

## 5. 检查更新、确认与移除

“检查新版”读取上游并比较快照，不应自动改动现有安装或权限。出现新版本后，检查文件与权限差异，再确认更新。更新计划绑定所见的候选内容与授权 revision；内容漂移、旧签名或其他窗口已修改状态时，应重新比较。

取消更新应保留现有版本。确认更新后，按界面重新核对权限与身份绑定；旧授权或旧会话不应因安装新内容而恢复。移除 Skill 会撤销相关权限，未知用户文件按归属规则保留；不要为了得到“卸载成功”提示手工删除这些文件。

Skill 更新与 SIQ 客户端升级是两类操作。客户端升级/回滚须使用对应发行清单和产品命令。回滚指向某次切换事务的准确历史二进制路径，不是任意一个同版本文件。具体参数和中断恢复见[本地操作指南](../AGENTSHIELD.md)。

## 6. 查看任务与导出证据

任务详情把操作、授权、回执、效果观测与完成判定分开展示。工具返回成功不等于任务目标已被独立验证。

任务导出和 trace-export 是经过脱敏的签名投影，只包含该活动绑定的回执及合同允许的来源信息。导出绑定当前快照；如果期间历史发生变化，刷新任务后重新导出，不反复提交旧快照。

默认导出不包含原文仓的明文或密文。验签应使用预先可信的本机公钥；仅信任导出文件自己携带的公钥无法证明来源可信。

## 7. 可选原文记录

默认不采集任务原文。需要保留时，在该任务上明确开启允许的内容类别、授权时间及保留期限。

授权期限控制是否还能继续采集；保留期限控制已采集内容多久后到期。撤销采集授权并不立即删除历史原文。删除某条记录或清理到期密文，不应删除任务授权、签名回执和审计历史，也不应影响其他任务尚未到期的内容。

查看原文需要管理权限。把别的任务 ID 填到某条原文记录上会被服务端拒绝；这不能通过只隐藏界面按钮来替代。

## 8. 停止、保留退出与再次进入

先通过产品命令停止自己选择的实例，再按保留退出流程注销对应服务。`teardown --confirm-teardown` 的当前平台行为见本地操作指南；确认对象归属后操作。

保留状态目录后再次使用相同路径进入，应沿用原身份和历史，重新配对。已撤销 Grant 必须继续保持撤销；旧管理会话不能因为重入而有效。不要把删除状态目录当作配对、升级或状态格式错误的通用修复。

## 9. 常见恢复路径

| 现象 | 操作 |
| --- | --- |
| 配对码过期 | 同一状态目录运行 `pair` 获取新码 |
| 服务重启或 24 小时到期后页面提示会话失效 | 新版可通过 SIQ Skill 重新连接；也可手动配对，按页面提供的恢复操作继续 |
| 更新冲突、旧 revision 或候选变化 | 重新读取安装状态并比较，重新确认 |
| 状态格式不兼容或迁移中断 | 先运行 `state-status`；保留状态，使用匹配程序按恢复说明处理 |
| 后端不可达时必要调用被拒绝 | 恢复对应服务后复核身份、授权和回执，不通过 warn/audit 配置绕过必需 Authority |
| OpenShell 未配置或身份不明 | 运行 `openshell doctor`；当前能力不足时保持其状态，不把 CLI 存在或端口开放当作真实隔离 |

## 10. 反馈问题时提供什么

提供 SIQ 提交或版本、OS/架构、宿主版本、页面操作步骤、稳定错误类别，以及脱敏的回执/活动引用。开发者另附源代码与候选摘要、执行命令、结果和未测边界。不要公开令牌、配对码、私钥或原文内容。


## Linux 独立实例的 HOME

新建测试或独立实例时，可在初始化/安装前的该实例 `config.json` 中设置 `linux_service_home` 为已存在的规范绝对目录。安装后 HOME 固定在该实例的签名 systemd unit 中，不改变用户服务管理器或其他服务。省略字段维持原行为；这不是操作系统沙箱。

已经注册的实例不可直接修改该字段：签名归属检查会拒绝变化。先恢复原配置并使用现有受支持生命周期操作处理旧实例；不要修改 unit/drop-in 或使用 `systemctl --user set-environment HOME=...` 绕过归属校验。Windows/macOS 不使用这一 Linux 专属选项。
