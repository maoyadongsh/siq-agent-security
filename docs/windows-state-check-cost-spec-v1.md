# Windows 状态检查成本修复 v1

冻结候选 38196ab 的现有 CPU/执行 trace 显示：一次 Authority HTTP 组件旅程执行约 57 万次 syscall；RequirePath 累计约 80%，重复 Windows profile 证明读取及父目录遍历占主导。修复范围仅为同一次 N01 兼容检查的重复工作，不调整 Authority、撤销、签名、旧消费者屏障或 4 秒宿主预算。

Windows profile 兼容元数据使用短生命周期的只读快照：每次检查新建，从卷根逐级打开并保持祖先目录句柄，拒绝重解析和非目录，不允许目录写入或删除/替换共享；目录句柄必须包含 FILE_LIST_DIRECTORY，只有 READ_ATTRIBUTES 的元数据句柄不能建立 Windows 写共享排斥。状态根及其下元数据目录仍逐个核验当前 SID、完整 DACL。固定相对路径文件在已固定目录下排他于写入/删除地打开，仍逐个核验普通文件、单链接、当前 SID 和 DACL、尺寸与读前读后身份/大小/时间。结束前再次核验打开对象的形态与 DACL；失败关闭，释放所有句柄。仅在此次调用内复用已固定的目录和已打开文件，不创建全局或请求间缓存。

兼容检查仍每次读取当前状态标记、本地实例、活动迁移屏障、Windows profile 计划/准备/完成点和原迁移历史。同一次检查内对完全相同绑定和计划的重复读取可合并；初读用于版本门禁的 Marker 必须与快照完成证明的目标 Marker 相同。不得跳过外层或嵌套状态根，不根据业务目录名猜根。DirectoryID 的持久身份算法、路径规范化和编码保持不变，ErrBinding 及使用初始化规范路径的恢复提示继续透传。POSIX 路径保持现有读取语义。迁移恢复入口继续持既有 Writer，并单独验证活动屏障；本优化不授权普通消费者完成迁移。

HTTP 登记由单一 `EnrollContext` 在同一身份锁内完成完整凭据/撤销/当前 Grant 验证并返回用于响应的 Record 与 Binding，不再由 handler 预认证后重复认证；身份认证函数可同时返回它本次已验证的 Grant 供本次 envelope 构造。裁决在解析有界请求后执行一次 `AuthorizeSessionContext`，后者仍读取当前身份签名/凭据/撤销/Windows profile，并从本次 ResolveBinding 已完整验证的选中 Grant 核对身份 profile 和精确引用。最终 Intent/Binding 发布复验、引擎裁决前复验、现有撤销锁与不延长会话期限保持。无结果跨请求留存；未认证畸形输入仅可能改变 400/401 错误优先级，不暴露身份详情。

Windows Intent 记录的单次读取合并为 `statefs.ReadPrivateRecord`：使用调用者已有的状态根及记录路径，前后各一次 RequirePath 保持所有外层/嵌套兼容与 N01 屏障，期间用同一 ReadSnapshot 固定根、记录目录和文件。先 PinDirectory 明确核验记录目录，即使文件不存在，目录缺失/不可读/扩权也不是“无撤销”。所有元数据和 ACL 均来自当前调用，读取结束再次 Verify 后释放句柄；大小上限及后续严格 JSON/签名解析保留。仅合并同一业务文件原有的五次兼容路径检查；不合并不同记录、Grant 查询、撤销查询或发布边界。

验证包括前后同旅程成本、缺失/损坏/替换/硬链接/重解析元数据、当前 ACL 扩权、检查结束后新调用立即看见变化、活动屏障及旧消费者拒写；不能以 profile 工具的额外成本当作正式性能门槛。最终须以不带 profile 的受管宿主 HTTP 登记＋裁决验证原 4 秒预算。
