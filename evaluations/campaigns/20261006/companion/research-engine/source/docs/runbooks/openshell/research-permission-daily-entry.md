# 本机日常分析助手权限测评接入

此入口用于用户明确授权的 DGX Spark 本地功能修复和测评。它仍使用 Research
本地账户与业务数据库，不是生产 IAM 接入或正式机密业务上线。所有模型任务使用
受控合成公司；已有公司不自动获得新增授权。

## 入口与保护配置

本机历史前端 `15173` 代理日常 API `18081`。旧 API 启动器固定为
`legacy`/`host`，且其冻结源码清单已与工作树不符。不能直接重启旧启动器，也不能
修改旧清单以冒充历史版本。

`scripts/ops/launch_research_permission_api.py` 使用显式的当前源码清单摘要和
已有私密环境文件引用。启动前验证源码、入口和环境文件权限，拒绝生产环境：

- `protected`：`SIQ_OPENSHELL_REQUEST_BACKEND=qwen38`、
  `SIQ_OPENSHELL_DATA_CLASSIFICATION=confidential_local`、请求部署为 `host`；
  日常 API 使用本机 `47611` SIQ 权威服务，不使用隔离测评的 `47811`。
- `rollback`：保留原私密配置及历史启动器的 `legacy`/`host` 显式覆盖；使用当前
  固定代码，不能恢复旧进程内存，也不保证原 Host 模型端点本来就可用。
- 主端口 `18081` 保留既有恢复配置。独立预检端口 `18083` 明确关闭恢复所有权；
  该端口健康不代表受保护业务可以运行。

保护模式仅在非生产本地环境启用已有本地数据 Grant 管理 API。发放仍要求经正常
认证的 `super_admin`，必须针对另一名当前有效用户，TTL 有上限、操作有审计。
该开关不创建业务或 SIQ Grant，也不授予模型管理员身份。原本仅用于隔离候选的
运维流程在此扩展到本轮明确授权的本机默认入口；生产接口仍拒绝此模式。

## 操作顺序

1. 记录日常 API PID、启动时刻、用户 unit、前端代理目标和所有已有覆盖文件。
   检查存活业务租约与请求 sandbox owner；存在未完成业务时不得切换。
2. 新建源码清单和归档，不覆盖旧清单。清单必须包含启动器、`apps/api/main.py`
   及实际依赖。使用 `--check-only` 校验保护与回滚命令。
3. 使用 `scripts/ops/prove_research_permission_launch.py` 在独立端口验证两种
   启动配置、匿名 HTTP 拒绝、退出和端口释放。该脚本不切换日常服务。
4. 为目标 unit 准备一对绑定同一清单的 `ExecStart` 覆盖。备份原 unit，确认无
   未登记覆盖，重新核对 PID 和存活业务后重启该 unit。主端口必须同时通过
   `/health` 中的池恢复与 Qwen 请求恢复，前端 `/api/health` 也须可用。
5. 用 `scripts/openshell/prove_research_daily_permissions.py` 从原前端正常登录，
   通过业务 HTTP 发放本批合成公司的授权，再按原业务链执行只读/批准写入配对。
   该脚本不指定 `runtime_target`，不替换 API 或运行镜像；凭据仅留在控制进程内。
6. 测后撤销本批授权、核对任务终态并回收本批资源，禁用两个合成账户，使其令牌
   失效。核对签名记录、独立文件字节及运行前后源码摘要；不能用健康状态代替效果。
7. 启动失败时使用预备回滚覆盖。测评失败后，先确认本批任务已终态，并重新检查
   是否出现其他用户的新任务，再切回原路由。不得删除未知 writer 或修改终态
   以强行通过回滚条件。

本机本轮 unit 为 `siq-research-api-main-delivery-20260924.service`，新增覆盖名为
`60-research-permission-evaluation.conf`。具体清单、覆盖模板、私密日志和原 unit
备份保存在 Security 独立测评目录的 `private/deployment/` 对应批次。日志和原
环境不进入公共报告；跨项目评测通过文件证据和公共 API，不导入 Security 内部代码。

后续修改已冻结源码时必须创建新清单、复核回滚路径并重新验证后再重启。不要删除
覆盖后直接启动已过时的历史清单。通过本轮配对也不意味着任意 Skill 自动归属、
任意本机进程强隔离，或已经提供系统重启后的自动启动配置。
