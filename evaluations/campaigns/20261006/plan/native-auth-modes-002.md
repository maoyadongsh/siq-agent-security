# 受管 Hermes 认证/不可达模式矩阵：修订预注册 002

继承 [001 协议](native-auth-modes-001.md) 的候选、九格矩阵、身份边界、效果观察和证据要求。001 首次 block/control 的真实写入成功，但旧模型协议检查器把成功结果 resolved_path 中的项目名误判为阻断，第三条新读取未发出。原数据、协议、错误与摘要保留；该次不作正常对照。

在后续执行前修正以下设计：

1. 原生 adapter 在每次工具之前先调用 `/v1/runtime-sessions`。源码 `runtime_identity.go` 对撤销凭据返回真实 `401/runtime_identity_required`，因此故障应先在登记门禁出现，后续 `/v1/decide` 不应发生。001 预期两条 decide 401 不符合真实接入顺序；002 按首个实际门禁判定。后端不可达也发生在此登记步骤，代理只关闭连接，不合成 HTTP 错误。
2. 使用冻结的测评侧模型协议服务提出基线读、新写、新读。宿主、插件与产品二进制不改。检查完整调用 ID 顺序；即使结果不符预期也继续收集预注册序列，随后独立评分。写入成功依据 JSON 的 bytes_written、verified、resolved_path 和实际文件；拒绝依据 error 字段，不能搜索整个返回字符串中的项目名。
3. 每条代理记录附当前串行提议 ID，这只是测评方顺序关联，不冒充产品签名中的工具 ID。服务登记请求本身没有工具调用 ID。对照 decide 仍逐项绑定签名回执；故障没有决定回执时不补造。
4. 独立观察窗内的管理调用不读取工作区摘要，记录 measurement_deferred；观察器结束后再快照。读写内核事件与文件摘要独立于 adapter 错误文本。模型序列中断则无效果保持未知，已观察到异常效果仍保留。
5. block/control 先重跑为 002，再执行其他八格 002。12 项模式专项检查加原生命周期检查，不当作独立攻击任务数。只覆盖同会话首读后、新的串行文件工具；不包含 legacy 非受管、并发、强 OS 隔离或自然模型攻击收益。

所有结果仍为作者侧实测。每格输出原始协议请求、实际 HTTP/连接错误、签名、独立观察器、清理与冻结核验；先执行再报告实际数量，不预填通过。
