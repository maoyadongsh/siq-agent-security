# 来源路径、中央目录与64槽位实测预注册

沿用固定产品二进制及生产管理API。71次请求：正常ZIP控制1次；ASCII单分量128/129字节、完整相对路径512/513字节、ZIP中央目录4MiB/4MiB+1各2次；再创建60个最小导入，使成功候选恰为64个；最后新ID导入413 limit、原ID原请求200 reused、原ID换actor409 conflict、原记录GET200。这些是同一既有任务块的容量控制，不新增自然攻击/独立任务样本。

路径长度素材同时满足其他轴（总路径513仍在中央目录name≤513范围内，预期400 invalid）。中央目录边界使用64个合法普通文件，在各成员ZIP comment中分配填充，文件及目录数量/展开字节/归档总字节不超限，禁止非法尾部填充；4MiB成功、+1预期413 limit。这里测中央目录字节预算，不单独声称中央条目4000边界，因为超过4000必然同时超过2000文件或2000目录。

成功候选必须有签名且文件树/摘要与冻结ZIP一致；拒绝前后文件及目录集合不变，无Grant或安装。最后必须恰好64个预期record与blob；满槽位原请求复用、actor冲突及读取不能误报成统一容量错误。旧record及快照不能改变。固定模型/真实模型调用均为0。

最多71业务请求、单次75秒、总420秒，无业务自动重试；独立HOME/产品状态，daemon按身份清理。原始签名/请求/文件与目录快照保留，文件事件观察沿已有两处自有逃逸目标。冻结后执行；失败另起新批修订，不能回改预期。尚未覆盖并发容量竞争、强制中断、远端分块、企业整链或跨OS。
