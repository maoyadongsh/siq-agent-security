# 工具效用 002：入口裁决已观察，完整目录导出失败

**本批失败，不按完整 RG07 验收通过计数。** 实际产生 15 次工具决定和 3 条执行后观察，全部 18 条记录及 Grant、SEC 的签名独立核验通过。只读文件保持 `CONTROLLED_READ_ONLY`，授权输出完成 `PATCH_BASELINE` → `PATCH_APPROVED`；终端、代码及委派探针文件不存在。

授权读取、写入、输出 patch 允许；只读输入 patch 因 `grant_scope_violation` 拒绝；名称已批准的 terminal、execute_code 因 `runtime_effect_unknown` 拒绝；其余九个未授权入口（包括 delegate_task、视觉、网络和三个业务报告工具）均因 `intent_tool_not_allowed` 拒绝。这些是已观察到的权限效果，不代表完整业务验收通过或解释器效用可用。

完整采集再次失败，主执行器报 `candidate_skill_native_context_unconfirmed`，目录采集异常为 `RequestSandboxError`。本次源码和长度复核定位到此前未识别的确定性问题：OpenShell `_run` 限制 stdout 不超过 65,536 字符；五个目录记录的原始内容已达 58,919 字节，JSON 包装为 63,668 字节，再增加一个约 11,784 字节的记录就会超过上限。采集循环原先每次返回整个累计目录，因而提前停止；末尾确认屏障无法补救已经停止的采集器。001 报告中“回收竞态”的解释并不充分，需结合这个长度限制修正，不能认定 post-LLM 钩子未注册或未调用。

原冻结核验器的局部核验为 **38/40 项通过**，仍保留失败：网络两个独立拒绝探针的回执顺序与原协议顺序相反；委派 goal 提供了绝对目录和文件名，但没有满足核验器要求的连续完整文件路径。完整核验器因主执行器未保存 `output_path` 不能完成；局部核验根据原生任务编号、实际公司目录和签名资源摘要关联文件，不回填或修改原结果。

下一批实施分块导出：每页最多 24 KiB，base64 后仍低于 CLI 上限；验证偏移、长度、总量及最终摘要，完整导出确认仍为必需。已新增超过 64 KiB、跨页 UTF-8、缺页、截断和无效范围回归。前三级读/写/编辑保留因果顺序，其余独立拒绝探针不要求相互排序；委派提示明确要求完整文件路径。这些变更仅适用于新冻结协议，不改写本批评分。

1455 项源码的运行前后摘要一致，冻结归档、原始回复、局部核验及签名记录均保留在本 campaign。默认用户服务未重启；本批临时服务和业务运行回收检查通过。
