# Edge 技能上传执行流程 v1

executeSkillUpload 组合当前确认范围检查、采集回调、持久签名批次日志和上传回调。Runner.Execute 的 skill_scan 分支在旧 scan 范围判断与完成台账之前调用它；serve 的现有任务锁覆盖执行和最终回执。

skill_scan 必须有已保存且摘要正确的安装计划；不同于旧 scan，未确认的 legacy 状态不能绕过。任务环境/origin 必须符合计划，connector=directory、inventory_kind=skills，设备目标精确匹配，scope roots 为计划已选 roots 的子集，include 精确为 SKILL.md，禁止 exclude 与额外请求字段。计划短安装期限不重新用于撤销已经确认的持久扫描范围，任务自身签名和有效期仍检查。

执行顺序：检查取消/确认/任务签名与期限 → 读取原日志 → 缺失时才采集 → 再检查取消与确认 → 用原设备签名身份准备并持久保存 → 重新读取验证 → 检查取消与确认 → 上传原日志 → 返回已确认摘要和观察数量。不能因缺密钥而生成新身份，不能因日志损坏而重扫。

上传失败不返回完成结果，不写成功台账，不删除原日志；下一次调用无需采集器即可重传完全相同的签名 body。采集错误、截断、取消或确认已移除均不上传。只有上游 UploadSkills 验证服务端回读成功才能作为上传确认，不等于最终回执或运行时保护生效。

无日志时先重新验证已安装签名制品和实际能力，只启动 SIQ_CONNECTOR_BIN_DIR 内的 directory-connector，不回退 PATH。采集器必须声明 skill_manifest 且不要求网络，范围再次验证；collect_skills 使用原确认范围及固定 200 文件/16MiB 上限。技能结果不进入旧执行完成台账或 pending receipt 队列；恢复时重新领取 uploaded 任务，复核当前确认，重传原日志后再生成技能摘要和显式观察数回执。未确认上传返回基础设施错误，不发送失败回执提前终结任务。

隔离测试不构成原生 Connector → 实际控制面全流程验收。任务签发/能力调度及正式签名安装包端到端验收仍待接通。
