# 周期确认材料换代与归档 v1

CL-02 恢复路径增量；不增加扫描范围、周期授权、业务权限或远端状态修改。
当前实施阶段：在线撤销读回、持久归档准备、完成/恢复及 Linux CLI 入口 `retire-discovery-schedule` 已实现；原生安装旅程与真实设备验收仍待完成，不可视为安装换代整体完成。

## 业务边界

已确认材料不会因本机时间超过 expires_at 自动删除或复用。为更换计划，操作者先经既有组织管理入口撤销旧计划，再在设备停止任务服务、取得任务锁后明确确认本地归档。该过程不停止真实服务、不替用户调用撤销，不取消已派发任务；旧计划撤销不等于撤销智能体业务权限。

即使旧计划看似到期，归档前也必须读回 revoked；不依赖可漂移的设备时钟。网络故障、无权限、找不到记录、未知状态、身份/摘要/原意图不一致一律拒绝。新计划必须走已有独立确认路径，不能继承旧 yes 或签名。

## 在线核验（本阶段实现）

复用 GET `/edge/v1/discovery-schedules/{schedule_id}`，无新路由。原获取待确认意图的消费者仍只接受 pending_confirmation + revision=0；换代核验使用独立调用方要求 revoked，不能放宽原消费者。

客户端严格验证既有 edge-discovery-schedule-intent/v1 的精确五字段、意图设备身份与 ID、完整意图摘要、已知状态、非负整数 revision；非 pending 状态 revision 必须大于零。拒绝重复/额外/null/别名/尾随 JSON、超 16384 字节、重定向、异常 HTTP 与取消，不重试、不回显响应正文。

撤销核验先验证原私密日志与当前本地身份/安装计划基线，要求 Client origin、设备身份与日志完全匹配；再 GET，要求读回意图摘要及解析后的每个意图字段与原日志一致，status=revoked，revision 大于原确认请求 revision。只返回经核对的计划状态摘要，不写本地文件、不签名、不发送 POST、不轮询或运行任务。

此读回证明的是绑定控制面报告旧计划已撤销，不证明取消已派发任务或真实扫描进程停止；普通 HTTPS/已允许的回环访问规则保持不变。原接口没有单独的发布者签名，不将响应宣称为离线可验证凭证。

## 已实现的持久准备阶段

持设备任务锁的内部调用方传入明确旧意图摘要后，复验本地状态基线/凭据、旧日志与可选成功回执，再在线核对 revoked。不存在成功回执允许保留为“结果未确认后已撤销”，但已有残缺/不匹配回执拒绝处理，不能冒充不存在。

先独占创建 `discovery-schedule-history-<SHA256>.json`：schema_version=edge-discovery-schedule-history/v1，journal_bytes 与 receipt_bytes 为 base64 编码的原文件字节（无回执为空字符串），revoked_state 为核对后的状态摘要。外层记录摘要用于文件名，不重新序列化原日志/回执。0600、文件和目录同步，安全读回字节一致后，独占写入 `discovery-schedule-retirement-pending.json`（schema_version=edge-discovery-schedule-retirement-pending/v1、state_baseline、archive_sha256）。原文件本阶段保持不变。

任意 pending 归档标记，包括残缺文件或链接，均使正常服务启动、安装前置及新/恢复确认拒绝；不自动删标记或更换日志。该准备函数由明确确认后的归档 CLI 调用，不会因现有确认/启动自行创建归档。完成前原文件不得移除。

当前恢复边界：历史副本已完整持久化但标记未发布时，重新明确确认可再次准备；底层只复用经安全读回且逐字节相同的完整副本，不覆盖它。残缺、被改写或不可核对的同名副本仍拒绝，保留现场供受控处置；不能宣称任意中断均可自动恢复。无未决标记时不能用 `--resume` 代替重新确认。

## 已实现的完成与恢复 CLI

`edge-agent retire-discovery-schedule [--resume] [--interactive | --confirm-retire-intent-sha256 DIGEST]`（仅 Linux；其他平台返回不支持）。

- 默认仅本地只读预览：无确认参数时不发网络请求、不写文件、不签名、不发送业务写请求；仅日志和回执均不存在时报告无材料。日志损坏、孤立回执、非法回执或符号链接均拒绝，不伪装成不存在。合法日志无回执可作为未确认结果的旧材料预览。存在未决归档标记时预览其归档身份与恢复说明；标记损坏即失败关闭。
- 执行必须绑定确切旧意图摘要（`--confirm-retire-intent-sha256`）或真实终端交互确认（`--interactive`，管道不构成同意，默认取消）；摘要不匹配在任何网络请求之前拒绝。确认语义不复用安装或新计划的 yes。
- 首次执行持设备任务锁后先调用既有 prepare 再调用 finish；`--resume` 仅消费既有未决事务，无未决记录时如实报告"无待恢复事务"，不伪造恢复成功；存在未决记录但未加 `--resume` 时明确报错。两条路径都重新在线核对 revoked，并复用既有的身份/摘要/回执核验，不自动调用撤销接口、不重签、不创建或确认替代计划。
- 完成与恢复沿用底层持久事务：历史副本经读回核验后才移除原件，写 `discovery-schedule-retired-<摘要>.json` 完成记录后再移除未决标记；历史与完成记录永不删除。prepare 成功而 finish 失败时保留未决标记并提示 `--resume`。
- 帮助与预览明示：先在组织管理端撤销旧计划；本命令不停止服务、锁冲突按现有任务运行器流程处理；归档不等于撤销智能体业务权限；不取消已派发任务；新计划需独立确认；历史材料保留；网络或状态不可核对时失败关闭。输出只含必要摘要（调度 ID、意图摘要、设备、origin、窗口、归档摘要），不含凭据、原始日志或远端正文。
- 剩余边界：残缺或不可核对的历史副本不自动修复；完整且相同副本可按上述边界安全复用。不得宣称任意中断均可自动恢复。原生安装旅程、真实设备与真实控制面验收未做。

归档实现、崩溃恢复、CLI 接入和原生安装旅程全部通过后才可关闭该恢复子项；在线 GET 前置核验单独通过不代表换代完成。
