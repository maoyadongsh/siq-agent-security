# 原生宿主 Authority 桥接 v1

这是 ADR-056 的宿主应用层，连接原生任务/文件观察与现有 v2 SEC、原生调用记录和签名裁决；不是新授权规则。调用者必须是独立认证的可信宿主。管理 HTTP、进程认证与部署接线完成前，不向普通运行时请求开放以下发布能力。

## 生命周期

1. `Begin` 接收可信宿主固定的完整 subject 与运行制品摘要。逐次调用必需运行验证器，证明进程、只读代码/安装及固定制品仍有效。登记真实会话，建立不可复用的任务记录；未登记任务不能隐式变成无 Skill。
2. `Load` 接收原生 load ID、父 load ID 和 `native-skill-source/v1`。必需来源解析器从管理员已批准的安装及实际受保护映射解析唯一安装记录，核对主文件与所读文件真实摘要；事件不携带可选择的 Grant/SEC。新 load 的父必须等于此任务当前 load；重复当前 load 可用于支持文件/缓存，但不能回退旧 load 或改变安装/主文件。来源验证失败使任务失效。
3. `Prepare` 只接受完整调用身份、最终工具名、调用 ID、请求摘要和当前 load ID。后端推导精确上下文；无 Skill 仅在任务确实尚未加载时成立。只允许单个在途调用；同任务调用 ID 永不复用。
4. `Bind` 在有界裁决入口得到实际参数后，以现有规范摘要核对 Prepare，再签发原生调用记录。参数不写宿主元数据台账；不能由运行时提交 SEC、Grant 或 no_skill。重复 Bind 拒绝。签名调用记录只是来源证明，仍须经过现有 receipt.Engine 的完整 Agent/Skill/祖先交集和 Intent 检查。裁决连接方在 deny/hold 时也须关闭该次在途调用，因为原生 handler 未进入，不会生成 handler 结果回调；关闭不得声明执行发生。
5. `Finish` 消耗原调用，签名回执与实际效果观察仍沿现有协议完成；宿主结束结果不授予执行或重试权。`End` 立即使该任务来源与调用验证失效，即使审计失败也不能继续。已结束任务的在途调用可晚到一次 Finish，保留不确定副作用，不能再授权。

Begin/Load/Prepare/Bind/Finish 的失败均保持关闭；不能通过清空来源、换调用 ID 或重用任务 ID恢复。其他独立任务不受同任务失败影响。任务最多 4096、每任务加载最多 256、调用最多 16384，达到上限拒绝而不删除旧记录。内存宿主事实不从签名文档恢复：daemon 重启后旧任务必需重新可信登记，原签名证据保留，但缺少活体事实即拒绝。

桥接 Bind 必须使用排他的新调用签发：持久目录已有相同 subject/call ID 的任何记录即拒绝，不使用底层 Store 的幂等读回恢复执行。即使可信宿主重启后重新登记相同 task/session，也不能再次授权旧调用；签名仍有效或调用结果未知均不例外。

## 依赖与锁

运行验证、来源解析、实际安装验证和审计是必需依赖，不提供宽松默认实现。验证器不能只返回事件中的值；运行验证器还须覆盖身份固定制品策略。来源解析与运行验证正常返回不等于授权。SEC/调用 Store 每次验证仍重新检查身份、会话、各级 Grant、安装、撤销、租约及宿主事实。

串行化宿主状态变更，状态读取独立短锁；不得持有状态锁调用签名 Store 或外部验证器，避免 Store 回调造成反向锁死。依赖回调必须有界且不重入桥接。所有对外返回是快照，不暴露可修改的内部父链或调用记录。审计只写固定事件类别和不可逆 ID，不包含参数、正文或明文路径。

本合同不自动启用管理身份创建、容器启动、受保护挂载或产品日常业务。实际线上接线必须继续验证调用者认证、可信来源解析、最终裁决与独立效果；组件夹具不能冒充这些证据。

## 受保护的原生 Skill 加载入口

仅在原生 required 身份、当前调用、Agent/Skill/祖先与 Intent 均已验证的 Hermes `skill_view` 中，将合法的 `{name, file_path?}` 归类为 `operation=skill.load`、`effects=[tool.invoke]`。这是对受保护加载工作流的调用许可，不是任意文件读取许可；实际正文返回前仍必须经过同步 `Load` 来源解析、签名安装和文件摘要校验，内联预处理继续禁用。主名称与可选支持路径必须是有界规范相对路径，无空组件、点/上级组件、反斜杠或控制字符，拒绝额外参数。

没有有效原生调用证据、其他平台、同名普通工具或非法参数继续保持 unknown 效果并按既有规则拒绝。普通归一化器不能仅凭工具名启用此分类；Agent 和全部既有 Skill 的工具 allowlist 仍必须允许 skill_view。此调用不会清空祖先权限；后续实际读写继续走各自文件效果和完整权限交集。
