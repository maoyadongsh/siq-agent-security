# 企业 OCSF 事件导出 v1

GET `/api/v1/export/ocsf` 的对外合同。本合同只定义**只读、有界、带截断事实声明**的 OCSF 事件导出；它不声称本接口是完整归档，也不定义任何删除、归档、游标续传、全量导出工作流或 `published`/`verified` 状态。

## 1. 路径、方法、权限与租户边界

- 路径与方法：`GET /api/v1/export/ocsf`。
- 权限：调用方身份必须具备 `audit:read`，否则统一 403。
- 租户边界：`tenant_id` 只从验证后的身份派生，永远作为过滤谓词的一部分；本接口不提供也不接受任何租户覆盖参数。不同租户中相同的规则标识、相同的时间戳互不混并，各自只命中本租户记录；一租户的行数不影响另一租户的截断判定。

## 2. 查询参数

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `class` | `detection_finding` \| `api_activity` | 必填；其他值 422 `invalid_class` |
| `since` | ISO 8601 时间串 | 可选；见 §3 |
| `limit` | 1–2000，默认 500 | 单次响应最多返回的行数 |

`class` 映射：`detection_finding` → `Finding`（OCSF Detection Finding，`class_uid` 2004）；`api_activity` → `AuditEvent`（OCSF API Activity，`class_uid` 6003）。

## 3. since 解析

`since` 按 ISO 8601 解析为时间戳，作为 `>=` 过滤下界。带时区偏移的输入先换算到 UTC 再与库内时间戳比较，因此不同时区写法表示同一时刻时结果一致。非法输入返回 422 `invalid_since`，不返回 500、不回显输入，也不放宽解析去接受它；极端的显式偏移（换算到 UTC 会越过 `datetime` 上下限，例如 `9999-12-31T23:59:59-14:00`）同样按非法输入受控拒绝。

过滤在数据库侧完成，因此**被 `since` 排除的行不参与截断判定**：截断只描述"在本次 `class` + `since` + 租户条件下是否还有更多匹配记录"。

## 4. 响应格式

- 媒体类型：`application/x-ndjson`。
- 正文：每行一个**完整** JSON 对象（OCSF 事件），行间以 `\n` 分隔，末尾带一个换行；不换行、不缩进、不做数组包裹。空结果集返回**空正文**（0 字节），不是空行。
- 缓存：所有成功响应带 `Cache-Control: no-store`（导出内容敏感，禁止任何层级缓存）。
- 顺序：稳定且确定——先按时间列升序（`Finding.last_seen_at` / `AuditEvent.created_at`），同一时间戳再按模型主键升序。相同 `limit` 与相同数据下重复请求得到逐字节相同的行序列与行数。

## 5. 截断事实声明 X-SIQ-Export-Truncated

所有成功响应都必须带精确响应头 `X-SIQ-Export-Truncated`，取值只能是字符串 `0` 或 `1`：

- `0`：本次结果**没有**更多匹配记录（含空结果、少于 `limit`、恰好等于 `limit`）。
- `1`：在本次过滤条件下，除已返回的 `limit` 行外**还存在**更多匹配记录。

实现语义：服务端按 `limit + 1` 查询，正文只输出前 `limit` 行，`limit + 1` 行是否被找到决定该头取值。

- 该探测行**只**用于计算响应头，绝不进入正文、日志、审计或错误信息。
- 正文行数在任何情况下都不超过 `limit`。
- 该头是对"本次结果面对 `limit` 的完整性"的**诚实声明**，不是游标、不是续传令牌；本接口不提供翻页，客户端需要更多数据时只能自行收窄 `since` 或提高 `limit`。
- `1` 只说明有更多记录，**不**说明导出完整、不说明事件已被归档，也**不**说明这些记录已发布或已核验。

## 6. 导出动作审计

成功响应在同一事务内写一条 `export.ocsf` 审计（`resource_type=export`，`resource_id=class`），`summary` 精确为 `{class, count, since}`：

- `count` 是**实际返回的行数**（即被 `limit` 截断后的条数），不是探测条数；探测行不得让审计泄漏出比正文更大的导出规模假象。
- `summary` 不含任何导出内容、事件字段、规则标识或租户数据。
- 审计写入失败时整个请求失败关闭：不返回正文、不返回 `X-SIQ-Export-Truncated`、不提交事务。
- 被拒绝的请求（403、422 等）**不**产生"成功导出"审计，也**不**返回该响应头。

## 7. 失败行为

- 403：身份缺少 `audit:read`。
- 422 `invalid_class` / `invalid_since`：参数非法，在导出前受控拒绝。
- 审计或提交失败：5xx，无正文、无截断头、无"成功导出"审计记录。
- 以上任何失败路径都不得回显上游错误正文、租户数据或凭据，也不得以空正文加截断头伪装成"导出成功且无更多记录"。

## 8. 只读与证明边界

- 本接口只读：不修改被导出的 `Finding`/`AuditEvent`，不改变其状态，不触发任务、通知或派发。
- 导出审计只记录"有人导出了哪一类、多少条、从什么时间起"，**不构成**以下任何结论：记录已被归档、记录已被发布、记录已被核验、事件对应的策略已生效或保护已生效。
- `X-SIQ-Export-Truncated=0` 只表示本接口本次没有看到更多匹配记录，**不代表**租户内不存在更早或未匹配的事件，也不代表数据保留策略允许多久的回溯。

## 9. 兼容范围与不做事项

- 兼容：既有客户端不传 `since`/`limit` 时行为与既有导出一致，仅新增响应头。
- 不做：不新增导出删除、归档、标记、游标/续传、压缩或推送接口；不引入 `published`/`verified` 状态或字段；不新增租户覆盖参数；不修改 OCSF 映射字段、模型、schema 或迁移。
