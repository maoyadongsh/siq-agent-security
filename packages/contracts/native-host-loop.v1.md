# 原生宿主服务循环 v1

可信业务启动器在实际进程/安装核验、Verifier 登记及专属 NamespaceHostChannel 创建之后，可使用 HostLoop 持续服务同一受管进程。该循环只转发已有 DecisionRelay，不审批、不续租、不改主体、不从事件选择端点或运行凭据。

HostChannel 的 accept 超时、且尚未接受连接时，抛出 ChannelIdle（ChannelError 子类）；不消耗序号、不进入处理器。连接已接受后的接收超时、坏包、错误内核凭据、重放或处理失败仍为 ChannelError，不能当作空闲恢复。旧捕获 ChannelError 的调用方保持兼容。

HostLoop 仅允许本进程启动一次，拒绝 fork 后控制和失败后重启。到期时间由已授权业务执行租约提供，UTC 和单调时钟双重限制，启动时最多一小时；循环不延长任何权限期限。每次等待/转发前后检查停止状态、租约与真实 RuntimeGuard；空闲仅继续等待，其他异常使循环永久失效。返回允许结果之前若观察到停止、到期或 guard 失效，必须返回固定拒绝，而不是把已失效允许结果交给运行端。

assert_running 仅报告服务循环和实际 guard 仍有效，不证明业务任务完成或用户授权当前有效。业务 Supervisor 必须沿既有业务授权/租约检查，在撤权、取消或失败时关闭本次循环并执行原有精确容器回收。循环不能代替业务授权检查。

close 先标记停止、关闭通道，再有界等待工作线程退出。未确认退出时报告固定错误，不能宣称清理成功；循环借用 guard，由所属启动器退出目录描述符作用域后关闭，避免循环抢先关闭上层资源。已开始的动作不会因此被宣称回滚。一个循环只处理一个已登记原生主体，不关闭共享 Verifier 或其他业务实例，不删除未知对象。宿主重启不能恢复旧在途调用。
