# 已确认安装计划首扫 v1

POST /edge/v1/initial-scan 使用设备凭据，body 为 {schema_version: "edge-initial-scan/v1", plan: enterprise-install-plan/v1}。仅接受本设备环境/租户且能与控制面 install.plan.create 审计摘要完全匹配的原计划。首次请求要求计划仍在有效期、最近心跳实测能力覆盖全部所选采集器且版本一致。不能从任意客户端 JSON 直接签发扫描。

每设备最多一个首次扫描批次，由 edge_initial_scan 主键约束。一次事务创建全部所选采集器的指定设备签名任务、首扫记录、审计和 outbox。重复同一计划返回同一 task_ids（即使原安装期限已过）；不同计划返回 409，后续重扫走已有管理入口。并发唯一约束冲突回滚全部新任务后返回 409，客户端可重试原请求。遵守现有租户 pending 扫描配额。

响应 {schema_version:"edge-initial-scan-result/v1", task_ids:[...], replay:boolean}，no-store。首扫签发不是资产已发现、纳管或保护生效。审计记录缺失时失败关闭；不接受替代范围，不批准业务权限。

已接通 Linux serve：确认计划对应的制品与能力核验成功、非空能力心跳成功后，提交同一已确认计划。成功后本次运行停止重复申请，重启后仍以原计划向服务端查询/重放；错误沿用后台退避，不换计划、不重注册、不绕过期限。旧无确认计划设备和未验证能力设备不自动申请。只有启动服务才触发该路径，setup 默认仅配置，--start 才启动服务。客户端仅发一次 HTTP 请求，响应须包含正确 schema、明确 replay 标记、数量匹配且不重复的任务编号。原生正式签名包全链路验收仍待完成。

首扫退避独立于正常心跳：首扫失败按 30 秒起、翻倍至最多 15 分钟重试，只在随后成功的能力心跳后检查到期时间。不因首扫失败触发心跳循环的网络错误退避；真实心跳发送失败仍保留原退避。首扫失败仅记录固定脱敏日志，不设置已申请标记，不冒充任务已创建。退出取消优先，重启可立即以原计划重放。此调整不改变服务端期限、设备级幂等、范围或签名要求；请求进行中的耗时仍受现有 HTTP 超时约束，不声称首扫与心跳完全并行。
