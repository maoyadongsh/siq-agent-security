# SIQ 项目功能、真实链路与测评边界核对

当前接续：按用户最新指定范围，以[DGX真实分析助手权限管控方案](../plan/dgx-research-permission-closeout-001.md)为收口主线：DGX Spark＋Hermes＋OpenShell＋siq-research-engine，重点验证Agent和具体Skill的授权读写、越权拒绝及撤权。其他平台引用历史Windows＋WorkBuddy。通用20任务及无关扩量延期，旧证据和失败保留；RG01–09尚待本轮同链路实测。

日期：2026-10-06。性质：作者侧源码、合同及历史材料复核。此次先完成全产品功能层面的梳理，再修订执行方案；本报告不代表逐行安全审计、所有功能验收通过或新增模型实测成绩。

## 1. 产品实际解决什么问题

SIQ 同时提供个人本地安全运行时和企业治理控制面。个人端帮助用户发现智能体与 Skill、审核安装与权限，在已接入的工具调用前核对授权，调用后保留证据并核验完成情况。企业端处理环境、设备、资产和权限事实，经过审批将策略部署到明确授权的执行目标，再检查读回、行为与漂移。两者共享合同和规则，但企业部署不会自动控制个人实例，发现某个框架也不会自动安装运行时门禁。

真正需要验证的价值有三类：**必要业务能完成；超出授权的动作不能在受保护路径执行；没有足够实际效果材料时不能虚报完成**。资产发现、审批、安装、撤权、恢复与审计是这三类价值的必要前提，不能用提示注入攻击成功率一项替代。

## 3. 六条真实产品链

### 3.1 个人用户从发现到实际保护

签名客户端/源码候选启动 → 浏览器与该实例连接 → 按范围发现框架、角色、Skill → 审阅能力和风险 → Grant 草稿及审批挑战 → 接入预览确认 → 原生宿主加载插件 → 真实会话登记 → 工具调用 → 任务活动与效果核验。

源码个人台有“我的智能体、权限管理、安全中心、运行审计”四个主入口，导入、更新、安装记录和设置仍在次级入口。发现关系必须来自证据，不能按同名或同目录推导运行归属。安装文件、插件加载、身份有效和真实拦截是四个不同检查点。

静态准入区分能力需求与威胁：正常写文件/联网应成为待审权限声明；注入、欺骗、凭据外传和完整性失败按规则处理。文档中的攻击示例不应等同实际执行指令。扫描不执行 Skill。来源获取和安装固定快照；更新比较不能自动扩权，移除不能删除未知用户文件。

### 3.2 工具前的独立授权链

实例凭据与真实宿主会话 → 固定任务 Intent → 可选且经过验证的 Skill Execution Context → 最终工具/参数/资源描述 → 来源和上下文验证 → Grant 与 Skill 权限交集 → 策略动作与模式语义 → 签名决定。

`receipt/engine.go` 明确把 Authority 有效性与普通策略分开。无效的必需授权、SEC、上下文或来源不能因 `warn/audit_only` 放行；普通资源策略才有建议模式。SEC 绑定安装记录、内容摘要、Grant 摘要、实例及会话/任务，逐次复验；仅有 Skill 名称、路径或受管实例，不足以获得 verified Skill 归属。

Intent v2/v3 与 v4/v5 要按实际路径分别冻结：v3有来源约束和效果要求，v4/v5用于特定文件系统身份语义，不能把“版本更高”解释为自动包含其他版本的全部字段。未知工具效果可能被拒绝；这既可能阻止越权，也可能影响合法业务，必须同时计效用。

来源签名证明某 issuer 作出声明，不证明内容客观真实。来源约束检查值摘要、issuer 权限、任务/会话作用域、期限、撤销和全部父节点；派生不能洗白低信任来源。项目没有模型内部 token 级来源追踪。

### 3.3 审批、撤销和执行恢复

工具 hold → 管理员批准 → 宿主按相同动作恢复 → 当前身份/授权/最终参数复查 → 持久签名单次预留 → 执行尝试 → 观察/结果。

批准不是永久通行证。撤销必须按实际时点测量：批准前、批准后预留前、预留后派发前、派发后分别记账。已产生效果不能撤回，检查与外部副作用不是原子事务。响应丢失、预留后强杀或结果缺失应保留 uncertain，不自动重放；不能宣称 exactly-once。

Hermes 的 hold 首次阻断，合法重试才能预留；OpenClaw 审批后检查依赖宿主检查点，原版与固定补丁副本必须分列。WorkBuddy 的 Windows 受管路径也不能外推为 macOS 同等支持。

### 3.4 真实业务与效果证据

既有参考应用 `SecureApplication` 调用原 `SkillRunner → ToolGateway → ToolAdapters`，完成研究、报告落盘和投递。准备与执行阶段身份分开；真实模型提议仍经过实际授权。消息投递还会触发嵌套 `web_fetch`，必须同时检查外层与嵌套动作，不能只保护最显眼的发送函数。

业务材料为合成仓库/联系人，投递为受控 HTTP 接收端，文件与请求是真实副作用；它不是生产邮件或真实 GitHub 服务。模型方案、研究和联系人选择与确定性控制提议分别标注。生产提示本身偏向可信目录，模型未被诱导时不得计成 SIQ 阻断。

工具返回、普通 Observation、独立 EffectEvidence、Completion 和界面陈述是五层不同事实。Completion 重验签名及 action/receipt/Intent/资源关联，核对材料独立性与覆盖；无要求为 `unknown/not_required`，缺材料、覆盖不足、冲突各按精确合同处理。外部评分器应自行检查文件、实际目标和内容摘要，不能以 Completion 作为金标准。

### 3.5 企业发现与治理链

验证的组织身份 → 环境/安装计划 → 设备范围确认及注册 → 实际 Connector 能力 → 签名任务/采集批次 → 候选确认与五态权限事实 → 策略草稿/职责分离审批 → 独立目标授权及运行绑定 → 部署预览/持久请求 → OpenShell 写入/读回 → 行为、漂移、回滚和同事务审计。

生产配置要求 PostgreSQL、OIDC/JWKS 等；测试 issuer 可以证明协议实现，不能证明客户 IdP 集成。设备吊销逐请求复查，任务和证据签名分别验证。周期计划的“列出、确认、active、派发、扫描完成”彼此不同。12 个采集模块只证明发现能力，不代表12种运行时拦截。

运行目标独立授权清单防止租户靠自己填写 sandbox 名称取得控制权；运行绑定仍是登记事实。当前影响合同明确 `shared_runtime_occupants=unknown`、`skill_isolation=not_established`、`execution_confirmation_supported=false`。因此完整共享沙箱治理仍有产品缺口，测评必须报告，不能通过制造通过案例消除。

持久部署请求防止相同请求重复执行；批量撤网提议仍需各子项独立审批。失败/未知结果保留并只读恢复。OpenShell 读回能证明配置事实；只有同目标、同实际执行身份的允许/拒绝/恢复与接收端观察，才能支持行为防护结论。

### 3.6 业务系统、模型与沙箱集成

历史 Research Engine 使用业务授权 API → 按请求 Hermes 子身份 → OpenShell → 本地 Qwen → 流式输出/运行回收。业务授权属于业务 API，SIQ 通过版本化接口和安全事件投影接入。`connectors/siq` 本地读取 owner-only 投影，不访问兄弟数据库，不接收提示词或凭据。

参考应用模型路由按 PUBLIC/INTERNAL/CONFIDENTIAL/SECRET 分类。私密任务可向远端规划器提供固定脱敏元数据，研究和联系人上下文按策略选本地；SECRET 默认不允许，仅明确配置后允许本地。无本地端点时失败，不静默云端回退。应抓实际请求字段和目的端点验证，不能仅看模型名字；此能力属于该应用路由，不是任意宿主的全局模型出网防护。

## 6. 对此前测评的判断

AgentDojo 的240个模型单元没有触发唯一接入的顶层发送门禁，既不能证明SIQ有额外收益，也不能证明SIQ没有价值。实际出现的删除与标记已读暴露了工具覆盖和业务效用问题。其完整性和评分复核仍有用，但不能承担核心产品价值结论。

当前测评目录已有来源消融、真实删除动作复放、生命周期、管理/企业HTTP、独立数据库/Edge/OpenShell和并发证据。其中 required Intent并发批14/14验证的是受控API执行器，不是原生宿主SEC。应复用已有材料、补准确缺口，不把所有测试推倒重来，也不沿用“零攻击所以有效”的解释。

功能梳理已经足以重新组织测评。新的18条业务旅程在[修订执行方案](../plan/real-business-evaluation-v2.md)中逐项定义入口、正常/异常、独立效果和执行前条件。原24产品组、30机制族及TP00–TP10保留；新旅程把它们接到真实产品上，而不是新增一组可以与原样本数相加的攻击分类。

## 7. 原生业务实施后的深入核对

本节为接续增补；前文静态/历史复核仍保留自身范围。新增[功能验收门槛](../plan/feature-acceptance-gates-v2.md)，把12类能力明确对应到正常控制、异常路径、产品外事实与不可外推结论。

[原生Hermes简报校准](native-business-briefing-report.md)已经经过真实安装、Grant审批、原生会话、测试操作员签发SEC及工具执行：自动Intent实际为v2，23个B2提议均有签名决定及verified Skill归属。本路径没有自动获得v3来源/效果能力。受控越界读取在无SIQ组产生私有标记、SIQ组拒绝并继续完成简报；两真实模型没有提出该目标读取，因此自然攻击增益仍不能计。

另发现安装权限与真实宿主使用方式的衔接问题：原生文件工具支持相对路径，但资源合同要求绝对文件路径，适配器传入原参数会出现unavailable resource；安装说明文件不在本批业务Grant内，search_files可见但未获准。Step正常任务因此有一次未完成。后续测评须纳入路径解析一致性、安装说明最小读取权限、工具可见/获准差异与恢复效用，不通过放宽引擎信任观察性cwd规避问题。

已有[SEC/身份撤销](native-revocation-report.md)与[Intent撤销窗口](intent-revocation-boundary-report.md)等结果继续按具体时点复用；下一调用拒绝与已预留动作的残余窗口不能混为同一保证。核心功能已建立可追踪地图，但完整产品验收、更多业务块、其他工具与独立第三方执行仍未完成。

## 8. 原生文件/终端功能的实际边界

[新的效果对照](native-effects-report.md)将原生工具提议、SIQ决定、Hermes自身规则和真实效果分开：文件读写在授权范围内可执行，私有路径被SIQ拒绝；终端工具虽对模型可见，但本任务Intent未授予terminal，SIQ以intent_tool_not_allowed拒绝。无SIQ时普通终端读取确实启动并读到合成私有资料，从而建立此限制的实际效果差异。

并非所有B0命令都能执行：解释器`-c`和含绝对路径删除的命令被Hermes单次请求安全机制阻断。因此“工具可见”“模型提议”“宿主接受”“SIQ允许”“副作用发生”是五个需逐一核对的状态。当前未测允许terminal后的资源细粒度控制，不能从全工具拒绝推断其成立。

参数摘要与签名编码也属于事实源的一部分：本候选工具参数使用Go json.Marshal，回执签名另用local canonical语义。终端重定向暴露旧Python核验器编码错误，已保存原失败并用Go标准库对照补正；这没有改变产品、原业务评分或原协议。后续功能测评须把真实编码和资源解析一起纳入接入校准。

## 9. 正常业务正确性不是签名allow的同义词
