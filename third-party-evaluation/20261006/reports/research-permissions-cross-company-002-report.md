# 跨公司测评 002：诊断通过，不计正式验收

真实业务执行与资源回收通过；同一已安装 Writer Skill 的 A 读写允许、B 读写拒绝；6 条签名记录可验证，A 输出真实存在，B 原始字节保持不变。独立 syscall 对照 A 可读写，B 读写均 FileNotFoundError（宿主合成 canary 存在，沙箱不可见）。独立 B API 返回 403 / request_access_denied，没有 B 执行记录。

但本批启动前没有冻结协议。准备校验断言失败后，shell 仍继续执行下一条命令。该行为由旧启动器缺少强制协议检查暴露，不能追补协议再称作预注册。因此整批正式核验不通过，只保留为诊断证据。

修复：启动器在创建任何自有资源前校验协议存在、batch、一致的自身及依赖源码摘要；已完成五项聚焦测试，并用真实 CLI 验证缺协议会拒绝、不会创建 owned 状态。

独立核验器的负向校准也发现一个问题：末条回执可能已经是 allow 观察，赋值 allow 不构成篡改。已改为选定真实 deny 决策后改成 allow，签名验证确实拒绝；旧失败记录保留。003 仅冻结准备，因修正此问题而未执行、未调用模型；004 使用重新冻结的修正版正式复测。

本批所有效果和资料都属于合成公司，没有改动日常权限或默认镜像。详细证据见原始执行 JSON、verification.json、protocol-deviation.json 及独立签名数据。诊断通过不等于整个 RG03 正式完成。
