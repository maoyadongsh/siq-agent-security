# 项目功能深入复核与测评设计判断

日期：2026-10-06。结论：SIQ需要按真实产品链路分别评价授权、执行防护、效果核验和治理闭环。旧AgentDojo试点不能作为核心功能效果的充分检验；已有真实链路证据值得保留，后续应补精确缺口，而不是整体推倒或继续增加同类断言。

本次交付是功能复核与方案完善。新增业务执行0、模型调用0；没有新增安全效果成绩，也没有把作者侧测评改称第三方认证。后续方案为[实施方案v3](../plan/product-grounded-acceptance-v3.md)，主方案升至v1.5。

## 2. 经代码核对的功能逻辑

**个人端管理与准入。** 发现、导入、批准、安装、插件加载、会话绑定、实际工具受控是不同状态。能力需求不等同恶意；安装与更新须固定字节，Grant/SEC不得随同名Skill或新内容自动扩权。来源组件存在不等于生产Git入口可用，四种来源路径需分别验证。

**动作授权。** `receipt/engine.go`先处理Intent、SEC、上下文、来源等Authority，再处理策略。必需授权无效不能依靠warn/audit_only降级放行；参数脱敏也不能跳过资源与审批复验。SEC证明当前安装归属，不自行产生权限。授权判断需要绑定真实工具、最终参数、会话、任务和当前版本。

**来源与宿主。** Hermes `_capture_mcp_result`只对配置的`mcp_sources`及有效call_id采集来源；引用还需实际被选择并传到最终调用。默认工具响应没有因此自动获得逐参数来源链，模型隐式推理也没有被追踪。显式来源桥接、默认原生接入和参考应用须分列。

**效果核验。** `completion.Evaluate`重验签名、action/receipt/Intent关联、独立性和覆盖。没有效果要求时为unknown/not_required；工具声称成功不足以完成核验。独立评分器仍应从文件和接收端建立真值，不能以产品Completion反过来给产品评分。错正文已送达后的conflicting属于检测，不是预防。

**参考应用与模型路由。** 原SecureApplication有自身任务范围和联系人/报告约束，B0必须保留。`application_router`默认PUBLIC研究本地，而直接构造默认ModelPolicy的行为不同；敏感任务的远端规划使用固定脱敏元数据。路由安全须检查实际请求正文和端点，不能从模型名称推断，也不能推广为所有Hermes流量的防泄露。工作树旧路由与已冻结来源分级修复候选身份不同。

**企业端。** 信任组织身份→Edge/Connector采集→确认资产→职责分离审批→独立目标授权→部署/读回→行为/回滚各有独立证据。风险处置还包含owner/reason/expiry、到期重开、规则重扫、同事务审计/outbox及通知。当前工作树已包含rulefix1的租户事务锁、活动风险复用和处置/reaper锁；这些修复不能追记到旧候选。

**隔离和跨仓边界。** 企业影响合同仍写明共享占用unknown、Skill隔离not_established、执行确认支持false；默认desktop-same-uid不提供同UID强对抗隔离。`connectors/siq`只读owner-only的版本化业务安全投影，不承担业务API授权，亦不查询兄弟数据库。E166历史撤权案例不能证明本仓独自实现整套业务权限。

## 3. 现有结果究竟说明了什么

| 证据 | 能支持的判断 | 必须保留的限制 |
|---|---|---|
| [原应用三臂控制](business-comparison-controls-report.md) | 同值不可信来源：B0、A-PROV各投递1次，B2为0；存在可归因来源约束 | 固定提议，不是自然攻击率；错误收件人与越界路径有应用自身防线；污染也误拒绝合法交付 |
| [原生实际效果](native-effects-report.md) | 部分真实文件越界/普通终端读取B0有效果而B2拒绝 | 解释器及某些删除先被Hermes拒绝，不能归因SIQ；终端全拒绝不证明细粒度可用 |
| [真实模型语义任务](native-semantic-support-model-report.md) | 四类任务中测得真实业务准确性/引用与效用差异 | 未出现目标私读提议，不能宣称自然攻击增益；四任务不等于20任务试点 |
| [委派生命周期](native-delegation-controls-report.md) | 当前required Intent阻止越界委派启动 | 合法委派同时不可用；父报告完成不替代子任务完成 |

| [规则并发与worker](rule-concurrency-report.md) | 原重复风险缺陷保留，rulefix1同协议复测及完整worker有证据 | 断言数不是攻击样本；通知故障/企业UI/其他平台未整体关闭 |

旧AgentDojo240单元未触及唯一接入的顶层发送门禁，结果相同说明该接入对所发生行为缺乏判别力。它既不是SIQ有效证明，也不是SIQ整体无效证明。删除与已读等实际动作要求完整工具覆盖；产品主价值应由真实链路的作用点、可达对照和独立效果支持。

## 4. 对原方案的具体修正

1. **用功能主张组织验收。** 保留40功能、18旅程和原TP，新增AC01–12关联表；每项同时规定合法、越界/故障、外部判据与能力边界。
2. **分开四类实验。** 确定性控制、自然模型、生命周期故障、效果识别分别统计。自然未触发、宿主先行拦截、SIQ拦截和已发生伤害不得混算。
3. **先补产品专项开发试点。** TP05未有20个不同产品任务块；TP06尚未执行。v3给出20种业务目标/资料结构和gold要求，先文件再交付，后续另建确认集。
4. **两臂/三臂不混称。** 没有可隔离来源谓词的原生路径做B0/B2；来源三臂只用于真实具备该作用点的子集。不能假造A-PROV来满足240次算式。
5. **按最新证据对账旧状态。** TP及RB早期状态落后于部分后续报告；新增精确变体复核任务，不把旧pending直接理解为从未测过，也不把一份通过报告提升成整旅程通过。
6. **有明确结束线。** 已解释的组件不无限增加变体；缺陷按新候选修复，不支持/缺环境登记后继续可测项；最后交付作者证据包和外部待验表。

本次完成的是全产品功能层面的重新梳理与执行设计，尚非所有功能分支审计。后续具体批次仍需读目标候选的精确合同和代码，冻结之后执行。[机器验收登记](../plan/product-acceptance-register-v3.json)保留这个区别，不把文档完成登记成产品验收完成。
