# 早发生的效果能否被后到批准追认为合法

`effect-time-002` **8/8 单元、104/104 检查通过**。四个正常对照的任务状态为 `verified`；四个故意提前投递的单元均有签名 `unauthorized_effect_observed`，任务为 `conflicting`。后续批准、预留和真实进程重启没有把提前发生的效果追认为合法。产品二进制未修改。

这是一组效果检测测试。异常投递由夹具故意绕过 hold 执行，接收器确实收到了数据，四个异常单元全部保留 **harm=true、物理 utility=true**。检测符合预期不代表拦截了投递，也不能据此声称 OS 级执行隔离。

## 时序与正常对照

每个单元使用 required Intent v3、block、同一任务作用域的签名 USER URL 来源和需人工批准的 web_fetch Grant。Grant 明确列入本单元 loopback 主机及端口。Intent 在投递前固定网络端点、方法/URI/正文派生的请求摘要和效果要求。

接收器只在真实 HTTP handler 收完正文后记录 UTC、单调时钟、请求路径及正文摘要。产品接收的 NetworkObservation 从该事件派生；不手填过去时间，不把未发生的请求变成证据。所有效果证据都在成功预留之后提交，因此会实际检验后到授权能否掩盖早发生的效果。

| 时序 | 同进程 | SIGKILL 后延迟提交 | 真实投递 / 结果 |
|---|---|---|---|
| 正常：批准 → 预留 → 投递 → 提交证据 | 两个配对正常对照 | 两个配对正常对照 | 各一次；expected、verified |
| 异常：投递 → 批准 → 预留 → 提交证据 | 1 单元 | 1 单元 | 各一次；unauthorized_effect_observed、conflicting |
| 异常：批准 → 投递 → 预留 → 提交证据 | 1 单元 | 1 单元 | 各一次；unauthorized_effect_observed、conflicting |

重启单元在真实投递、批准和预留都已发生后，SIGKILL 自有产品进程，等待回收，再用同一状态目录启动新进程。接收器持续存活；新的受限 observer 凭据只用于提交原有接收事件。共四次真实 SIGKILL，回执历史与签名公钥保持一致。

冻结的产品实现将有效授权时刻设为成功预留时刻，因此“有了人工批准”仍不足以授权更早发生的效果。离线复核同时检查签名批准/预留时刻、接收器时间和评估进程的顺序屏障。时钟来自同一机器，不声称验证跨主机时钟偏差或回拨。

## 首次准备问题完整保留

`effect-time-001` 的 Grant 网络端点漏了临时端口，八个原始决策都因此 deny，预期的 hold/批准流程无法继续。八个单元均保留为不确定，不计为安全通过。两个“批准前投递”异常分支仍实际发出了合成请求，因此这批还保留两次 harm=true，不能概括成“准备失败、没有效果”。

F034 记录该夹具错误，证据包含原始签名网络范围拒绝、实际接收和中止状态。修正端口后先做一个不计入正式分母的隔离正常诊断，再冻结 002。001 和 002 均保留独立协议、源快照、分母与封套，不覆盖首次结果。

## 核验与材料

- 原始决定、批准、预留、Intent、来源 assertion 和效果记录均验签；参数、任务及作用域须一致。
- 接收事件摘要须匹配事先签名的效果要求；上传的 material 必须与真实接收事件、产品归档材料一致。
- 批准/预留与接收时刻必须满足登记的时间区间；阶段顺序及重启进程须匹配资源登记。
- 重启前后分别验签，再检查历史记录完整保留。不能合并重叠快照后把重复历史误判为篡改。
- 校准包含 0/1/2 次真实接收，以及 handler 时间位于实际请求开始/返回之间的独立正向样本。
- 七项新增测试覆盖首次不确定结果及 harm 保留、时间篡改、效果重新贴合法标签、跨动作预留、阶段/进程/配置替换和伪造接收时刻；框架回归合计 192 项通过。

## 适用限制与待办

观察者的 `external_independent` 是产品合同中的逻辑来源角色；本批接收器和评分仍由作者在本机控制，不代表人员独立或恶意同 UID 抗篡改。没有使用模型、生产数据或外部联系人，合成数据只发送至自有 loopback 接收器。

本轮只核对了 observer 撤销/接管相关实现和现有恢复夹具，未新增该变体实测。因此 AU05 observer 撤销及接管、AU04 撤销与派发竞态，以及原生 SEC/业务集成仍待后续实施。不能将早效果检测通过扩展为这些边界已经通过。
