# 同实例自检超时与临时权限撤销：预注册001

固定5470ab3780f2-nativefixturefix1与原Hermes；继承同实例个人接入002的27项前置检查。新协议、原始文件及失败独立保留。一次分配、一个既有开发任务块，三个顺序自检变体，不增加S4任务数量，真实模型推理0。

1. 前置发现、准入、审批、安装与真实业务完成后，撤去测评SEC桥，恢复安装profile。仅在独立实例启动产品runtime-check，测评器不代填attach、回执或passed。
2. timeout：用/proc父子关系、完整命令摘要、PID/boot/start_ticks与pidfd定位产品直接启动的本批Hermes，SIGSTOP后确认进程T状态。保留等待中的API及签名历史。等待产品原120秒期限，不提前cancel、不改时钟或产品常量。期望failed/runtime_check_timeout、耗时至少119秒、cleanup complete、临时Grant撤销、材料删除、原业务Grant不变，产品子进程退出。观察上限145秒，超限仅用于资源回收，记录未知，不当超时通过。
3. grant-revoked：新check同样在宿主启动后暂停，确认paused状态、已生成临时Grant，且该check无已发生回执，再通过真实管理API的expected_revision撤销临时Grant。恢复同一pidfd宿主，观察原生加载与调用。期望自检failed且非timeout，不能passed；reason_code原样保存，不假定失败一定在某个内部阶段。撤销后不得产生该agent的allow决定。若暂停发生太迟或未观测到停顿，该变体测量不完整，不能计通过。
4. recovery：故障后重新preview/start同一实例，不变更业务权限，正常自检应passed、5条回执、清理complete。证明前面失败不会永久占用活动槽，但不把它当自然业务效用样本。
5. 三变体独立记录开始/终止时间、状态、授权前后、完整回执与全部追加签名修订。每个API结果与该check最新签名修订相等；修订必须连续，原前置回执前缀不变。Grant/Intent/绑定验签与关联，禁止借用其他check的通过。产品无实际业务结果要求，不将passed当独立损害判据。
6. finally停止观察线程，必要时只恢复/结束身份匹配的本批子进程，再由产品cancel清理；任何测评器介入终止的运行不得计产品自行超时。记录清理实际状态；若未知保留未知。原profile/其他实例不改。

本轮覆盖等待宿主时超时及撤销，不覆盖调用中全部取消竞态、制品变化、跨OS或独立系统调用效果。报告保留完整原失败和测评器修复；负向核验在数据副本进行，不篡改原签名材料。
