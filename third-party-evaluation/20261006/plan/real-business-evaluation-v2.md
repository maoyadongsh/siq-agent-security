## 1. 评什么、按什么顺序得出结论

测评必须回答：用户能否完成应做的任务；SIQ在哪个实际入口阻止了越权；未完成或错误完成是否被准确识别；安装、授权、撤销和故障恢复是否仍可操作和追溯。

先检查接入，再做机制因果对照，再跑自然模型业务，最后确认与复核。没有触发门禁的任务只能说明该次模型行为；仅有deny回执不能证明没有外部效果；某个组件通过不能外推整条产品链。

现有AgentDojo试点保留为公开基准探索：240单元未触发唯一顶层发送门禁，另有删除/标记已读副作用。新的核心证据优先来自原参考应用、真实Hermes和真实OpenShell，企业流程从真实HTTP/数据库开始。不得另写一个简化“业务应用”替代原产品。

## 3. 完整接入的执行前检查

为每条旅程落盘`integration-map.json`。每项必须记录**actual / fixture / absent / unsupported**之一，说明对应版本与证据：

| 层 | 必须核实 |
|---|---|
| 用户入口 | 实际CLI/API/浏览器操作、原用户任务和合法目标 |
| 模型 | 真模型或固定提议，准确模型名/端点引用、参数、system prompt摘要、工具清单 |
| 宿主 | 真实版本、原版/补丁差异、实例/会话、插件加载；不能用直接调用hook代替原生派发 |
| 授权 | Grant、Intent版本/模式、实例身份、任务绑定；需要SEC的场景必须有真实安装及verified SEC |
| 来源 | 哪个真实来源被报告、怎样选择/派生并传入最终参数；未实现的隐式lineage保持unknown |
| 工具 | 所有可读/写/删除/出网/委派工具，别名及嵌套调用；逐项注明门禁、资源映射和实际执行器 |
| 执行后 | 普通observe、产品observer、Completion要求、独立文件/读取/接收端观察 |
| 用户呈现 | 最终文本、任务状态、活动/回执、导出；与外部效果比对 |

先跑一个合法工具和一个已知越权工具：B0目标效果可达，B2实际进入门禁并产生关联拒绝，正常业务仍可执行。再做观察器0/1/2事件和断连校准。任一不成立先修集成或记录不可区分，不扩大模型批量。

工具覆盖分母包括**注册工具库存与本次实际调用**两种，分别统计；未出现某工具不能证明其已保护。对支持未知效果的工具保留原能力，不能删掉合法任务所需工具换取零攻击率。若按范围禁用工具，必须预注册并同时约束所有组，结论随之缩小。

异常改变低信任资料或联系人建议，合法目标不变。B0/B2保持业务工具、生产提示、模型参数及输入一致。原应用交付链B0接缝已实现并校准：只移除SIQ装配，保留原工具执行和应用自身检查，不伪造SIQ allow回执。无SIQ时产品Completion记不适用，独立业务效用仍可判定。当前B0接缝不支持审批/撤权和confidential专用场景，扩展时另立协议；不是原生宿主B0。
